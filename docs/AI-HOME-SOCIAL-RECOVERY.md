# 小窝社交恢复与回退

社交恢复必须使用完整实例检查点：精确代码身份、配置、一致 SQLite 在线备份、打包素材、目录版本与许可资料。个人记忆导出不包含双角色社交表，不能用于恢复拜访。备份包含私密记录，应按实例的私有备份策略保管；清理运行库正文不会删除离线备份。

## 恢复新版检查点

1. 停止目标实例。将完整检查点恢复到独立数据目录，保留源检查点和当前实例的最新检查点。不要直接覆盖正在运行的数据目录。
2. 核对代码提交及构建摘要、配置、数据库完整性和打包素材 SHA-256。配置或账本缺失不能用默认值或空数据库补齐。
3. 在新版代码中执行恢复屏障，明确传入当前正文保留天数：

   ```sh
   node scripts/home-social-recover.mjs --data <离线恢复数据目录> --retention-days 30
   ```

   命令拒绝持有 `process.lock` 的目标，也拒绝缺失配置或数据库。它先原子保存全局暂停、社交和交流时段关闭的配置，再在事务中轮换恢复代次，失效旧 pending 邀请、active 拜访、房间 grant、上下文和排队工作。已领取而结果未知的模型调用不会重放，原有用量与预留保持保守占用。数据库屏障失败时配置仍关闭，不得跳过失败直接恢复活动。

4. 屏障保留身份代次、原 requestId、operationId、提交时间、消息序号、墓碑及用量账本。按当前保留期限与检查点内期限的较短值清理已到期终态正文；新关闭的拜访从恢复时刻计算终态保留期。
5. 用同一新版代码启动恢复目录并检查实际进程、构建身份、数据库和配置。先保持暂停，核查双方身份、原回执、无自动模型调用及无 QQ 投递。管理员复核后再决定恢复已有活动和启用新社交能力；旧终态拜访不会因重新开启而复活，需重新自愿邀请。

该入口只准备离线恢复数据，不复制整个运行目录、不恢复登录凭据、不启动服务，也不代替代码与资产校验。不要把普通进程重启当成完整恢复：普通重启中断旧交流时段，但可以保留逻辑拜访；完整恢复更保守地撤销旧通行证。

## 回退旧版

回退前停止新社交写入并排空事务，保存当前代码、配置、在线数据库备份及资产的完整检查点。旧版必须使用升级前的成套检查点，禁止旧程序写入已经升级的数据库。旧检查点不会包含升级后消息，也不会自动合并新数据；当前检查点应完整保留，以便后来恢复新版。

恢复演练使用合成身份、独立目录与假网关。数据库检查与原回执一致性由 `test/home-social-recovery.test.mjs` 验证；跨版本及全链路验收结果由二阶段交付记录补充，不能用这些测试声称真实模型或 QQ 已完成验收。
