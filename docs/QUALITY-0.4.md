# 外部工具与长期记忆验收 · 0.4.0

日期：2026-10-25。基于 0.3.0 / `133e0ad` 开发。所有消息投递终止于隔离 HTTP/WS 网关，未向真实 QQ 发消息、@、收藏或改备注。生产两个桥接的最新只读状态均为在线、QQ 在线、paused=true；未修改原生 PacketBackend、登录、人格、历史、Docker 或生产部署。

## 实现

- MCP 支持 stdio、Streamable HTTP、显式 SSE。`external_tools` 返回真实 tools/list 中的白名单工具、参数 schema、缺失工具和分页；不会暴露启动参数、环境变量或认证头。发现成功不代表执行成功。
- `external_tool` 识别内嵌 image/audio/resource blob，验证格式和 MIME，登记到本主体媒体库。错误结果不登记可发送媒体；resource_link 不擅自下载。保留结构化文本并限制文本/媒体数量，图片与音频仍走原 outbox、暂停、限频与幂等。
- `audioInput` 可把本主体已登记音频按已发现的服务参数名绑定为 base64/MIME；再次检查向外部服务提交资料的权限。这是 ASR 接口适配，不代表已连接 ASR 服务。
- `voice_synthesize` 提供显式启用的 macOS 本地 TTS。默认关闭，使用已安装音色、独立临时目录、FFprobe 验证并登记 WAV，不自动发送。保存输入文字为 `tts-input-not-asr`，不能称作转录。其他操作系统明确返回不可用。
- 平台工具可选择 native/index/auto，并提供最近探测状态。按实际 Exa schema 修复了索引搜索缺少 `objective` 的兼容问题；黑话研究可配置固定参数和查询字段，仍只提交候选词，研究结果保持 candidate / unverified。
- 记忆增加 `memory_related`、关系索引、场景重叠去重、事件 keyset 游标、FTS5 trigram 候选索引及管理台关系展开。没有自动话题分类、事实合并、删除历史或更改人格。
- SQLite backup API 一致备份及新路径恢复命令；schema 1→2 在事务中补建索引，保留原记录、日记修订、证据和主体隔离。

外部查询不发送真实 QQ 聊天。服务调用规模：Exa 共 4 次搜索（直接 1、两个后端各 1、黑话研究 1）；平台搜索 5 次、正文/评论 8 次，单次限 2 条（平台可附带回复或元数据行）。imagegen 生成 1 张，之后仅重复读取同一文件。总计启动 27 个模型验收用例回合（包括失败、被停止的初轮及修复后复验，不是 27 个独立质量场景）。模型使用已有独立 DSH/Codex 账户，未开新付费服务；这些调用会使用既有额度，接口未返回可核对的计费金额，不能报告为免费。

## 记忆质量评估

合成档案含同时发生的项目见面、晚饭和天气话题；四名同昵称但不同 QQ 的发言者；三天后引用原提议的改期及确认；未经核实的场地传闻及次日撤回；缺失引用；在私聊写下、关联群聊证据且经过修订的日记想象。

两个真实后端均通过六维结构化判断：最终口头计划、另一话题的身份、撤回与真假未知、引用缺失、日记想象与事件时间、没有记录的后续。检查具体值、人物 ID、原始证据 UUID 和日记版本，包含显式未知；不采用几个关键词命中就判正确。另逐段检查中文说明，两者均区分发言、传闻、日记和未记录的后续，未补出真实看海经历。

首轮 DSH 使用了 QQ messageId 代替记录 UUID，严格评估失败；也发现旧隔离 bundle 没有刷新新增工具白名单。刷新测试 bundle 并明确 ID 说明后复验通过。DSH 一次尝试跨会话已读水位，服务端拒绝；Codex 两次请求超过 16000 字符预算被拒绝后自行更正。另一次 Codex 转发回归因超过字符上限、工具只返回笼统失败而未读到内层，严格验收失败。现在两个后端返回脱敏的校验字段和上下限，并给预算补充说明；单独重跑 Codex 转发用例通过。保留这些失败，不把主结论正确描述成所有工具调用都正确。样本只有一个复杂场景在两后端各跑一次有效复验，不承诺普遍准确或消除幻觉。

## 20 万条合成压测

环境：Apple M1 Pro / macOS arm64，Node 24.19.0，SQLite 3.53.4。20 万条含两主体、20 个群、100 个发言者；每万条约一条稀有词，重复中文正文。按 1000 条事务写入，用时约 24.6 秒。数据库约 200.1 MiB：原始 events 约 87.0 MiB，FTS 派生数据约 37.2 MiB，其余主要为身份、来源、时间和消息索引。未删除或裁剪原始记录。

每项测量 9 次，表中为中位数；基线是原 LIKE SQL，优化列包含候选筛选、字面校验和结果构建，非单独 SQL。测试关闭邻居上下文，结果受 16000 字符预算限制；两列返回条数可能因预算不同，不能将延迟比例当作统一吞吐量保证。

| 查询             | 原 LIKE SQL | 新完整搜索 |
| ---------------- | ----------: | ---------: |
| 稀有蓝鲸实验     |   67.553 ms |   0.798 ms |
| 不存在的长词     |  110.710 ms |   0.082 ms |
| 蓝鲸（两字）     |   65.742 ms |  69.055 ms |
| 明（单字）       |   66.947 ms |  67.704 ms |
| `%_`（字面字符） |    2.411 ms |   2.763 ms |

人物 QQ + 来源 + 时间筛选约 7.2 ms。小库单元测试另覆盖中文交集、人名、数字身份、引号、ASCII、emoji、字面通配符。采用 FTS 的依据是长词收益；短词仍扫描，尚未证明百万级/并发下性能。依据 [SQLite FTS5 文档](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)，trigram 对少于三字的 MATCH 不适用，不能把它当作所有中文查询的加速器。
