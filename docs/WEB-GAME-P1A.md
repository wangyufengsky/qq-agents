# 网页游戏 P1a：通用内核与隐藏选择夹具

P1a 已提供可独立验证的通用房间内核，以及只在本机运行的 `choice-probe` 非棋盘夹具。它使用合成参与者，不连接真实 QQ、不调用模型，也没有五子棋规则。P1b 将接入五子棋；真实来源身份适配、邀请投递与 AI 执行在 P2 完成。总体约定见 [v0.5 契约](plans/WEB-GAME-v0.5.md)。

## 本机体验

Node.js 24+，在已安装依赖的代码目录运行：

```sh
node scripts/game-p1a.mjs --data /absolute/private/game-p1a-data --port 35822
```

必须使用新的独立数据目录。程序拒绝带真实配置、P0 数据或其他文件的目录；只监听 `127.0.0.1`，不提供公网参数，拒绝转发头及不匹配的 Host。不要给这个合成身份夹具配置隧道。正常 QQ Agents 启动不会加载或开放它。

程序将两个参与者的邀请写入该目录的 `invitations.json`，控制台不打印凭据。使用两个独立浏览器配置或无痕上下文分别打开 A、B 邀请，点击「确认加入」。普通同一浏览器的两个标签页共享 Cookie，不能用来模拟两个身份。

1. 两人加入后，A 点击「开始」。如果 B 尚未加入，会明确拒绝，可在 B 加入后重试。
2. A 选择太阳或月亮，再点击「确认选择」。B 此时只能看到 A 已行动，看不到 A 的选择。
3. B 选择并确认后，双方一起看到结果：相同则共同成功，不同则共同失败。
4. 刷新保留身份和状态；A 可暂停、恢复或结束房间。结束房间不计为任一方获胜。
5. 提交响应丢失时，页面保留原操作编号，使用「查询待确认操作」对账；明确拒绝后允许重新选择，不自动改版本补交。

关闭脚本后只显示已经认证参与者的静态投影快照，不能操作。`Ctrl+C` 停止服务；重启恢复旧房间和 Cookie，并在容量允许时另外创建一局。夹具最多保留 8 个房间；容量满时保留旧邀请文件并继续提供旧局访问。邀请 15 分钟有效，会话最长 24 小时，仍受房间保留期限与撤销约束。

## 内核与模块边界

实现位于 `src/games/core/`，没有棋盘尺寸、坐标、棋色或五连规则分支：

| 模块           | 职责                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| `registry.mjs` | 校验可信内置模块清单、宿主能力与资源上限；固定完整模块引用与内容摘要       |
| `store.mjs`    | 独立 SQLite 格式标识、WAL、即时事务与原子提交；拒绝其他应用数据库          |
| `kernel.mjs`   | 房间、参与者、版本、生命周期、动作回执、通知、决策引用与视图边界           |
| `identity.mjs` | 绑定挑战、源主体确认、单次兑换、会话轮换与房间隔离                         |
| `http.mjs`     | 仅本机的 HTTP 适配，严格 Host/Origin、请求大小和 Cookie 路径；不挂载管理台 |

`src/games/fixtures/choice-probe.mjs` 拥有选择规则和投影，`public/game-p1a.js` / `.css` 是最小验收界面。另一个仅用于自动测试的随机状态模块验证同一内核可接不同动作和状态结构。

模块由宿主静态导入。注册时提供清单、Zod schema、规则函数及完整发布源文件；宿主计算摘要，夹具同时纳入依赖锁文件和网页资源。模块不是沙箱，不能接受网页或模型提交的代码。修改发布内容必须升 moduleVersion；旧房间只接受其完整固定引用，缺失或摘要不符报 `GAME_MODULE_UNAVAILABLE`，不会自动迁移或丢弃状态。

规则函数输入为冻结的 JSON 副本，不包含 principal、QQ 身份、会话或凭据。`create` 返回初始状态；`applyAction` 返回 `{state}` 或固定的 `{rejected:true}`，后者统一映射为 `GAME_ACTION_REJECTED`，避免规则错误夹带隐藏内容。`nextActor`、`outcome` 和 `projectView` 均校验返回值；下一行动者与结果必须相容。所有参与者投影验证通过后才能提交。

平台为规则生成冻结的逻辑时间与随机材料，将成功动作的原 context 保存在私有审计记录中。重放使用原材料；玩家回执和通知只含确认元数据。宿主不声称能自动证明第三方规则的确定性、信息安全或 CPU 上限，新增内置模块必须通过相应契约测试。

## 认证入口与当前限制

`kernel.actor(principalId)` 是服务端可信适配器的认证入口，返回不可序列化复造的上下文对象。未来 QQ 适配器必须从已认证消息的真实发送者和来源授权派生主体，不能把网页参数传给此入口。房间 API 只接受这个上下文或房间 Cookie；动作正文不能切换主体、座位或 agentId。

身份流程为 `invite → request → confirm → exchange`：

- `invite` 由房主管理权限签发，绑定既定参与者；令牌只存摘要。
- 浏览器显式 POST 后创建挑战，并绑定浏览器私密 Cookie；GET/预览不兑换。
- `confirm` 必须来自预期参与者的可信来源上下文，房主不能代另一人确认。
- `exchange` 同时检查已确认挑战与浏览器秘密，单次兑换房间会话。重新发邀请作废旧挑战；重新兑换撤销同座位旧 Cookie，保留 participantId。
- `confirmAgent` 仅供可信角色适配器确认已声明的真实 agentId，不存在对应网页端点。P1a 不提供真实 QQ 认证或 AI 调度适配器。

本机夹具用自己持有的合成主体自动确认挑战，这不证明 QQ 身份。未来公网适配必须保留 v0.4/v0.5 的 HTTPS、Secure Cookie、精确 Origin、来源确权和邀请发送账本；本机 HTTP 例外不能直接用于公网。

`allow(principalId,roomId)` 为宿主的同步当前授权检查；绑定、视图、动作和回执均重新检查。P2 还须对接真实框架的暂停、静默、白名单、隔离、QQ 连接及预算门禁。当前 AI 决策只持久化为 `blocked/P2_NOT_IMPLEMENTED`，动作直接拒绝；没有租约 worker、模型调用或任务投递成功的承诺。

## 持久化、期限与失败处理

每个新动作在 `BEGIN IMMEDIATE` 中检查主体、幂等键、版本、规则与生命周期，再同时保存状态、回执、事件及下一决策引用。相同编号与正文返回原回执；不同正文报冲突。明确拒绝、模块异常、非法输出、存储故障均不产生半提交；没有成功提交就没有成功回执。

建房请求编号也持久去重，删除房间后原编号不会隐式另建一局。P1a 保守保留建房墓碑，上限 4096 条；达到上限停止建房，不自动清除幂等历史。生产容量与清理管理待后续完善。

默认空房 15 分钟过期；活动局 30 分钟无有效写操作暂停；暂停 24 小时过期；结束或过期后保留 24 小时。`sweep()` 是独立、可重复调用的期限处理入口，CLI 每秒调用一次；读取视图不调用规则、不续期、不创建决策。到期尚未 sweep 时拒绝新操作，仍可查询未删除、未撤销的成功回执。

通知最多保留最近 256 条，每次读取最多 128 条；过旧游标要求重取快照。状态、动作和投影按 UTF-8 字节限制；每局最多 10000 个用户动作，达到上限仍可受控结束。独立数据库不迁移现有 QQ Agents 或 P0 数据，不新增默认工具权限。

## 验证

```sh
node --test --test-timeout=120000 test/game-core.test.mjs test/game-identity.test.mjs test/game-p1a-http.test.mjs test/game-p1a-cli.test.mjs
node scripts/game-p1a-browser-acceptance.mjs
# 已安装匹配的 Playwright WebKit 时：
node scripts/game-p1a-browser-acceptance.mjs --webkit
npm run verify
```

自动测试覆盖事务回滚、跨连接并发、隐藏值双状态比较、会话与挑战隔离、撤销、期限、重启、模块版本/能力/输出拒绝、随机重放及 HTTP 边界。浏览器脚本使用两个隔离上下文、手机视口，验证拒绝后重试、隐藏选择、提交后丢响应、刷新对账和共同结果；它不代替 P1b/P3 的真实手机与异地验收。
