# 后端连接状态与恢复

管理台“AI 后端”分别显示 DSH 和 Codex 的后端状态、最近检测时间、角色检测结果以及自动恢复次数。角色卡片也显示后端状态；QQ 实例是否在线仍单独显示。连接就绪表示实际登录/模型目录检查通过，不代表已运行模型对话或已投递 QQ 消息。

## 管理台操作

- **检测连接**：对每个绑定角色执行新的连接检查。Codex 检查专用实例的登录和模型目录，DSH 检查所选提供方和模型。不会重放模型回合；首次检查可启动桥接自己管理的 Codex 子进程。
- **恢复连接**：重新建立这个后端的角色连接。已有活动回合会正常取消并完成交接；已完成、仍兼容的会话在下一次唤醒时复用。保留经历、日记、读取进度和发送账本，QQ 连接与其他后端保持运行。
- **选择 DSH 实例**：显示真实探测到的实例地址、进程信息和是否支持跟随重启。多实例无法唯一对应时必须选择；提交时再次发现，过期或伪造的候选不会被接入。
- **开启/关闭自动恢复**：按后端保存，旧配置默认关闭。开关本身不取消回合、不重建会话，也不改变 QQ 连接或参与率。

自动恢复开启后约每 30 秒检查一次；连接失效后延迟尝试恢复，最多连续 3 次。需要登录或选择实例时停止自动尝试。三次失败后显示停止原因，可以手动恢复重置次数。全局暂停、所有绑定角色暂停及隔离模式下不执行自动检测/恢复；自动恢复不会中断活动回合。首次配置或后台恢复只建立连接，不启动模型回合。

手动恢复期间，新回合暂缓启动；重复点击合并为同一操作。恢复和完整配置编辑互斥，参与率单独热更新仍可正常保存。已取消/失败的回合沿用原有交接规则，不直接重发提示或消息；未知发送仍保留未知状态和原请求标识。

## DSH 实例绑定

在 macOS 上，支持绑定桌面 Host 发布的 `plugins/dsh-relay/<profile>/relay-endpoint.json`。同时检查对应状态描述符、DSH home、authority/epoch、进程监听端口归属和 DSH 协议特征。只读取路由元数据，不读取 Relay 凭据或会话内容。

持久化的是 `recovery.dshInstance`（例如 `relay:web`），不是每次重启变化的端口。每次重新连接都验证并解析该发布位置；它暂时不可用时不会静默切换到另一个 DSH。其他实例可作为固定地址选择，界面说明重启后可能需要重新选择。原有显式 `baseUrl` 继续生效，只有管理台选定实例后才迁移；无绑定且有多个候选时拒绝按端口顺序猜测。其他系统保留固定地址及原有标准端口/进程发现，不声称已验证桌面描述符绑定。

```json
{
  "recovery": {
    "autoReconnect": true,
    "dshInstance": "relay:web"
  }
}
```

Codex 仍使用各角色独立的 `CODEX_HOME` 和桥接拥有的 app-server 子进程，不操作日常 Codex 应用。旧子进程延迟到达的退出/错误/输出事件不会破坏替换后的连接。

## 接口与验证

`GET /api/status` 的 `backends` 提供状态快照。管理员使用 `POST /api/backend`，传 `id` 和 `action`（`check`、`recover`、`discover`、`settings`）；选择实例额外传 `candidateId`，开关传 `autoReconnect`。沿用管理员认证、Origin/Host 防护和 live 模式边界，模型工具目录不暴露这些运维接口。响应只显示归一化错误，不向管理台传递底层凭据诊断。

测试覆盖管理员 HTTP 接口、真实控制台操作函数、隔离/认证、并发恢复、角色及 QQ 隔离、会话复用、无提示重放、自动恢复次数和暂停、发现期间出现新回合、DSH 端口变化与多实例、Codex 新鲜健康检查和旧进程事件。真实后端连接检查及生产部署另行记录；模拟测试不代表 QQ 已实际回复。
