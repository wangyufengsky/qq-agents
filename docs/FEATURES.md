# 功能说明：主动调度、语音与旧工具

## 功能一览

- 任意数量的 `agents`、`connections` 和 `backends`。一个角色对应稳定 `agentId` 和一个 QQ 身份，AI 后端/模型会话可以变更。
- 统一管理台：增改角色、QQ 账号连接、AI 后端、提供方、模型、思考强度、人格、工具白名单、群/私聊白名单、名字/@/问句唤醒、参与率、静默时段、暂停及状态。
- OneBot HTTP + 正向 WebSocket；连接前核对实际登录账号。群聊和私聊按白名单接收；自己的消息不触发自己；其他 AI 的互聊有共享计数与冷却边界。
- DSH Web RPC + mux 适配，动态发现本机端口；独立的 DSH preset/MCP bundle 生成器。Codex 使用专用 app-server、独立 home、动态工具和回合取消。
- 完整入站消息在接收时持续写入 SQLite。出站尝试、确认、失败/未知结果分别记录。幂等键避免重复接收/发送；网络结果未知时不自动重放。
- 手动连接过的 QQ 接收通道意外断开后按指数退避自动重连（默认最多 8 次，可按连接关闭）；只恢复接收，不重发、不补录断线期间消息，账号不匹配立即停止。NapCat 报告 QQ 已离线（被顶下线、登录过期、风控）时同样断开并标为 `QQ_OFFLINE`，重新登录后自动接上；重连不会替 QQ 登录。
- 管理台总览列出结果未知的发送，管理员在 QQ 中核对后标记“已发出/未发出”，两种结论都不会重发同一请求；每个角色卡片显示当前无法发言的具体原因（隔离、全局/角色暂停、静默时段、AI 后端或 QQ 未连接），对照见 [故障排查](TROUBLESHOOTING.md)。
- 自主个人日记及版本历史，中文关键词/人物/来源/时间检索，命中附带场景、发言者与引用，按 ID 分页展开及前后文读取。不同角色不能互读；同一角色可回忆自己的群聊和私聊。
- 心情：角色在心情真的变化时自己记下心情、原因和大约持续多久；有效期内各会话的模型各看到一次，变了再看到，过期不再提示。管理台角色页的「心情」标签只能查看变更记录，不能修改，详见 [心情](SELF-CONTEXT.md#心情)。
- 人物卡：角色按 QQ 号记下怎么称呼对方、彼此关系与印象（带证据和版本）。对方在聊天中说话时，自动附在提示最后，同一会话每个版本只给一次；管理员可在角色页的「人物卡」标签查看、修改和删除，详见 [人物卡](SELF-CONTEXT.md#人物卡)。
- 回忆表达由角色判断，允许在私聊中谈及群聊回忆；个人日记也不逐次请求发言授权。本地运维文件与把跨会话资料提交外部服务仍有独立授权检查。
- 图片像素读取、角色独立的表情收藏、图片/文字/引用/@ 投递；允许的外部 MCP 图像工具可返回图片并登记为受控媒体后投递。平台只读搜索/内容/评论复用 social-reader 的并发锁。
- 显式原生进程启动/停止、带归属标签的 Docker 容器启动/停止。仅操作本管理器拥有的实例，不创建/删除登录目录、容器、卷或镜像。
- 旧 social-v2 窗口、JSONL 历史、旧 SQLite 笔记的只读预检与幂等导入；单身份导出/恢复；保留旧资料及修订历史。
- 角色语音库、导入/试听、音量/响度处理、受控语音发送；嵌套转发展开、归档、分页与合并转发发送；拍一拍与分段连发。
- 可取消长等待、睡前观察、条件唤醒、有限睡眠、消息合并与回复检查、主体主动意图与统一发送限额。
- 13 类定时规则、时区/排除日期、固定文字/AI 任务、配额、忙碌队列、执行日志及重启不重放；管理台预览与编辑。
- 显式有向跨群汇总；独立工作任务 L1–L3 运维、逐项批准与 TOTP 防重放，默认关闭。

图片/音频生成与转录依赖管理员配置的 MCP；平台读取依赖 OpenCLI/mcporter 和已有登录。官方表情收藏/备注需要旧网关扩展接口，不能假定所有 NapCat 版本支持。旧项目功能对照见 [功能对照](FEATURE-MATRIX.md)。

## 浏览与分享

网页“浏览与分享”按角色开启 B 站、小黑盒、知乎、小红书、贴吧的读取与分享。主体可自主选择来源并提出意图，目标聊天决定发送、暂缓或放弃；当前聊天也可分享自己实际读取的内容。权限和预算一次保存持续生效，暂停仍优先。页面提供来源范围、登录检查、浏览记录、分享理由、目标、取消和出站回执。平台能力、分页限制与升级说明见 [APP-EXPLORATION-IMPLEMENTATION.md](APP-EXPLORATION-IMPLEMENTATION.md)。

在“角色 → 配置角色”开启“允许自主搜索与联网浏览”后，该角色可自行搜索公开资料、选择平台内容和调用已配置的外部工具，无需 `/search`、`/browse` 或逐次确认。该持续授权按角色保存，旧配置默认关闭；平台权限、时段、预算、凭据和运维内容保护仍独立生效。详见 [联网权限说明](CHAT-NETWORK-POLICY.md)。

## 第三方平台读取

“浏览与分享”和旧读取工具会访问第三方平台的内容：B 站、知乎、小红书、贴吧通过本机安装的 OpenCLI 读取（`src/apps/opencli-runner.mjs`），小黑盒的接口请求使用移植自 heybox-cli 的签名（`vendor/heybox/signature.mjs`），搜索则读取其官网页面；`vendor/social-reader` 是沿用旧项目的读取模块，其中的 `social_search`、`social_read`、`social_comments`、`social_status` 工具绕过平台权限、预算和来源记录，目前不会提供给任何角色。

- **默认关闭。** 角色的 `apps.enabled`、`apps.sharing` 默认都是 `false`，`apps.platforms` 默认为空；示例配置同样关闭。需要管理员在“浏览与分享”里为每个角色单独开启并选择平台。
- **使用者自行遵守平台条款。** 开启前请确认相关平台的服务条款和账号使用规则是否允许这种读取；登录哪个账号、读取频率和每日预算由管理员决定，相应责任也由使用者承担。
- **与这些平台无关联。** 本项目与上述平台及其运营方没有任何关联，也未获得其认可。登录由管理员在本机浏览器自行完成，项目不索要账号密码；平台接口和页面随时可能变化，读取功能可能随之失效。

## 文件下载与发送

网页“权限”页按角色开启自主文件收发：公开链接与 QQ 附件下载、文本附件生成、专用目录导入和当前会话发送。文件库按主体独立，默认关闭；普通操作无需逐项确认，仍遵守暂停、白名单、限频和幂等。管理员可以在网页导入文件。配置、限额、DSH 工具目录更新及验收边界见 [FILE-TRANSFER.md](FILE-TRANSFER.md)。

## 主动参与

角色的 `behavior` 管理合并唤醒、频率、等待、分段发送和主动机会。`wake` 配置 @、名字、私聊、问句、关键词、指定发言者、拍一拍及入群事件。每个会话可通过 `qq_set_wake_config` 设置有限睡眠或条件唤醒；暂停、白名单和静默始终优先。

合并唤醒由 `batchWindowMs` 和 `batchMaxMs` 控制：每来一条消息，都在它之后再等 `batchWindowMs`，从第一条算起最多等 `batchMaxMs`。`batchMaxMs` 不大于 `batchWindowMs`（默认 0）时，从第一条起固定等待 `batchWindowMs`。已在本批次里的发言者接着发的消息，即使本身不触发唤醒，也会顺延等待；其他人的普通闲聊不会。定时任务、意图和睡眠到期的唤醒不会被后来的消息推迟。

`qq_wait_for_messages` 最长等待十分钟，收到消息后等待安静窗再返回；停止/暂停立即取消。潜水前默认观察五分钟，发言后观察重新开始。读取不会偷偷把未展示内容标成已读。未读原因持久化，繁忙时排队合并；已读消息不会重复触发普通唤醒。主动机会默认关闭；开启后由每个主体的空闲思考入口合并检查，受间隔、滚动预算、明确联系范围和未回应冷却控制。旧逐聊天随机主动入口已移除。模型仍自行决定是否说话，普通 assistant 文本不会自动投递。

回复失败提示（`behavior.failureNotice`）默认关闭，可在“配置角色”里开启并填写一句固定的话。私聊、被 @ 或被叫名字触发的回合，因 AI 后端出错或超时失败、而这一轮一句都没尝试发送时，由程序把这句话发到原会话，免得对方以为被已读不回。同一会话在 `cooldownMs`（默认 10 分钟）内最多发一次；这句话走与定时固定文字相同的发送出口，暂停、静默、白名单和发送限额照常生效，并以请求 ID `turn-failure:<回合 ID>` 记入发送账本，之后的回合能看到自己说过。模型的普通回复、已发出部分内容的回合和群里的普通闲聊都不会触发。

Self、候选、主体意图及 75% 上下文管理见 [Self 与主体说明](SELF-CONTEXT.md)。

## 定时任务

管理台“主动与定时”支持保存、编辑、启停、删除、预览与执行记录。隔离模式仅允许编辑/预览。支持一次性、每天、每周、工作日、每月日期、每月第几个星期几、每年、特殊日期、每隔 N 天、时间窗内每隔 N 分钟、每天随机、每月随机、五段 cron，共 13 类。

AI 仅能在管理员私聊中登记任务。其他联系人或群默认不开放登记；开启 `scheduler.allowAiOtherTargets` 后，默认仍需在控制台确认。管理员可关闭 `scheduler.confirmAiOtherTargets`，使管理员私聊要求的跨目标任务在创建和修改后直接生效。目标白名单、暂停、免打扰、限额和不重放规则始终适用；普通聊天不会获得登记权限。

任务可发固定文字或把说明传入 AI 会话，配置时区、排除日期、随机偏移、最多执行次数。工作日以星期和管理员列出的节假日计算，不自动拉取法定调休安排。预览标出群聊静默。保存后的任务随机种子固定，管理台未保存预览的随机时间不保证与最终种子一致。

任务、预算、下一次时间及执行保留在 SQLite。先持久化执行占位再进入网络/模型；重启时未完成项变为 `unknown`，不会自动重放。错过执行按 `missedPolicy` 与宽限处理，一次推进到下一未来时间，不积压补发。暂停/静默期间到期记为跳过，不在恢复后集中发送。`maxRuns` 计到期处理次数，包含跳过；每日单任务预算计尝试次数，目标配额计已预留投递。历史保留最近 1000 条。

聊天回合（不含空闲时间）的提示附上目标是当前聊天、接下来要执行的定时任务，最多 3 条，多出的只给条数。每条给名称、按角色时区的下一次执行时间、重复规则，以及是固定文字还是 AI 任务；不给固定文字的正文和 AI 任务的说明，`/remind` 拿正文开头当名称时名称也不给。提示说明这是管理员安排的，不必主动提起，也不要再答应一遍。同一模型会话只给一次，任务新增、删除、改名或改规则后再给；任务按时执行只是推进到下一次，不算变化，所以定时任务唤醒的那一轮不会重复。列表清空后告诉一次“现在没有待执行的定时任务”。看过的列表摘要记在会话状态 `scheduleShown`，会话退休后从头计算。新会话交接里的 `scheduled` 同样不带正文和说明，已在这一行列出的任务不再重复。

AI 只能在配置的管理员私聊登记本人任务；允许跨目标时仍须管理台独立确认，AI 修改跨目标任务会再次停用等待批准。cron 只允许管理员管理台。`/remind help`、`/remind list` 等来自真实管理员私聊的命令由程序处理。模型必须登记成功后才能承诺提醒。任务里不得包含密钥或本机私人路径。

## GIF 动图阅读

`qq_image_read` 和 `sticker_read` 对 GIF 自动检测帧数和单次循环时长。静态图片仍返回原图；动图默认返回覆盖整段时间的至多 10 帧 PNG，每帧附原始帧序号、起始时间和持续时间。FFmpeg 先按透明区域、局部画面和 disposal 规则合成完整画面，再缩放到最长边 512 像素。不把 GIF 直接交给会静态化动画的附件链路。两个后端使用同一结果，Codex 转为有序 `inputImage`，DSH 使用 MCP 的多个 image block。

原始 GIF 仍以同一 `mediaId` 保存在所属角色媒体库，收藏和发送使用原始字节，不发送采样帧。返回的 `animation.complete=false` 表示本次没有展示全部帧，不能声称看完；抽样可能漏掉快速动作或短暂文字。

需要细看时，传可选 `animation`：

- `mode: "overview"`（默认）按时间抽样；`limit` 默认 10，范围 1–12。
- `mode: "frames"` 连续逐帧读取；`offset` 是从 0 开始的原始帧序号。按返回的 `nextFrameOffset` 继续，最后一页为 `null`。
- `startMs` / `endMs` 选择半开时间区间，也包括区间起点仍在显示的帧。结束时间不得超过返回的 `durationMs`。
- 首次 `qq_image_read` 后，可用 `sticker_read` 和返回的 `mediaId` 继续读取缓存，不必重新下载或先收藏；分页返回的 `animation.next` 可直接作为 `sticker_read` 参数。
- 重读同一主体、经历和图片序号会复用已完成的原图缓存；旧的、没有图片序号的缓存不会误作第 0 张图片。缓存仍保留全部来源和运维内容的披露限制。
- QQ 将 GIF 作为文件发送时，传包含该附件的经历 ID。`source` 可选 `image` 或 `file`，`index` 从 0 开始按所选类型计数；省略时优先图片，无图片再读图片文件。文件路径仍要求 `file_download` 工具和文件接收权限，遵守当前连接、来源白名单和文件库限额；仅接受 GIF、PNG、JPEG、WebP 文件名并校验实际图片格式。

例如 `sticker_read({"mediaId":"<已读取的图片ID>","animation":{"mode":"frames","offset":0,"limit":12}})`。同一 GIF 只解码一次循环，缺失或为零的帧间隔按 100 ms 解释，非零间隔保留。

GIF 原图最多 20 MiB，其他格式原图仍最多 8 MiB；图片文件同时遵守管理员配置的文件限额。图片下载复用文件下载器的 DNS 固定、逐次重定向校验、实际字节计数和 60 秒总时限，普通图片段最多同时两次下载；文件附件继续遵守每主体一次入库的限制。取消后不得登记迟到结果。超时、超限、HTTP 拒绝和选错经历/附件返回分别可辨认的错误及处理建议；失败不能当作已看图，也不自动反复下载同一链接。

运行环境需有 FFmpeg，可通过 `FFMPEG_PATH` 指定；时间信息从 GIF 结构读取，运行时不依赖 FFprobe。动图最多 1000 帧、120 秒、画布 1600 万像素、整段 1.5 亿画布像素。每次最长处理 15 秒、输出不超过 8 MiB、最多同时处理两次；单帧 GIF 也受 8 MiB 输出上限约束。暂停或取消回合会停止解码。缺少解码器、坏文件、超限及暂不支持的动画 WebP/APNG 均明确报错，不悄悄降级成第一帧。处理过程没有新增外部视觉服务。

专项测试使用合成 GIF 和真实 FFmpeg/FFprobe，覆盖不等帧间隔、透明叠加、disposal、末帧、分页、时间范围、两个读图入口、角色隔离、原始发送字节、后端图片序列和失败边界。协议回归不代表真实模型一定正确理解所有动作，真实 QQ 收件端效果需另行验证。

## 语音

“语音库”按角色导入文件、列出与本机试听。支持识别 WAV、MP3、Ogg、FLAC、M4A、AMR、SILK；默认最多 20 MiB、300 秒。常规音频由 FFprobe 实际解码检查时长；SILK 无解码器时保留为不透明附件、时长未知，不能声称听懂。音量与响度转换需要 FFmpeg，安装后可使用默认命令或在角色 `voice` 指定命令位置。

工具通过 `audioId` 读取/发送库内素材，不能传任意本机路径。来源语音只能从已观察消息读取。公开 URL 受 SSRF 和大小限制；原生 QQ 网关返回本机路径时，优先用该消息的文件引用调用 `get_record(out_format=wav)`，校验返回的 base64 音频、大小与时长。网关不提供音频字节时，管理员可在角色 `voice.localRoots` 明确列出音频缓存目录作为本机读取后备；默认空列表拒绝本机路径，规范化路径及符号链接不得逃出目录，模型无法设置这些目录。音频来源保留；跨会话回忆表达由机器人判断，向外部服务提交资料仍保留独立检查。发送字节由目标 OneBot/QQ 转码和接收，真实目标兼容性另验收。

DSH 的 MCP 结果可携带 audio block。当前 Codex 动态工具适配没有原生音频输入路径，会明确返回“不支持音频输入、无转录”，不能把音频元数据当转录。需要识别语音时可配置允许的转录 MCP，未经验证不自动启用外部服务。

## 嵌套转发与动作

`qq_forward_read` 仅展开已观察转发或其已归档子资源，默认 NapCat 使用 `get_forward_msg.message_id`，通用 OneBot 可将连接 `gateway` 设为 `onebot` 使用 `id`。QQ 的 `com.tencent.multimsg/contact` JSON 转发卡片也可提取其中已观察的 `meta.detail.resid`；其他卡片、畸形或过大 JSON 保持不透明。识别资源不保证网关支持拉取。对本项目已确认发送的消息，网关拒绝时可从成功回执关联的发送快照恢复外层；若内层也是自己先前成功发送的卡片，则逐层核对方向、连接、回执和源消息快照后读取；`source=confirmed-send-sources` 明确标记来源，`warnings` 保留网关读取失败。其他消息或无法取得的内层仍返回 `complete=false` 与 `FORWARD_FETCH_FAILED`，不触发重新发送。NapCat 已返回的 `forward.data.content` 会直接归档并展开，不重复拉取不可独立获取的内层 ID。最多五层、一次十个资源，分页返回；达到预算会给出可继续展开的资源。原文归档保留，节点中的图片可以继续读取。转发中的署名是来源声称的署名，不等于认证身份。

`qq_forward_send` 成功返回的 `eventId` 可直接交给 `qq_forward_read`，不必先获取 QQ 卡片。新发送在网络请求前持久化源消息段快照，只有已确认发送且身份、连接、会话、消息 ID 和回执一致才可使用；0.2.2 旧回执可关联当时已存在的源事件。深度、分页、资源预算、来源记录和暂停规则继续生效。对真实收到的消息使用原消息 ID 保留附件；不具备可复用消息 ID 的归档节点按文字署名发送。`qq_send_poke` 只对当前私聊对象或核对过的群成员操作。NapCat 的拍一拍依赖可用的 PacketBackend，禁用时返回 `DELIVERY_FAILED_PACKET_BACKEND_DISABLED`，不可用时返回 `DELIVERY_FAILED_PACKET_BACKEND_UNAVAILABLE`；失败请求不会自动重试。启用和重启属于网关配置操作，桥接不会自动修改。`qq_send_burst` 每条独立回执，失败停止并保留已成功前缀。

官方表情读取使用 `fetch_custom_face`。收藏和备注沿用旧网关 `add_custom_face`/`modify_custom_face`，由工具白名单单独控制；目标网关不支持则明确失败。仅返回 URL 的表情用内部摘要 ID 读取，不能虚构可编辑 emoji ID。角色本地表情库不依赖这两个扩展。

## 跨群与运维

**黑话学习已在 0.5.3 移除**：旧配置里的 `slang` 字段和工具白名单中的 `slang_*` 在读取时忽略，下次保存时不再写出；数据库里已有的候选和 learner 回合记录原样保留，程序不再读取，导出和恢复照常带上。此前 2026-10-27 起已暂停提供：候选无人确认、聊天中从未被查询，学习回合却持续消耗模型调用。

`crossGroup` 默认关闭，显式有向 `links` 只允许成员关系或活动汇总。没有反向隐式授权，不返回原文；每次查询入审计档案。

`operations` 默认关闭。启用前设置独立工作区、真实 ownerIds 和允许命令。L1 只读普通文件；L2 写入需要逐项确认且原文件变化时拒绝；L3 需额外开关、环境变量中的 TOTP 密钥及独立命令批准。模型拿不到确认码，也没有自批准工具。私有仓库和运维只在管理台创建的[独立受保护工作](PROTECTED-WORK.md)中处理，管理台展示并批准具体内容；QQ 私聊命令只提示转到管理台，不授予权限。级别与待批准请求不跨重启保留，TOTP 已用计数器持久化；暂停撤销权限。三次错误撤销本请求，五次累计错误锁定确认五分钟。禁止把完整主目录或含凭据的项目目录设为工作区。

## 场景记忆与日记

`memory_search` 的 `contextBefore` / `contextAfter` 默认各 2 条、最大各 5 条，`contextSeconds` 默认 600 秒、最大 3600 秒。结果包含同源消息的群/私聊标识、已观察名称、发言者、明确引用和 @；关键词与人物条件只用于选中命中消息。`conversation_read` 的 `aroundId` 自动保持原连接范围，分页可带 `connectionId`。管理台支持检索、场景展示、继续读前后文及原文分片。

个人日记由程序记录写作场景及时间；写作场景不代表日记叙述事情的发生场景。日记、普通跨会话回忆不锁住 QQ 发言，模型自行判断表达范围。完整约定和未知/截断处理见 [场景记忆设计](MEMORY-DESIGN.md)。

## 0.4.0 外部服务和语音

每个后端的 `toolServers` 可配置 stdio（`command`/`args`）、`transport: "http"` 或 `"sse"`（`url`）。网络 URL 允许 HTTPS 或本机 HTTP，不接受 URL 中的用户名、密码、查询参数或片段；认证通过 `headers` 指向环境变量名。例如：

```json
{
  "id": "exa",
  "transport": "http",
  "url": "https://mcp.exa.ai/mcp",
  "allowedTools": ["web_search_exa", "web_fetch_exa"]
}
```

角色需要显式启用 `external_tools` 和 `external_tool`。先发现实际 schema，再调用白名单工具；服务未配置返回空目录，未列出的工具无法调用。服务工具说明和结果属于不可信资料。示例 Exa 的搜索 schema 在本轮要求 `query` 和 `objective`，以后以实时目录为准。不得配置绕过统一 outbox 的第三方 QQ 发送工具。

`external_tool.audioInput` 接受 `audioId`、`dataArgument` 和可选 `mimeArgument`，按真实服务的顶层字段提供音频 base64/MIME；不能借它读取其他主体音频或绕过跨会话资料外发检查。尚无默认 ASR 提供者。只返回网页 URL 的图像/音频结果不会自动登记；服务应返回 MCP 内嵌内容或 blob。

macOS 本机 TTS：将角色 `voice.tts` 配为 `{"enabled":true,"voice":"Tingting"}`，再允许 `voice_synthesize`。工具返回登记的 audioId，模型可另行决定是否 `qq_send_voice`。需已有系统音色；默认关闭，不自动下载音色。生成文本只作为 TTS 输入来源保存，不是 ASR 转录。资料来源和运维限制会随生成音频保留。

## 后端连接恢复

“AI 后端”提供 DSH/Codex 连接状态、检测连接、恢复连接与自动恢复开关；DSH 可选择桌面实例并跟随重启后的端口。恢复只处理该后端的角色，保留 QQ 连接、记忆及兼容会话，不重放被中断的回复。操作方式、自动恢复边界和实例绑定见 [后端连接恢复](BACKEND-RECOVERY.md)。

## 短句与分条聊天

表达长短由各角色当前 Self 与场景决定；普通闲聊可先说一个短念头，需要补充再自然分条。`qq_send_burst.messages` 的每个元素会成为一条独立 QQ 消息，默认使用已配置的发送间隔；`qq_send.text` 中的换行仍在同一条消息内。工具提示明确这一区别，不强制角色每次连发，不机械切碎长文，也不改变字数校验、发送预算或限流。

恢复某个角色的表达偏好时，要通过管理员 Self 编辑追加新版本；只改初始化 persona 模板不会替换已有 Self。新版本在下一回合通过既有会话交接载入，历史版本保留。生产角色的私人 Self、账号及运行数据不纳入源码仓库。

管理台「经历与日记」的阅读全文窗口按普通正文显示标题、时间和段落。长文继续阅读时追加正文，保留前文；日记可切换修订版本，分页固定所选版本，避免阅读期间修订导致内容混杂。模型使用的 memory_read 仍保留原有结构化分块协议。
