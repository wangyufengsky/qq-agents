# 网页游戏 P3：公网部署与真实手机对战验收

P3 使用正常桥接中的独立游戏子进程、真实 QQ 来源和隔离 Codex 对手。本文提供部署与验收流程；代码回归通过、同机公网请求成功均不能替代手机蜂窝网络与真实完整对局。每次部署的实际结论存放在部署者的私有运维记录中，不把进行中的验收写成通过。

## 部署入口

先按 [P2 指南](WEB-GAME-P2.md)检查 Codex 角色、白名单、暂停意图与有限游戏预算。保存配置、部署版本和聊天会话基线；聊天数据库与已有游戏数据库分别做 SQLite 一致备份。仅显式启用参加测试的角色，保留其他权限。

反向代理只通往 `127.0.0.1:35824`（以实际 `games.port` 为准），不能映射管理端口。代理保留精确公网 Host，覆盖 `X-Forwarded-Proto: https`；HTTPS、同源 POST 与安全 Cookie 校验保持开启。公网 `/api/config`、`/api/status` 应返回 404。

已有域名时，用部署者管理的固定 HTTPS 域名及隧道；没有域名时可使用 Cloudflare Quick Tunnel 做临时验收：

```sh
cloudflared tunnel --url http://127.0.0.1:35824 --no-autoupdate --protocol http2
```

游戏子进程只监听本机，经隧道进入的请求在应用层看不到真实客户端地址。已登录玩家按房间会话单独限流；已经拿到本服务签发的加入请求的浏览器，按该请求单独限流；其余匿名访问按房间共用额度，一个房间被刷不会影响其他房间。公开群链接每个房间最多保留 64 条待确认请求，满额时只轮换最早的未确认公开请求，已确认的请求和私聊邀请不会被挤掉。应用层无法分辨同一房间内的不同匿名访客，持续高频刷同一房间仍可能让新访客暂时收到 429；需要更强防护时，在隧道或 CDN 边缘按真实客户端地址限速。

将本次分配的 HTTPS origin 保存为 `games.publicOrigin`，通过已认证管理 API 带当前 revision 保存配置。首次从关闭状态启用可启动游戏子进程；已有子进程时改端口、域名或预算须按正常流程排空并重启。配置与已启动入口不一致时，ready 与外部验证状态均为 false，拒绝投递新邀请。

[Cloudflare 官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)将 Quick Tunnel 定位为临时测试入口，进程重建会换域名，没有在线保证。电脑休眠、断网或关闭隧道都会使页面不可达。持久服务需要固定域名、隧道进程托管和稳定联网；不把一次临时验收称为正式长期上线。网络失败先保留错误与连接阶段，不能通过关闭证书校验、放宽 Origin 或修改系统代理绕过。

每次游戏子进程重启后，让手机关闭 Wi-Fi，从蜂窝网络访问 `/health`，将本次 challenge 交由部署者调用 `POST /api/games/verify-entry`。同机请求只做预检；未收到外部设备的本次 challenge 前不设置 external 验证标记。

## 从 QQ 发起并完成一局

1. 用允许的 QQ 账号私聊启用的 Codex 角色，发送 `下五子棋`。群里须明确 @ 角色；首次验收优先私聊。
2. 房主的“开始对局”按钮位于棋盘上方。从 QQ 邀请打开网页，点击确认加入，把完整确认口令私聊原 QQ 角色（群游戏也须私聊），收到原角色私聊的8位验证码后，返回本人网页输入验证码、继续加入并开始。不要替别人复制确认口令，也不要转交验证码。
3. 玩家执黑，选择空位并确认落点。等 AI 白棋落子后再进行下一步。页面轮询不会追加模型调用；有效决策的已终态失败最多自动追加一次尝试，之后房主可在网页请求一次受限重试，未知结果不自动重试。
4. 同一浏览器刷新并切后台约 20 秒再返回，检查身份、棋局与已落棋子保持一致。QQ 内置浏览器和 Safari/Chrome 分别验证，不能假设 Cookie 共享。
5. 继续到真实五连胜负或满盘和棋，记录服务端终局与手机结果一致。认输另作测试，不用认输代替正常规则终局；关闭、到期、模型失败也不算一整局已完成。

邀请由统一 QQ 发送器处理；只有确认回执才记为投递成功。`pending`/`unknown` 保留原请求，不重复发送。实际模型调用会消耗额度，同一后端的日常聊天与游戏串行协调。

## 重入与换域

在原 QQ 会话发送 `重新加入游戏 <roomId>`（roomId 为邀请路径 `/rooms/` 后的房间编号）。框架要求新鲜可信入站事件，校验原角色、QQ 连接与账号、后端、来源会话和实际发送者；浏览器不能指定身份。群内仍须 @ 角色。

新邀请保持原房间、棋局、参与者与座位，撤销该座位未完成的旧邀请/挑战。换浏览器时，原已登录浏览器在新浏览器确权完成前仍可使用；完成后轮换该座位会话，旧 Cookie 失效。邀请仍投递到原 QQ 会话，身份确认及验证码回执由发起人与原角色的私聊完成，私密邀请不进入聊天归档或模型返回值。重复处理同一来源事件不重新投递，未知投递不自动再发。

换域时先等待当前模型回合结束、保存游戏数据库与配置，再配置新 origin、排空重启并完成新启动的外部挑战。新域名不继承旧 Cookie，必须通过原 QQ 的重新加入命令取新邀请。旧 Host 请求被拒绝；终局或已到期房间不能用重入命令复活。

## 断线与异常验收

- 同一域名短暂断隧道：先记录房间 revision 和已落棋子，断开期间不反复提交。恢复隧道后刷新并核对权威状态与动作回执，确认没有重复落子。隧道断开不代表已提交的 AI 任务取消；合法在途回合可能继续完成。
- 如果隧道重建换域，按上面的换域流程重新确权，不清空房间或复制浏览器凭据。
- 当前实现没有主动的端到端公网存活监测；外部验证证明的是本次启动曾经可达。隧道后来失效时，部署者应暂停新建游戏并修复入口。管理状态 ready 只表示子进程与配置一致，不能用它证明此刻公网可达。
- AI 结果未知时保留运行证据，按 P2 的原生终态查询流程处理；不换 requestId、房间或后端自动补跑。认输只在玩家当前行动回合进行，终局后验证不能继续落子。

## 网页操作与身份确认

页面顶部显示身份与 AI 状态，房主可直接开始、暂停或结束房间。仅在服务端确认可安全重试时显示有限重试按钮，轮询不会自动重试模型。非本人回合不能认输，页面会解释原因。网页口令只能由原 QQ 发送者私聊原角色确认；群房间也只在私聊返回验证码，避免同群成员读取兑换码；QQ 返回的验证码须在申请加入的同一浏览器输入，5分钟内最多尝试5次，成功后一次消耗。验证码不会进入聊天上下文。升级前已登录的网页会话保留；升级前已在 QQ 确认但尚未兑换的旧邀请需要通过原 QQ 会话重新加入，以取得新验证码。

未认证请求使用独立限流；已验证会话按可信凭据隔离，伪造 Cookie 不能创建可信配额。同一浏览器重复申请复用待确认席位，不挤出其他浏览器的待确认记录。不同浏览器仍受房间最多8个待确认记录限制；达到上限时，原发起人可在原 QQ 会话发送 `重新加入游戏 <房间编号>`，撤销旧待确认记录并取得新邀请，不必等待15分钟。

## 私有验收记录

记录设备/系统、浏览器与版本（可获取时）、网络类型、时间和时区、发布提交以及脱敏房间代号。不要在公开仓库放真实 QQ 标识、完整邀请、确认口令、Cookie、聊天或原始截图。

| 路径/场景     | 必须记录                                             | 证据来源                   |
| ------------- | ---------------------------------------------------- | -------------------------- |
| QQ 内置浏览器 | 打开、确认、落点、AI 回应、刷新、后台返回            | 手机用户反馈或实机直接观察 |
| Safari/Chrome | 独立邀请或重新确权后的同座位流程                     | 手机用户反馈或实机直接观察 |
| 正常终局      | 连五/满盘结果、最终 revision、合法动作与模型任务终态 | 手机反馈 + 服务端辅助证据  |
| 认输          | 玩家回合认输、终局后拒绝落子                         | 手机反馈 + 服务端辅助证据  |
| 重入/换域     | 原房间/座位保留，原来源重新确权，旧邀请失效          | 手机反馈 + 服务端辅助证据  |
| 断隧道恢复    | 请求不明时对账、恢复后不重复落子                     | 操作记录 + 服务端辅助证据  |

每项结果写“通过 / 失败 / 阻塞 / 未验证”。桌面 WebKit/Chromium 和假网关回归单独记录，不能替代上表的手机或真实模型证据。
