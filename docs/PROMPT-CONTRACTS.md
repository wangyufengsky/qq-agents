# Prompt 与 Self 的职责

稳定层包含程序生成的固定身份、当前 Self 和场景协议。固定身份绑定本人 QQ、管理员和同伴的主体 ID/账号/别名，不依赖可成长 Self 保留这些数字。平台消息使用 senderId 识别当前发送者；引用作者独立判断。主人是程序配置确认的 AI 项目管理员，按固定账号识别。

稳定层对聊天和主体同样要求分清事实与喜好：事实看来源、说错就认，不为维持人设坚持错的事实；喜好和判断不因有人反对就马上改口附和；看法改变时说得出之前的理由和让它改变的原因，也不为显得有主见制造分歧。

Self 写性格、喜好、关系与表达倾向，允许长期发展；不维护工具参数、发送水位、授权凭据和强制收尾步骤。管理员改写通过 `/api/self` 的 edit 操作及 expectedVersion 创建新版本，旧版本与初始化模板保留。只改 persona 配置或导出 Markdown 不会替换已建立的 Self。运行中回合维持旧版，下一回合安全交接加载新版。

聊天与主体思考使用不同协议。聊天才处理回复、连续消息已读和潜水等待；主体只处理内部回顾、来源检索、日记与聊天意图，完成检查后结束。主体不直接发 QQ，目标聊天决定最终表达。日记按意愿写，Self 候选延后回顾，没有强制更新频率。

每轮增量提示包含场景、Self 版本、唤醒、新消息及 nowMs/ISO/时区/本地时间。相对日期基于程序时钟，消息发生时间另计。正常续轮不重复追加完整 Self；初次、版本更新或协议变化时重建并交接，历史原文留在账本按需查。

## 两个后端的工具协议

- Codex 动态工具直接使用各自 schema；回合能力在程序调用闭包中绑定，不向模型提示 context，也不让模型额外传 context 参数。
- DSH MCP 静态目录仅提供 `bridge_tools` 与 `bridge_call`。两个入口的外层参数带当前 context；`bridge_tools` 默认分页列出允许工具的名称和用途，指定最多 8 个 names 获取完整 schema。`bridge_call` 的 name 为发现的短名，arguments 按该 schema 填写，不再嵌套 context。
- 发现与执行都检查当前能力、场景和功能开关。知道一个名字不授予调用权限，暂停/撤权立即生效。聊天不能采纳 Self 候选，主体不能取得 QQ 发送入口。
- 旧 social\_\* 读取器不再由 Runtime 暴露或执行，避免绕过 App 的平台、时段、预算和来源记录。旧实现留在仓库用于历史参考；需要额外平台应接入统一 App 管理。
- 已禁用的调度、运维、App 功能，以及非管理员私聊的调度入口，不列为可调用工具。平台能力发现仍可说明当前配置状态。

## DSH 升级要求

生成 bundle 版本为 0.2.1。正式部署时先暂停角色，备份旧 bundle/profile，再生成并使用 DSH 支持的流程安装/重载新版。只更新 bridge 源码而保留正在运行的旧 MCP 进程，可能仍看到旧工具目录；部署验收必须实际确认 MCP tools/list 只有两个入口，并验证发现→调用→回执。旧 preset 和回退数据不得提前删除。

此修改不自动安装 bundle、切换运行服务、继承日常 Codex 插件、启用生图或改变主动联系与浏览时段配置。那些属于独立的部署/能力选择，不应靠 Self 假定已有。

## 回归范围

`test/prompt-contracts.test.mjs` 检查两个后端的参数契约、纯性格 Self 更新后账号仍存在、同伴配置变化触发交接、主体续轮时间与协议隔离、过期/暂停目录拒绝、旧浏览入口不能绕开配置、功能和来源裁剪。`test/server.test.mjs` 实测 MCP stdio 发现与内存读取链路；后端协议、上下文与现有完整回归仍需通过。离线或替身网关通过不代表真实 DSH/QQ 部署通过。
