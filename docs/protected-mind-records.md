# 受保护的工作笔记、聊天意图与文件

当前版本将私有仓库与运维放在[独立受保护任务](PROTECTED-WORK.md)中，工作任务没有共享笔记、意图和 Self 写入工具。以下保护规则继续适用于历史派生记录及保守写入防线。

`work_note` 保存当前角色的当前会话工作笔记；`intent_create` 保存后续联系计划。两者允许在读过私有 GitHub 或受限运维资料后保存，程序自动合并以下来源的保护标记：

- 本轮上下文中已经读过的受保护资料。
- 证据链里的原始事件、日记及其父来源。
- 更新前记录已有的保护标记。

保护字段是程序维护的 `protectedRepositories` 与 `protectedOperations`，不接受模型传入。修改正文、替换证据、完成后重新打开、取消意图，都不能删除已有保护标记。原始来源被删除后，记录本身的标记仍保留。JSON 导出、恢复和 SQLite 重启保留这些字段，无需数据库结构迁移。

## 读取与交接

所有普通聊天（包括管理员私聊）与空闲主体在记忆召回阶段隔离带 `protectedRepositories` 或 `protectedOperations` 的记录。搜索结果不返回其正文、标题或关联场景；直接按 ID 读取或展开受限锚点返回 `RECALL_SOURCE_NOT_ALLOWED`，不会因为拒绝读取而污染当前上下文。分页游标仍前进，空页不代表后面没有可读记录。场景邻文和引用即使省略了保护字段，也会按原始记录检查。

`work_notes`、意图列表和新会话交接同样过滤当前场景不能读取的受保护记录。只有当前独立工作任务可以按任务声明的仓库、运维范围读取；不同工作任务也不能读取彼此的记录。工作笔记的保存结果、聊天意图的创建、去重返回、更新、目标决定、排队唤醒与最近联系历史继续恢复保护。新会话不能把旧会话的受保护摘要当成公开内容。

工作笔记仍按角色及 conversation 隔离。`self_propose` / `self_review` 等共享人格写入仍拒绝受保护内容，默认证据校验也保持严格；只有带保护的笔记与意图存储可以引用受保护证据。

`subject.sessionMode=fresh` 的自动交接同样先隔离受保护笔记、意图、日志和日记标题，防止旧资料使每个新空闲回合都无法浏览。新回合建立前先归档旧会话与来源，保护记录不被删除或降级。主体显式读取受保护记录同样会被读取边界拒绝。详见 [空闲时间](SELF-CONTEXT.md#空闲时间主体回合)。

## 对外行为

保存不是披露授权。工作上下文没有 QQ 或公共网络出口。管理员只能在管理台审阅精确结果文字后解除这段文字的工作保护，原始记录不降级。普通聊天无法读取这些来源，因此不会因搜索到旧保护记录而失去正常联网能力。

## 恢复已受影响的聊天上下文

首次升级到独立工作版本时，程序先归档并退役普通聊天和主体的旧模型会话，再建立干净上下文；旧受保护记录继续被读取边界隔离。只清除来源标记而保留模型原上下文是不允许的，归档失败也不会解除保护。下面的手动恢复接口保留用于旧版本或针对性排障；不会重放发送。

管理员先备份私有数据目录，通过 `POST /api/conversation/state` 暂停指定会话，再调用需要管理令牌的 `POST /api/session/recover`，请求体为 `{"agentId":"角色 ID","conversation":"group:示例群号"}`。该入口只处理已暂停、存在保护标记的群聊或非管理员私聊；不向模型开放，也不会发 QQ 消息。

恢复会撤销旧能力、等待旧回合和发送链结束，归档原后端会话引用、保护来源和连续性记录，然后为下一回合建立空白后端上下文。受限笔记、意图和来源不会进入新交接；原始聊天、日记、工作笔记、发送账本、速率限制和后端历史均保留，旧上下文的延迟回调不能重新写入已恢复状态。归档失败时保留保护且继续暂停。恢复成功仍保持暂停，管理员检查后再通过会话状态接口解除暂停；不会重放先前失败或未知的发送。

自动调度不会把受保护的意图交接给无权接收的目标；记录保留为等待状态，仍受有效期约束。允许目标的意图仍要经过现场 `intent_decide`、主动联系预算、冷却和发送账本。投递前再次恢复记录保护，避免读取后到发送前的状态变化绕过检查。

## 主体保存文章

主体场景补充开放已配置的 `file_create`、`file_list`，以及随 `file_list` 一起开放的 `file_read`。只有管理员已经开启文件库及创建权限时才能写入。文章可用 `file_create(name,text)` 保存为 txt、md、csv、json 等 UTF-8 文本，返回 fileId；之后可用 `file_read` 读回原稿接着改，不必凭日志概要重写。文件内容不会执行。

不需要通用 `terminal_open`。原生终端入口仍禁止；模型不能传任意本机路径、越过自己的资料库或修改其他目录。主体不直接发送 QQ 文件；进入适当聊天后，通过现有 `qq_send_file` 和披露规则投递。文件继续继承私有仓库及运维资料保护。

## 回归边界

`test/work-note-privacy.test.mjs` 覆盖允许保存、证据链继承、更新不降级、各场景读取与交接、分页、来源删除、重启及导出恢复、派生日记与文件、意图创建与去重、排队唤醒、目标授权和发送前检查。测试使用临时数据库、受限临时文件库与模拟 QQ 网关，不写入真实人格记忆或发送真实 QQ 消息。
