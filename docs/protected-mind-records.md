# 受保护的工作笔记、聊天意图与文件

`work_note` 保存当前角色的当前会话工作笔记；`intent_create` 保存后续联系计划。两者允许在读过私有 GitHub 或受限运维资料后保存，程序自动合并以下来源的保护标记：

- 本轮上下文中已经读过的受保护资料。
- 证据链里的原始事件、日记及其父来源。
- 更新前记录已有的保护标记。

保护字段是程序维护的 `protectedRepositories` 与 `protectedOperations`，不接受模型传入。修改正文、替换证据、完成后重新打开、取消意图，都不能删除已有保护标记。原始来源被删除后，记录本身的标记仍保留。JSON 导出、恢复和 SQLite 重启保留这些字段，无需数据库结构迁移。

## 读取与交接

工作笔记的保存结果、`work_notes` 分页结果和初始会话交接均恢复上下文保护。聊天意图的创建、去重返回、列表、更新、目标决定、排队唤醒、交接摘要与最近联系历史也执行相同处理。新会话不能把旧会话的受保护摘要当成公开内容。

工作笔记仍按角色及 conversation 隔离。`self_propose` / `self_review` 等共享人格写入仍拒绝受保护内容，默认证据校验也保持严格；只有带保护的笔记与意图存储可以引用受保护证据。

## 对外行为

保存不是披露授权。读到这些记录后，公开检索、网页请求和 QQ 发送仍经过现有策略：私有仓库资料只能在已授权的主人私聊中披露，运维资料继续需要对应披露授权。

自动调度不会把受保护的意图交接给无权接收的目标；记录保留为等待状态，仍受有效期约束。允许目标的意图仍要经过现场 `intent_decide`、主动联系预算、冷却和发送账本。投递前再次恢复记录保护，避免读取后到发送前的状态变化绕过检查。

## 主体保存文章

主体场景补充开放已配置的 `file_create` 和 `file_list`。只有管理员已经开启文件库及创建权限时才能写入。文章可用 `file_create(name,text)` 保存为 txt、md、csv、json 等 UTF-8 文本，返回 fileId；文件内容不会执行。

不需要通用 `terminal_open`。原生终端入口仍禁止；模型不能传任意本机路径、越过自己的资料库或修改其他目录。主体不直接发送 QQ 文件；进入适当聊天后，通过现有 `qq_send_file` 和披露规则投递。文件继续继承私有仓库及运维资料保护。

## 回归边界

`test/work-note-privacy.test.mjs` 覆盖允许保存、证据链继承、更新不降级、各场景读取与交接、分页、来源删除、重启及导出恢复、派生日记与文件、意图创建与去重、排队唤醒、目标授权和发送前检查。测试使用临时数据库、受限临时文件库与模拟 QQ 网关，不写入真实人格记忆或发送真实 QQ 消息。
