# 连续聊天、公开浏览与来源保护

## 连续回复

`maxConsecutiveSends` 限制没有新的人类输入时，一批连续发送的尝试数。未设置时使用旧字段 `maxSendsPerTurn` 的值；旧配置中的 8 仍为 8，无需扩大限额。两字段同时存在时新字段优先。控制台角色编辑显示实际生效值。

完整读到当前聊天、当前连接的可信人类新消息后，批次恢复。输入必须由实时传输接收、具有存档身份，并在模型实际取得的完整正文中出现。新额度不累加。重复读取、已消费的水位、历史导入、引用/转发作者、自己和已配置的同伴机器人、仅截断摘要均不恢复额度。长消息通过 `memory_read` 按顺序读完后才推进。未知机器人无法由纯文本可靠识别；已配置同伴身份和原有互聊协调器继续生效。

批次消费和最近人类输入水位持久化，后端结束、失败、重试或重建会话不额外恢复额度。发送在连接级队列内检查和预留；失败/未知回执消耗额度，同一请求 ID 的已确认重试不会重复收费或投递。每分钟/每小时限速独立存在。

确定性的管理员控制回复和调度文本有独立调用预算；主动联系继续由主体意图的次数、冷却和幂等控制。已登记的 AI 调度运行有独立持久预算；一旦读到新的人类输入，同一后端执行中的后续聊天转为正常回复批次。读取消息不会放宽自主意图权限。

## 来源与具体出站请求

管理台使用独立审批 ID，不再取得模型 capability；审批接口和失效规则见 [凭据边界](CREDENTIAL-BOUNDARIES.md)。

旧 `disclosureTaint` 数组保留，按记录重新识别群聊、私聊、日记、运维和未知旧来源；群聊不会再被诊断为私聊。当前私聊的历史同样不是公共资料。缺失记录保守保留来源边界。已有会话、旧版本交接和 learner 注入的内容会补充来源标记；没有清空状态或全局批准。

持有这些来源不再等于禁止所有联网。以下依据由程序校验：

- 管理员为该角色开启 `network.autonomous`：持续允许普通公开网页读取、已启用平台的搜索/浏览/正文/评论和后端白名单中的外部工具调用。模型可以自行组织查询，无需当前人类消息、命令或逐次批准。该授权允许向外部服务提交查询内容；来源记录仍保留，关闭后立即恢复原检查。运维来源与 `audioInput` 媒体外发不在此授权内，凭据、内网和 MCP URL 委托检查始终先执行。
- 管理员在角色的 `network.publicUrls` 中登记的**精确 URL**，包括路径和查询参数；没有域名通配授权。默认列表为空。
- 以 `requestEventId` 引用本轮完整读到的可信人类消息，使用其中原样的公共 URL，或下面列出的明确请求。模型增加的字段、查询或不同地址不继承权限。
- 平台固定推荐/关注/热门入口，以及来自实际平台结果且没有 QQ 私密来源的内容记录；入口不携带模型生成的搜索文本。原有运维受限上下文对 App 的额外限制保留。
- 管理台批准的具体请求，绑定工具、完整参数、来源集合及当前上下文。普通 QQ 内容披露批准不会批准联网。参数变化、增加来源或换上下文后重新判断。

普通网页请求获准后，服务器返回的重定向属于同一次请求；每一跳仍检查凭据、协议、全部 DNS 结果和内网地址，并连接已校验的 IP。模型不能通过另一次 `web_fetch` 继承重定向权限。平台短链同样保留逐跳检查及平台目标约束。授权不能覆盖 SSRF 或凭据拒绝。

未开启自主联网时，外部 MCP 使用同一精确参数策略；开启后也只允许该角色后端白名单内的工具，不扩大服务和工具范围。音频先登记来源再批准具体媒体引用和参数。**不把任意 MCP 服务当作受控 URL 抓取器**：其实际 DNS/重定向无法由桥接预检查约束，因此 URL/文件地址参数返回 `EXTERNAL_URL_REQUIRES_WEB_FETCH`；公开网页用 `web_fetch`。已配置的 MCP 工具及其内部服务行为仍是独立信任边界，不能声称所有第三方工具内部联网都经过桥接的 SSRF 检查。

自动黑话学习保留原始证据；研究调用也走统一策略。持续授权开启后可使用已配置的研究工具；未开启或涉及运维受限资料时，留待在活动聊天中精确批准。候选提取和已处理水位仍可完成，不因联网拒绝反复提取同批证据。

## 当前用户请求与自主浏览

开启自主联网后，日常搜索和浏览不需要 `requestEventId`。固定提示、DSH 动态目录和 `app_capabilities` 都显示当前授权，切换权限时通过正常会话交接加载新规则，不删除历史。模型应提炼本次所需的公开查询内容，不复制聊天原文、私人日记或保密约定内容；这是模型行为要求，并非对任意查询文本的语义保密证明。

未开启持续权限时，工具参数 `requestEventId` 是消息来源引用，不能由模型声明 `userInitiated: true` 替代。支持：

| 人类当前消息                                | 对应请求                                                        |
| ------------------------------------------- | --------------------------------------------------------------- |
| `请打开 https://example.com/public?q=hello` | 该精确 URL 的 `web_fetch`，或对应记录的 `app_read/app_comments` |
| `/search zhihu 公共话题`                    | 知乎搜索原样查询                                                |
| `请在知乎搜索「公共话题」`                  | 同上；支持五个平台名称                                          |
| `/browse zhihu recommend`                   | 指定平台/入口；board 入口附板块名                               |
| `帮我测试知乎能不能浏览`、`测试所有平台`    | 对应平台的默认浏览入口；B站/贴吧为热门，其他为推荐              |
| `/boards heybox`                            | 小黑盒板块目录                                                  |
| `/mcp 服务ID 工具名 {"query":"公共话题"}`   | 精确 JSON 参数；服务与工具仍须管理员白名单                      |

这些是未开启自主联网时的明确请求入口，不是任意自然语言意图识别。语义含糊、跨轮指代或改写查询仍需持续权限或管理台具体批准；已开启自主联网的角色不能继续要求人类使用这些命令。消息中的引用、其他聊天和同伴发言不能冒充当前人类请求。

## 时段、配置与迁移

`apps.hours.enabled=false` 关闭时段限制；为 true 时 `scope="autonomous"` 只约束自主浏览，`scope="all"` 也约束明确用户请求。未设置新字段的旧配置仍保留原 09:00—22:00（或自定义）窗口，默认仅约束自主浏览。跨午夜时段和时区继续支持，开始等于结束表示全天。读取预算、平台权限和暂停始终独立生效。本地续读已保存记录不消耗平台网络预算，也不受浏览时段阻挡。

角色配置片段：

```json
{
  "maxConsecutiveSends": 8,
  "network": {
    "autonomous": true,
    "publicUrls": ["https://example.com/"]
  },
  "apps": {
    "enabled": true,
    "platforms": ["bilibili", "zhihu", "xiaohongshu", "tieba", "heybox"],
    "hours": {
      "enabled": false,
      "scope": "autonomous",
      "start": "09:00",
      "end": "22:00",
      "timezone": "Asia/Shanghai"
    }
  }
}
```

这只是示例，不会自动应用到任何现有角色。`network.autonomous` 缺省为 false，旧配置保留原行为。管理台“机器人 → 配置角色”可逐角色开启“允许自主搜索与联网浏览”，不改变另一角色；开启不会绕过平台开关、时段、预算和暂停，也不会新增外部工具或自动对外发送消息。上线前备份配置、SQLite 和发布快照；管理员决定是否关闭时段、是否添加精确公开 URL。旧发送字段可保留，或显式迁移为新字段。旧记录不具有新实时输入证明，不会被重新读取来兑换新发送额度；下一条真实人类来信可正常推进。会话重建、两个后端 schema/提示更新和批准面板应在独立部署验收中一起检查。合并代码不等于部署。

## 诊断与验证范围

控制台受限动作卡显示具体工具参数、完整来源集合和来源类别计数；批准只对展示的请求生效。模型侧错误不回显私密参数或凭据：`REPLY_BURST_LIMIT` 表示等待实际新人类输入；`SEND_RATE_LIMIT` 是独立时间限速；`PRIVATE_RECOLLECTION_EXTERNAL_CALL_BLOCKED` 表示该请求缺少合适的出站依据；`APP_OUTSIDE_HOURS` 表示配置的时段拒绝。

`test/chat-network-policy.test.mjs` 使用 FakeTransport、临时 SQLite、合成 DNS/HTTP/MCP：覆盖连续超过 8 次人机交互、两个后端闭包、跨回合/并发/失败/幂等、读水位、旧交接、私聊/群聊/日记/运维、音频精确授权、MCP URL 变体、合法/内网/带凭据重定向、时区和主动/用户请求。完整 `npm run verify` 还覆盖原有主动意图、机器人互聊、调度、文件和会话恢复。

`test/autonomous-network.test.mjs` 另覆盖两种后端的自主工具调用路径、权限持久化/撤销/角色隔离、历史来源保留、平台记录读取、运维限制及权限变化后的提示交接。控制台表单保存覆盖在 `test/config-updates.test.mjs`。

这些测试不代表真实 DSH、Codex、QQ 或平台登录已经在线验收；实际服务探测和生产部署需单独记录。
