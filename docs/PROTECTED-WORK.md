# 独立受保护工作

普通 QQ 私聊（包括主人）、群聊和空闲主体负责聊天、公开浏览、日记与普通记忆。私有仓库和运维在管理台创建的独立任务中处理。两类上下文使用同一个角色的基础人格，但不共用模型会话、工具能力或原始工作记录。无需增加 QQ 账号或复制角色。

## 使用流程

1. 在角色配置中登记允许读取的私有仓库；需要运维时启用运维并设置受限工作区。默认不开启这些权限。
2. 打开「系统 → 受保护工作」，选择角色，点「新建任务」，填写任务说明，并明确选择一个仓库或运维权限，两者必须分任务处理；也可以不选权限，仅起草隔离结果。创建与开始是独立操作；任务不会因 QQ 消息自动启动。
3. 点击「开始任务」。模型只能使用记忆读取、所选仓库的只读工具，以及已开启的运维工具。L1–L3 级别、写入和命令仍需管理台单独批准，L3 继续使用 TOTP。
4. 任务通过 `protected_work_submit` 提交候选结果。继续任务时重新建立模型会话，仅提供本任务说明与最近工作记录；失败、中断或重启不会自动重跑。
5. 管理员审阅完整结果文字、选择聊天并勾选确认后，才能交回结果。审批绑定版本和 SHA-256 摘要；旧页面不能批准已被修改的结果。

**批准会解除所示文字的工作保护，把它加入角色普通记忆。** 所选聊天是结果的落点，不是永久保密范围；角色以后可正常回忆这段获批文字。原始文件、仓库内容、任务说明和其他草稿仍在工作上下文中，审批不会自动发送 QQ。不要批准仍应保密的原文。

## 边界与失败范围

| 行为                                    | 普通聊天 / 空闲主体                       | 独立工作任务                                                       |
| --------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------ |
| 回忆普通聊天、普通日记                  | 按现有记忆与联网策略允许                  | 按当前角色记忆权限允许                                             |
| 读历史私有仓库或运维记录                | 搜索过滤；直接指定 ID 拒绝                | 仅任务声明的仓库、运维范围；其他工作任务记录不可读                 |
| 公开搜索、网页、平台浏览                | 按角色开关、白名单和预算正常运行          | 不提供这些工具；外发策略再拒绝                                     |
| 私有 GitHub                             | 请求转到独立工作                          | 仅选定且仍在配置白名单的仓库，凭据与路径检查保留                   |
| 运维                                    | 不提供；QQ `/ops` 仅提示管理台，L0 可撤权 | 仍需逐项审批，不获得任意终端                                       |
| 写共享 Self、笔记、意图、媒体或 QQ 发送 | 原有规则                                  | 不提供；直接 QQ 发送也被执行层拒绝                                 |
| 任务失败 / 取消                         | 不设置角色整体故障，不消耗 QQ 发送预算    | 仅任务状态改变；取消中止当前能力与已批准命令，撤销待批准操作和结果 |

普通聊天遇到受保护记录时，是该次读取被拒绝或该条搜索结果被过滤，不会先把正文交给模型再封锁整个会话。分页游标仍前进，空页不表示后面没有内容。历史文件、媒体、生成图片、等待消息、场景引用、Self 证据、主动意图与会话交接都使用读取边界。

工作上下文在模型请求中标记 `protectedWork`。Codex 关闭原生浏览器、应用、图像生成、计算机使用和 Shell；DSH 使用桥接工具守卫；其他 API 后端只获得本任务工具清单。能力凭据仍按角色与会话绑定，伪造 `@work:` 名称不能获得权限。保护范围是桥接控制的模型会话与工具，不改变模型服务商的数据处理方式。

## 升级与持久化

首次升级时，先退役普通聊天与空闲主体的旧后端会话、归档原来源和连续性，再清除旧上下文的强保护标记。原始聊天、日记、文件、发送回执、已读进度、限额和保护字段保留。新会话交接过滤原始受保护资料，旧能力的延迟回调不能恢复已退役状态。归档失败时不会解除保护。

任务状态保存在现有 `runtime` 表的 `@work:<UUID>` 下，工作事件进入同范围账本，因此现有 SQLite 备份和完整导出覆盖任务。重启把进行中的任务标为中断，取消中的任务标为取消；只由管理员再次开始，不自动重放命令或 QQ 投递。任务终态为已取消或已交回，不能继续调用旧能力。

## 管理 API

所有请求都需要管理令牌，不接受角色能力凭据：

- `GET /api/protected-work?agentId=...`：查看任务与候选结果。
- `POST /api/protected-work`，`{agentId,instruction,repositories?,operations?}`：创建。
- 同一路径，`{agentId,taskId,action:"run"|"cancel"}`：开始或取消。
- 同一路径，`{agentId,taskId,action:"release",revision,digest,target}`：批准精确结果；返回 `sent:false`。

隔离模式不能开始模型任务，全局或角色暂停时不能运行。任务审批不会扩大原配置的仓库和运维权限。每个仓库任务至多声明一个仓库，不能同时启用运维；因此不能先读运维或另一私有仓库，再把这些原文作为查询参数发往 GitHub。持久化的旧混合任务也不能恢复执行。
