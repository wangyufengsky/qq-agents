# 网页游戏 P1b：五子棋规则与界面

五子棋已作为 `gomoku` 模块接入 [P1a 通用内核](WEB-GAME-P1A.md)。同一套身份、房间、动作事务、回执与 SQLite 存储同时服务五子棋和隐藏选择夹具，内核没有新增棋盘或棋色分支。

当前入口是仅本机的双人验证程序，两名参与者均为合成身份。首个产品预设仍是一人一 AI；真实 QQ 身份、邀请投递、AI worker 和框架门禁在 P2 接入，公网与真机产品验收随后完成。正常 QQ Agents 服务不会自动启动游戏端口。

## 启动与对局

在 Node.js 24+、已安装依赖的代码目录执行：

```sh
node scripts/game-p1b.mjs --data /absolute/private/game-p1b-data --port 35823
```

使用新的独立私有目录，不能指向生产、P0 或 P1a 数据。只监听 `127.0.0.1`，没有公网参数，拒绝转发头及错误 Host/Origin。不要把合成身份确认入口接到隧道。邀请保存在该目录的 `invitations.json`，不输出到控制台。

1. 使用两个独立浏览器配置或无痕上下文，分别打开黑方、白方邀请，点击「确认加入」。同一浏览器的普通标签页共享 Cookie，不能模拟两个身份。
2. 双方加入后，黑方展开「对局操作」并点击「开始」。黑方先行，双方交替。
3. 点棋盘选择位置，在坐标与 3×3 局部放大区核对或调整，再点独立的「确认落点」。选点不会直接提交；确认按钮及放大格子至少 44×44 像素。坐标 A1 对应左上角，O15 对应右下角。
4. 15×15 棋盘，无禁手，横、竖或任一斜线连续五个及以上获胜；满盘且无人获胜为和棋。最后一步同时填满棋盘并连成五子时，以获胜为准。
5. 当前行动者可点击「我要认输 → 确认认输」，对手获胜。首版顺序回合契约不允许非当前行动者提交认输。房主可暂停、恢复或结束房间；结束房间不伪造胜负。
6. 刷新恢复 Cookie 与棋局。版本变化、切后台或旋转屏幕会清除旧选点，重新同步后再选择。

提交前，页面将完整动作编号、原版本与正文保存到当前标签页的会话存储。响应丢失时，轮询先查询原回执；没有回执时保留待确认操作，点击「查询待确认操作」才以原编号与原版本重试。明确拒绝后重新同步并要求重选，不自动换编号或版本补交。浏览器无法保存待确认操作时禁用写操作，仍可查看棋局。

轮询正常间隔约 2–3 秒，不重叠；失败后指数退避并加入抖动，上限 30 秒。切后台停止安排轮询，返回前台立即同步。同步失败禁用旧快照操作。关闭脚本时，已认证用户仍能看到服务端渲染的棋盘和结果，所有按钮禁用，可手动刷新快照。

`Ctrl+C` 停止程序。重启保留旧局、会话、动作回执，并在容量允许时新建一局写入邀请文件。最多保留 8 个房间；容量满时保留旧邀请。邀请 15 分钟有效，房间及会话期限沿用 P1a。没有对既有游戏数据或生产数据库的迁移。

## 模块接口

实现为 `src/games/gomoku/module.mjs`，当前 `moduleVersion/rulesVersion/stateSchemaVersion/uiVersion` 均为 `1`。固定摘要包括规则、页面模板、浏览器脚本、样式及依赖锁文件。更改发布内容需要新的模块版本；旧房间引用缺失或内容不符时拒绝加载，不悄悄换规则。

| 项目          | 约定                                                                                                   |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| 人数与座位    | 固定两人；座位 0 执黑，座位 1 执白；支持人类/AI 声明，但当前内核仍拒绝真实 AI 动作并记录 P2 未实现阻断 |
| 选项          | 严格空对象，不接受客户端自定棋盘尺寸或规则                                                             |
| `game.place`  | `{x,y}`，各为 0–14 的整数；非空、越界、错误回合均拒绝                                                  |
| `game.resign` | 严格空对象；当前行动者认输                                                                             |
| 私有状态      | 棋盘、双方 participantId、轮次、上一落点、认输标记                                                     |
| 玩家投影      | 公开棋盘、上一落点、自己的颜色、当前轮次、可否行动、结果；不含 QQ 主体、Cookie 或凭据                  |
| 结果          | `FIVE_OR_MORE`、`BOARD_FULL`、`RESIGNED`；获胜仅列胜者，和棋胜者为空                                   |

坐标、颜色、棋盘尺寸、胜负检测均属于模块；界面为五子棋专用。其他网页游戏可继续注册自己的 schema、规则和投影，使用同一内核而无需实现棋盘。

## 验证

```sh
node --test --test-timeout=120000 test/game-*.test.mjs
node scripts/game-p1b-browser-acceptance.mjs
# 已安装匹配的 Playwright WebKit 时：
node scripts/game-p1b-browser-acceptance.mjs --webkit
npm run verify
```

自动测试覆盖四方向与长连、黑白获胜、满盘和棋、认输、非法落点，并将相同的身份隔离、事务回滚、幂等、回执、版本冲突、暂停、持久化重启和模块固定契约分别运行于 `gomoku` 与 `choice-probe`。CLI 测试验证独立目录、仅本机监听、邀请私密输出及重启。

浏览器验收使用 Chromium/WebKit 的隔离上下文及手机视口，覆盖完整对局、放大确认、版本变化清除选点、横竖屏布局、提交前/后断网与原操作对账、失败同步、认输、无脚本快照及存储拒绝。它验证的是浏览器引擎与模拟手机视口，不代表这版已在 QQ 内置浏览器或异地真机上验收；P0 的真机成功记录也不能替代 P1b/P3 的产品验收。
