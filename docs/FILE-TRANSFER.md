# 自主文件下载与发送

文件权限按角色独立配置，默认关闭。管理员在网页上方选好角色，打开“文件”页，展开“自主文件收发”，开启“启用此 AI 的文件权限”并保存后，该角色可以在已有白名单中的群聊和私聊内自主操作，不需要每次确认。保存不解除任何暂停，不连接 QQ，也不修改另一角色的权限；会中止被修改角色的当前回合，下一回合使用新权限。已经发出的网关请求可能仍完成，明确回执仍会归档。

## 网页操作

“文件”页最上面是这个角色的文件库：已用容量，每个文件一行写类型、名称（过长截断，悬停看全文）、大小和时间，可以下载到本机。管理员可以直接放入文件导入到这个库，上传不会发送到 QQ。

下面的“自主文件收发”默认折叠，标题栏写着当前允许的操作和单文件上限，例如“已允许接收 · 上限 20 MiB”；浏览器会记住展开过的区块。展开后分别控制公开链接下载、QQ 附件下载、文件发送和文本文件生成。默认单文件上限 20 MiB、文件库总量 200 MiB、1000 个文件；单文件最高可配置 50 MiB。超限明确失败，不自动删除历史文件。

“允许导入的本机专用目录”可选，每行一个绝对路径（输入框里有示例），目录编号从 0 开始。管理员提供相对路径后，AI 可将其中的文件导入库内。路径遍历、符号链接、硬链接、隐藏或常见凭据文件名会被拒绝；其他 AI 的文件库不能作为导入源。留空不影响链接下载、QQ 附件下载和网页导入。目录授权表示允许该角色在已授权会话中发送其中的普通文件，不走运维写入审批。

示例配置（位于每个 `agents[]` 的 `files`）：

```json
{
  "enabled": false,
  "download": true,
  "receive": true,
  "send": true,
  "create": true,
  "maxBytes": 20971520,
  "maxTotalBytes": 209715200,
  "maxFiles": 1000,
  "localRoots": []
}
```

网页保存会同步配置该角色的文件工具白名单；使用完整 JSON 配置时，还需将下表工具加入该角色的 `tools`。DSH 的独立 bundle/preset 也需要重新生成并更新工具目录；Codex 使用桥接动态工具定义。原配置无需迁移，未出现 `files` 时按默认关闭处理。

## AI 工具与文件身份

| 工具            | 作用                                                           |
| --------------- | -------------------------------------------------------------- |
| `file_list`     | 按名称查询本主体文件，返回分页、用量与可导入目录编号           |
| `file_read`     | 分页读取本主体文件库里的 UTF-8 文本文件，按 `nextOffset` 续读  |
| `file_download` | 公开 HTTP(S) URL，或已观察记录的 `eventId` + 附件序号，二选一  |
| `file_create`   | 创建 UTF-8 文本附件；支持 txt/md/csv/json/tsv/log/xml/yaml/yml |
| `file_import`   | 从管理员配置的目录编号及相对路径导入                           |
| `qq_send_file`  | 用 `fileId` 和唯一 `requestId` 向当前绑定会话发送              |

文件保存在数据目录的 `files/<agentId>/`，字节文件与元信息均按主体隔离。`fileId` 是 SHA-256 内容摘要，相同内容在各自库内去重，显示名称采用最后登记的名称；发送时可指定显示名称。知道另一个 AI 的 `fileId` 不会获得访问权。元信息记录来源、文件名、大小、创建时间和内容摘要，不返回本机绝对路径或带访问参数的下载链接。

下载不会执行、解压或解释文件。工具返回 `contentRead=false`，不能据此声称读懂 PDF、Word、Excel 或压缩包。`file_read` 只读文本扩展名（与 `file_create` 相同）且是有效 UTF-8 的文件，其他文件返回 `FILE_NOT_TEXT`；开启文件库时它和其他文件工具一起加入 `tools`；之前保存的配置里只要有 `file_list`，升级后同样可用。读取结果带 `contentRead=true`、`totalChars` 和 `nextOffset`，`nextOffset` 为 null 才算读完。受保护文件读不到（`RECALL_SOURCE_NOT_ALLOWED`），来自其他聊天的文件读过后本回合按读过那里的资料处理，与 `qq_send_file` 相同。文本生成不会把普通文字冒充 Office/PDF 格式。来自现有运维文件读取的受限内容仍保留原披露限制，普通文件收发不进入运维确认队列。

图片附件可另用 `qq_image_read({id: "<附件经历ID>", source: "file", index: 0})` 读取像素；无普通图片段时可省略 `source`。这个入口通过同一个 `file_download` 授权路径下载，仍要求文件接收权限、工具白名单、来源白名单及文件库配额，不能绕过文件权限。校验为 GIF 后返回多帧，其他支持格式返回图片；GIF 原图另限 20 MiB、其他格式 8 MiB。读取结果保留文件库中相同内容的已有来源和运维限制；后续可用返回的 `mediaId` 在 `sticker_read` 中继续读图。

兼容 NapCat 消息段的 `file` 文件名字段及上传通知的 `name/file_name` 字段，包括已经保存的历史附件。私聊附件直链接口明确报告 PacketBackend 禁用或不可用时，会通过同一网关的 `download_file_stream` 获取已观察到的附件 ID。分片下载校验文件大小、序号、完整性和 60 秒超时，并响应回合取消；不接受模型指定的文件 ID、网关本机路径或任意 URL，也不需要打开本机导入权限或 PacketBackend。

## QQ 与下载协议

普通 file 消息段、群 `group_upload` 与私聊 `offline_file` 通知会显示附件名称。下载仅使用本主体、当前 QQ 连接及仍允许来源中已归档的附件；不接受模型自行编造的 QQ 文件 ID。附件直链过期时可通过 `get_group_file_url` / `get_private_file_url` 刷新。网关没有可用直链时明确失败，不读取其返回的任意本机路径。

公网下载复用现有 URL/DNS 检查，每次重定向重新校验并固定连接到已检查的地址。限制总时间与实际响应字节；不发送 Cookie、自定义认证头，不访问本机或普通内网地址。暂停或撤权取消下载，迟到结果不能登记为可发送文件。同一角色同时只接收一个入库操作，发送沿用已有连接队列、限频和幂等规则。

发送使用 `upload_group_file` / `upload_private_file`，传递库内校验过的 base64 字节，避免宿主机与容器路径不一致。只有非空 `file_id` 回执才能记为成功；超时或缺少回执记为 unknown，同一 requestId 不重发，也不能将“已上传”描述为“对方已阅读”。原生网关不支持接口时明确失败，不调整 PacketBackend。

接口依据：[NapCat 文件指南](https://napneko.github.io/develop/file)、[群文件上传实现](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/go-cqhttp/UploadGroupFile.ts)、[私聊上传实现](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/go-cqhttp/UploadPrivateFile.ts)。这些接口的存在不代表已验收所有 NapCat 版本或真实 QQ 客户端。

## 隔离验收 · 2026-10-25

- 文件专项测试覆盖权限持久化、主体隔离、容量、重复内容、重启、完整性、导入路径、内部库导入拒绝、真实 HTTP 大小限制与取消、私网/重定向限制、附件来源、权限撤销、发送队列、幂等和管理接口认证。
- DSH 与 Codex 各跑一次真实模型 `files` 用例，分别完成公开链接下载、合成 QQ 附件下载、文本创建和两次附件发送；共四次发送均只到回环模拟网关。发送字节 SHA-256 与所属库的 fileId 一致，生成文本内容符合指定值，普通流程没有确认请求。
- 合成附件使用公开 Node.gitignore 文本作为下载对象，未读取真实 QQ 文件或发送真实 QQ 消息。真实 QQ 私聊/群聊展示、账号文件配额、过期附件及各版本兼容性尚未做生产验收。
- 浏览器实查权限保存、切换角色后独立开关与文件列表、网页选择文件并导入成功；预览处于隔离模式且全局/角色均暂停。

复验：`npm run verify`；已配置独立测试账号后运行 `npm run acceptance:live -- --allow-real-models --run-all --case files`。真实模型会使用既有账号额度，本轮共两个模型用例回合，接口未返回可核对费用。原始测试输出和预览数据保存在忽略目录，不提交到 Git。

本功能没有进行生产部署或文件迁移，生产角色保持暂停。备份文件库时需连同 `files/` 保存；现有 SQLite/JSON 历史导出不包含附件字节。库内文件不会自动过期删除，达到配额后由管理员清理专用数据目录或调整容量。

合并前审查补齐了生成文本文件的凭据过滤：文件入库前复用普通 QQ 消息的检查，拒绝凭据形状的文本和能力令牌，不影响普通文件的持续授权。文件分支单独复测 178 项测试全部通过；新增用例确认拒绝发生在登记及发送之前，普通文本仍无需逐项确认。
