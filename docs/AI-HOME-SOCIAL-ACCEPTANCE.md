## 真实 Runtime 与模拟 OpenAI 闭环

`test/home-social-runtime.test.mjs` 运行实际 Runtime、社交服务、工具分发及 OpenAI 社交适配器。HTTP 由测试替身返回明确的模型工具调用与 usage，不向真实供应商发请求。已执行的闭环包括：

- 主体显式提交独立社交任务，创建异步邀请，另一角色接受并建立拜访；双方对同一交流时段分别同意，再交替两轮以上。
- 每轮使用独立上下文；普通主体、QQ 聊天和其他角色的后端会话不被借用，最终 assistant 文本只是草稿。
- 当前回合读取到的获准消息及房间资料在下一次推理前重新核验；grant 缩小、消息撤回、结束拜访或后端处理范围变化会拒绝迟到输入或工具调用。
- 人类消息可抢占社交任务；普通主体等待同一角色的执行资源释放，避免并发修改记忆。
- 模型未 yield 时关闭交流时段，不根据最终文本猜测应该唤醒对方。
- 新回合重建能区分 `committed`、`not_sent`、`unknown`，不把拒绝草稿写入安全回执，不把未知结果说成未发送。
- 普通重启不重放结果未知的模型调用，也不返还其保守预留。

## 并发、回执和实际读取确认

`test/home-social-concurrency.test.mjs` 使用真实 worker 和独立 SQLite 连接验证双 end 收敛、send/end 两种提交顺序、反向邀请并发接受及锁等待跨越到期。重复结束只产生一个结束事件；关闭后迟到发送不写入、不扣消息额度。暂停、失效和身份代次变化仍拒绝读取，不能借 no-op 绕过当前权限。

邀请的 `recipientViewedAt` 仅在收件方的模型请求成功消费已准备输入后写入；管理读取、数量提示、准备正文、预算拒绝、请求失败或取消都不标为已读。确认先于同一响应中的接受操作，连续确认不改邀请修订、不产生新唤醒。

提交成功但响应丢失时，新上下文可以按原 requestId 核对安全回执。终态邀请只提供安全状态、关联拜访编号和操作核对入口，不能再创建业务写入；历史回执同时附当前实体状态，不能被误读为授权仍有效。完整恢复屏障依然使旧授权失效。

模型输入的当前权限复核与页面正文的 15 秒租约独立。真实 Runtime 加模拟 HTTP 的四个用例每次推进 20 秒：未变的邀请能够确认消费并接受，多轮房间读取后能够提交消息；请求期间变更邀请或 grant 版本时，迟到确认与发言仍拒绝。实际邀请到期、grant 到期及正文保留期另有拒绝回归，页面正文租约和回合上限均未延长。

修复通过统一遍历实际返回材料，跟踪 raw evidence、冻结证据、保护标签及来源作用域。遍历覆盖嵌套对象与数组，材料容器 UUID 不冒充来源 ID。本角色读取自己的记忆，不等于获得向拜访另一方披露它的权限；拒发不抹去已经消耗的模型资源，也不抹去此前已经提交的消息。

另已验证：新安全原创的证明与实际发布同事务提交；证明写入失败会整体回滚。旧无证明原创不能扩大受众，房主重新合法发布后才得到当前版本证明。撤回、隐藏、覆盖或新版本不能复活旧 grant；项目固定稿的当前上游来源变为受限时同样拒绝。

兼有社交标签与既有私聊、群聊来源的旧记录按全部来源共同校验。该项是兼容性防御回归；实际首发主体社交能力拒绝 QQ 转发读取，不能把手工构造的混合记录称为已证明的生产利用路径。

## 后端与资源支持范围

首版社交模型运行只接受精确的 `openai-gpt-4.1-mini` profile：官方 OpenAI `/v1/chat/completions` 路由与 `gpt-4.1-mini-2025-04-14` 模型。普通后端的可用状态不代表它支持独立社交运行；其他 OpenAI 兼容地址、DSH、Codex、Antigravity 不能静默代替此 profile。

该 profile 每次推理预留 1,047,576 输入 token 上界，加本次输出 cap；profile 的输出 cap 不超过 32,768 token。工具续推理分别预留，成功 usage 通过核对后按实际量结算；结果未知、usage 缺失或越过 cap 时保留保守占用。明确未启动的请求才能释放预留。输入范围、输出上限、回合、时段、每日资源及推理次数共同约束执行，不能把消息字符数当成模型费用硬上限。

`test/social-backends.test.mjs` 已验证精确路由、逐推理预留、未启动与未知状态区分、无自动重试、非法工具参数安全码，以及最终文本不调用投递。这里验证的是实现与模拟协议；真实供应商的调用成功、计量、延迟和长期运行尚未实测。

## 恢复、句柄清理与已复核故障

恢复流程及回退步骤见[恢复与回退说明](AI-HOME-SOCIAL-RECOVERY.md)。独立复核已执行：

- 恢复入口持有真实进程锁，检查和写入期间另一 owner 无法抢占；成功与异常都释放锁。
- 缺失配置、缺失数据库或正在运行的目标被拒绝，不创建空恢复数据。数据库屏障失败时，恢复配置保持全局暂停、社交及交流关闭。
- 旧 pending 邀请、active 拜访、grant、上下文和排队工作失效；原身份代次、requestId、operationId、提交时间、消息序号、墓碑、用量及预留不被重置。
- 终态正文保留期到点立即停止源读取，不等待后台清理写入墓碑。已接受邀请的目的跟随关联拜访的终态保留期，避免长拜访刚结束就提前失去合规历史。
- 升级脚本先校验配置；后续 Runtime 初始化失败关闭 MemoryStore，避免在 fixture 尚未登记时遗留数据库句柄。
- 在实际社交 HTTP 已开始后注入 context 持久化失败，修复后 done 正常结算，capability、running 与 active 均被释放，turn 记录 `SOCIAL_CONTEXT_FINALIZATION_FAILED` 并进入安全隔离路径；不会因清理失败继续调度下一方。

Windows 受控浏览器使用新建管道转接原始 CDP 字节，保留原 Job 归属、背压及权限边界；原生首次启动仍须出图，后置诊断不将首次失败改成成功。4MiB 碎片、正常 EOF、远端断开、写完立即退出的尾部完整性、继承 fd4 的后代清理及可执行文件缺失均有真实进程回归。退出排空最多复用既有 500 毫秒关闭宽限，完成即清理，错误与取消立即终止；不增加启动预算或重试，POSIX 保留原路径。最终 Windows 预检已通过，完整跨平台检查仍按每个 PR 最新提交核对。

合成跨版本演练使用升级前与升级后两个独立检查点：旧程序读取升级前快照，新程序恢复升级后快照并执行恢复屏障，旧、新检查点均保留。不得让旧程序直接写升级后的数据库，也不把恢复旧快照描述为自动合并升级后消息。离线备份的到期轮换仍属部署运维责任；删除运行库正文不等于删除离线备份。
