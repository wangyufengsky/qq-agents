# 第五轮：调度、配置隔离与维护边界

本轮覆盖到期索引、按影响范围提交配置、运行时与工具职责拆分、增量质量门禁和默认配置收尾。源码与合成回归不代表生产部署或真实 QQ / 模型验收。

## 到期索引与状态兼容

`runtime` 仍为权威状态。`conversation_due` 是可重建派生表，以 `(agent_id, conversation)` 为主键，记录 `next_due_at` 和 `state_version`，以 `(next_due_at, agent_id, conversation)` 建立部分索引。SQLite 内置 JSON 表达式和触发器让插入、修改、删除、恢复与索引更新处于同一事务，不依赖只有新版进程才注册的 SQL 函数。启动时重建索引，导出不包含它；数据库 `user_version` 保持 6，此变更为附加表与索引。

下一到期点覆盖排队唤醒、有限睡眠和回复检查，并考虑会话暂停、静默结束时间及主动冷却。每 tick 最多取 256 条；暂停、无权限、忙碌、断线等不能执行的条目延后 30 秒再次检查，避免每秒反复读取。状态写入会立即更新索引；解除暂停、重新接入连接及配置生效会刷新相关角色的索引。已有回合结束时继续立即检查积压唤醒。限频按实际窗口结束时间重排。后台积压分批处理，不在一次 tick 中无限展开。

聊天状态新增内部 `_conversationSchema: 1` 标记。无标记的 v0 状态兼容读取，并在下次写入时升级；保留未知业务字段，不把内部标记带入状态 API。未知未来版本拒绝读取。主体状态、游标、发送预算等内部账本保留各自既有格式。

验证覆盖状态与索引回滚、旧导出恢复、重开数据库、索引丢失重建、暂停/恢复、断线/重连、忙碌、限频、过期候选不能覆盖新状态、删除同步，以及超过单批大小的积压。生命周期整理会话也改用部分索引；黑话研究的可选扫描仍沿用原有流程。

## 配置影响范围

提交仍遵循“校验版本 → 原子落盘 → 同步撤销受影响授权 → 清理旧资源”。落盘失败保留旧配置与回合。已落盘后的清理故障返回 `saved: true` 和诊断警告，失败资源仍由停机流程持有以便重试。

| 改动                                       | 影响                                                                   |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| 参与度、主体检查间隔/配额                  | 更新未来调度，保留当前回合与连接                                       |
| 角色权限、人设、模型、后端绑定，或删除角色 | 撤销该角色的旧授权、回合、适配器与运维授权；等待回合收尾；保留其他角色 |
| 后端实际配置                               | 处理所有依赖该后端的角色，保留其他后端和 QQ 连接                       |
| QQ 连接实际配置                            | 处理绑定角色并关闭该连接；其他连接保留；由管理员手动重新接入           |
| 连接/后端显示名称                          | 保留回合和连接                                                         |
| 全局暂停/运行模式/互聊策略                 | 按全局依赖处理角色；只有运行模式或连接配置变化才关闭连接               |
| 管理端口                                   | 保存后提示重启生效，当前监听不被替换                                   |

托管 QQ 进程只在其连接配置将变更时要求先停机；角色权限变更无需停止它。配置写入仍串行，受影响后端的管理操作互斥；无关角色在异步清理期间可以继续回合和工具调用。旧连接对象晚到的事件和故障不能再进入替代连接。

API 返回 `affectedAgents`、`reconnectConnections`、`reconnectRequired` 与 `restartRequired`，管理台据此展示结果。该变更不自动连接 QQ，也不自动恢复生产运行。

## 模块与工具边界

- `core/config-impact.mjs` 计算配置依赖，`core/config-updates.mjs` 管理提交与资源清理。
- `core/turn-runner.mjs` 管理模型回合、恢复、取消及收尾，`ctx.done` 覆盖整个收尾过程。
- `core/delivery.mjs` 持有每连接发送队列和预算调和状态，负责预算/出站记录/回执事务。确认送达后审计失败仍不能降级已确认回执。
- `core/runtime-status.mjs` 集中状态展示的字段白名单，不包含 capability。
- `tools/registry.mjs` 将 schema、描述和处理函数绑定，发现与调用使用同一注册表。核心工具改为具名处理函数；启动时检查缺失和重复处理函数，拒绝原型属性名称。`catalog → index` 的依赖被移除。

`Runtime` 保留协调与兼容入口，从约 1,400 行降至约 840 行。此次没有把所有模块迁移成 TypeScript。

## 质量门禁与安装包

`npm run verify` 依次运行语法检查、ESLint、checkJs、示例配置一致性、全部测试、Prettier 和隐私扫描。ESLint 对本轮协调/状态/工具模块及相应测试启用 recommended 规则；checkJs 覆盖配置影响分析、默认配置、会话版本与到期索引。具体范围写在 `eslint.config.mjs` 和 `tsconfig.json`，后续可逐模块扩展。

本地完整验证通过：712 项测试、214 个 JavaScript 模块语法检查，以及 ESLint、checkJs、默认配置、格式和 268 个文件的隐私扫描。

新增 PR / main 的 GitHub Actions，使用 Node 24，在 Linux 与 macOS 执行 `npm ci` 和 `npm run verify`。动作固定提交 SHA，权限为只读；媒体回归安装 FFmpeg。常规 CI 只使用合成数据和本机替身，不配置生产凭据或真实模型。

运行默认配置位于 `core/default-config.mjs`。`npm run defaults:write` 从它生成示例，`defaults:check` 防止漂移。启动不再读取 `examples/config.example.json`。安装包通过 `files` 白名单包含源码、公开静态资源、vendor 与文档，排除运行数据、测试和示例。集成测试实际执行 `npm pack`，解包后复用已安装依赖，验证缺少 examples 时首次启动、第二次保留配置、HTTP 状态与页面，以及 SIGTERM 后清锁；它不是独立依赖安装或生产重启测试。

相关工具规则依据：[ESLint 配置](https://eslint.org/docs/latest/use/configure/configuration-files)、[TypeScript checkJs](https://www.typescriptlang.org/tsconfig/checkJs.html)。

## 合成性能结果

运行 `npm run scheduling:benchmark -- --synthetic`。Node v24.19.0、SQLite 3.53.4、macOS / Apple M1 Pro；单角色，每条聊天状态额外 1 KiB，无到期任务，预热 10 次后采样 100 次。角色不暂停，但不接入 QQ、不启用主体检查或黑话研究，也不调用模型。

| 会话数 | 旧候选 SQL p95（ms） | 新索引查询 p95（ms） | 新版完整 tick p95（ms） | 完整 tick 采样期间事件循环 p99（ms） |
| ------ | -------------------- | -------------------- | ----------------------- | ------------------------------------ |
| 10     | 0.009                | 0.022                | 0.083                   | 1.151                                |
| 100    | 0.048                | 0.022                | 0.054                   | 1.188                                |
| 1,000  | 0.496                | 0.028                | 0.062                   | 1.269                                |
| 10,000 | 7.623                | 0.021                | 0.052                   | 1.801                                |

旧候选 SQL 与新版完整 tick 是不同口径，不把两者相除宣称总体提速。小样本下索引查询存在固定成本；大样本确认避免逐条解析状态。查询计划使用 `conversation_due_time`，无需临时排序。以上结果不代表密集到期任务、可选研究流程、真实网关、模型或生产磁盘负载的性能。
