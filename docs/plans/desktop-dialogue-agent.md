# 桌面对话 Agent 三阶段计划

桌面小窝是可进出的本机公共群聊。一个角色在 QQ 私聊、QQ 群聊和桌边共用 Self、角色记忆和模型配置，各场景维护自己的模型 Session 和进度。房间里只有一位角色时仍采用群聊语义。相关讨论见 [#271](https://github.com/wangyufengsky/qq-agents/issues/271)。

## 第一阶段：正式桌面回合与进出房间

- 通过现有功能 Agent、会话契约和工具凭据运行桌边回合，复用模型和思考档位、当前 Self、生命周期和回合记录。
- 管理员邀请唤醒受邀角色的主人格。主人格正常完成回合并同意时，框架安排桌面 Agent 入场。角色主动来访由主人格敲门，管理员请进后走同一入场入口。
- 入场时建立新消息游标。离开终止此轮房间参与，其他角色继续处理各自的输入。有效 QQ 来信抢占同角色桌边生成，等待原生回合收尾，保留在场状态。
- 验收覆盖同意、婉拒、撤销、超时、忙碌排队、迟到回复、多人进退、会话续接和工具凭据隔离。

## 第二阶段：持久化、双向记忆与别处近况

- 把桌面公共时间线写入现有 SQLite，使用桌面来源和稳定消息 ID，保存角色的在场、发言确认和实际呈现记录。历史记录随整库备份恢复，角色导出只带自身记忆及关联资料。
- 入场角色可主动分页回看公共历史。从入场位置开始派发实时消息；回查按历史资料处理，不增加回复额度，不生成本人曾参与的经历。
- 桌面与 QQ、主人格共享同角色的普通记忆。桌面普通群聊资料参与回忆和「别处近况」；仅在可信身份映射和真实往来证据成立时按人关联。保留原有受保护资料和私聊来源规则。
- 验收覆盖重启、同消息去重、分页、备份恢复、跨场景记忆、来源拒绝和近况的实际呈现。

## 第三阶段：工具、主人格接力与验收

- 桌边使用框架已有且获准的公开搜索、网页、附件、本人文件和草稿等工具。各后端根据能力交付媒体，并在工具执行时检查角色授权、在场和资料来源。
- 桌边可给同角色主人格提交工作或联系提议并查看回执。QQ 行动由获准的目标会话处理，继续使用既有发送审阅和投递账本。主人格决定、目标处理和最终投递分别显示。
- 管理台可在现有管理员鉴权下查看桌面 Session 和回合。对 DSH、Codex、Antigravity 分别验证兼容性与取消，使用隔离数据、假网关覆盖实际投递契约。本机更新和真实角色验收按已有运维授权进行。
