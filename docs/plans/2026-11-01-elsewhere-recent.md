# 别处近况：让角色记得刚在别的聊天里和谁说过话

实施记录，设计基线：PR #128 / f47fc4c，实施跟踪：[Issue #131](https://github.com/wangyufengsky/qq-agents/issues/131)。以下方案已实现，离线验收使用临时数据和假网关；CI 与合并状态以实施 PR 为准，部署版本以实际运行进程为准。交付遵循 [AGENTS.md](../../AGENTS.md) 与 [CONTRIBUTING.md](../../CONTRIBUTING.md)。

## 背景

模型会话按“角色 × QQ 会话”划分（见 [架构](../ARCHITECTURE.md)），每个群、每个私聊各有一个模型上下文；经历、日记、Self、人物卡、相处记录和意图在同一角色的各会话间共享。这一划分保留：合并成全局会话会让群聊和私聊互相阻塞、上下文更快挤满、发送目标和授权更难分清，一次不确定回合还会牵连所有聊天。

现在跨会话回忆只能靠模型自己发起：它要先想到调用 `memory_search`。人物卡里的 `interaction.lastDirectAt` 只给最近一次直接来往的时间，不说在哪；人物卡在一个会话里也只展示一次，之后变化的来往计数不会让它重新出现。于是会出现这种情况：A 十分钟前在私聊里刚和角色聊过，现在到群里 @ 角色，角色却像刚见到 A 一样。真人在这种场合自然会记得“刚刚聊过”。

## 目标

- 在普通聊天回合开始时，为本轮涉及的人附上一条**被动索引**：对方在别的聊天里最近和角色直接来往过，在哪、什么时候、几条、从谁开始，以及回查入口。
- 只给索引，不给原文。是否回查、是否提起、怎么说，由角色结合现场判断。
- 与人物卡、心情一样“每个模型会话见一次、有新变化再见一次”，不在每轮重复。

## 非目标

- 不合并模型会话，不改变“角色 × 会话”的串行与并行模型。
- 不跨角色共享，不读取其他角色的记录。
- 不由程序生成别处对话的摘要，不把别处原文放进提示。
- 不推进任何会话的已读水位，不增加回复额度，不产生新的发送、外部访问或运维授权。
- 不涉及别人之间的对话：只统计角色自己参与的直接来往。“A 在别的群里和其他人聊天”不会出现。

## 方案

### 适用范围

只用于 `group:` / `private:` 聊天回合。`@subject` 空闲回合已有自己的空闲素材，`@work:` 受保护工作不使用本功能。

本轮涉及的人沿用 `peopleInTurn`（新增消息的发言人、私聊对方、被 @ 或被引用的人），与人物卡一致，不扩大范围。

### 取哪些记录

对每个人，在 `windowMs`（默认 6 小时，与来往统计的 `EPISODE_GAP` 一致）内取**当前会话以外**的直接来往，判定规则复用 `src/core/closeness.mjs` 的 `interactionEvents`：

- 私聊里的收发、群里明确 @ 或引用的收发才算直接来往；仅同在一个群不算。
- 发出的消息只计投递账本确认 `sent` 的记录；`pending` / `unknown` 不算。
- 同一消息按身份、别名和 requestId 去重。
- 带 `protectedOperations` / `protectedRepositories` 标记的记录跳过；每条结果再经 `recallBoundary(...).allowed` 检查，受保护工作上下文按其自身规则读取。
- **收到的消息只取该会话已处理的部分**：`seq` 不超过那个会话的 `readThroughSeq`。还排在队列里、角色尚未在原会话处理的私聊，不能先在群里被看到，否则模型可能在群里抢答私聊内容。暂停会话中归档但没有处理过的消息同理不出现。

`interactionEvents` 目前固定扫描 30 天，实现时增加起始时间参数，让本功能只查窗口内的记录，避免每轮为每个人重扫 30 天。

### 呈现

每人最多列 2 个别处会话，每轮最多 6 条，按最近时间排序；超出的按人物记 `more: { [personId]: 条数 }` 计数。每条形如：

```json
{
  "personId": "30000",
  "where": "private",
  "lastAt": "2026-11-01T09:40:00.000Z",
  "messages": 6,
  "startedBy": "them",
  "lastFrom": "you",
  "continuation": { "tool": "memory_read", "id": "<最后一条记录 ID>" }
}
```

- `where`：对方私聊记为 `"private"`；群聊记为具体来源键（如 `"group:20000"`），群名只在有观察记录时附带，并注明观察时间，不用当前群名冒充当时名称。
- `messages`：窗口内该会话的直接来往条数；`startedBy` / `lastFrom` 只取 `them` / `you`。
- `continuation` 指向最后一条记录；通过它或 `memory_search` 回查得到的跨会话结果本来就是 `markReadEligible=false`，不推进当前会话水位。

提示行放在人物卡之后、“还没了结的事”之前，说明随数据一起给出，不写入稳定层，因此**不触发会话交接**：

> 别处近况（程序按你自己参与的直接来往统计，只是索引，不是原文；要用时按 continuation 回查。fromPrivate 是对方私聊里的事，不要在群里提起内容，除非对方先提；其他会话的经历由你结合场合判断怎么用）：…

私聊记录出现在群聊回合时加 `fromPrivate: true`，与“还没了结的事”里 `fromPrivate` 的约定一致。群聊记录出现在私聊或另一个群里时，沿用 [场景记忆](../MEMORY-DESIGN.md) 的约定，由角色判断表达。

### 展示去重

- 会话状态新增可选字段 `elsewhereShown: { [personId]: <最近记录 ID> }`，记录这个模型会话已见到的最新别处来往。
- 新会话（`fresh`）从空开始；同一会话里，只有某人在别处出现了更新的直接来往才再次列出。
- `model_turns` 记录本轮实际展示的条目（`personId`、`where`、最后记录 ID），供以后追查某条回复时看到了什么，与 `moodShown`、`personCards` 相同。
- 这些字段只用于展示去重，不是权限状态；缺失时按未展示处理，不需要数据库迁移。

### 配置

| 配置                          | 默认值 | 说明                                         |
| ----------------------------- | ------ | -------------------------------------------- |
| `behavior.elsewhere.enabled`  | `true` | 只增加回合内的索引提示，不新增发送或外部访问 |
| `behavior.elsewhere.windowMs` | 6 小时 | 范围 10 分钟–24 小时                         |

已同步 `default-config.mjs`、`policy.mjs` 配置校验、`npm run defaults:write` 生成的 `examples/config.example.json` 与 [配置说明](../CONFIGURATION.md)。已有显式配置保持不变。

## 兼容性

- 数据表、导出与导入格式不变；新增的会话状态字段可选，旧状态缺省即未展示。
- 稳定提示不变，不触发交接。开启后，已有会话在下一次涉及相关人的回合里会第一次看到别处近况。
- 每轮新增的提示受条数上限约束；窗口查询有 `agent_id`、时间与类型条件；`EXPLAIN QUERY PLAN` 确认使用已有 `events_time` 索引，无需新增索引或旧库迁移。

## 测试计划

`test/elsewhere.test.mjs`、`test/elsewhere-lifecycle.test.mjs` 使用临时目录和假网关，不调用真实模型；配置与会话保留分别由 `test/config-elsewhere-policy.test.mjs`、`test/session-config-retention.test.mjs` 覆盖：

- 私聊刚聊过的人在群里 @ 角色，群聊回合出现一条 `where: "private"`、`fromPrivate: true` 的索引，正文不出现在提示里。
- 群聊里的直接来往出现在随后的私聊回合；当前会话自己的记录不出现。
- 仅同群、未 @ 未引用的发言不计；`pending` / `unknown` 发送不计；同一消息的别名只计一次。
- 原会话尚未处理（`seq` 大于其 `readThroughSeq`）的收到消息不出现；处理后才出现。
- 受保护运维 / 私有仓库来源、`@work:` 记录不出现；受保护工作上下文按 `canRead` 判定。
- 同一会话第二轮不重复；别处有更新记录后再列一次；新会话重新列出。
- 超过窗口的记录不出现；条数上限与 `more` 计数正确。
- 回查后当前会话 `readThroughSeq` 不变，回复额度不变。
- 开关关闭时提示与旧版本逐字一致。
- 跨角色：另一角色与同一 QQ 号的来往不出现。
