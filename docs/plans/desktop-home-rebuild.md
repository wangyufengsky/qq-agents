# 桌面小窝重构

桌面小窝要让 AI 自主决定怎样和主人及同伴相处。愿景及 13 条原文载于 [总 Issue #375](https://github.com/wangyufengsky/qq-agents/issues/375)。遇到现有实现或平台能力与契约冲突时，提交具体情形和方案，请维护者先确认。子任务各自验证，全部接入正常入口后逐条验收。

## 实现顺序

| 交付范围                                                                         | 设计                                                                                                                                                                                                  | 对应契约    |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| [房间与 Session #377](https://github.com/wangyufengsky/qq-agents/issues/377)     | 公共消息发布时确定并持久记录接收者。每角色队列按序保留聊天、唤醒与交互，模型实际收到后提交进度。桌边活动使用该角色稳定的 `@desktop`，普通上下文整理负责退休。桌面工具声明稳定，调用时按当前能力判断。 | 1–4、7–9    |
| [桌面客户端与操作 #376](https://github.com/wangyufengsky/qq-agents/issues/376)   | 一个观察开关，覆盖授权期间所有在场角色。按需将完整桌面交给该角色的 Session。窗口与浏览器目标分别授权直至取消，客户端按实际目标确认执行结果。通过同一队列提交摸头及带实际起终位置的拖动。              | 4–6、11–12  |
| [双向留言 #379](https://github.com/wangyufengsky/qq-agents/issues/379)           | 同角色桌面与主人格互相留言。两个接收入口各用原会话，真正提交模型输入时更新交付状态。复用角色身份与资料权限。                                                                                          | 3、10、13   |
| [正式入口切换与验收 #378](https://github.com/wangyufengsky/qq-agents/issues/378) | 接通现有管理台、Electron 和三种模型适配器，验证 QQ 会话能力的桌面对应入口，迁移显式配置与历史，清理被替换的旧逻辑。                                                                                   | 1–13 及愿景 |

房间模块拥有在场关系、唤醒排程与发言额度。收到新事件时追加到对应角色队列。活跃角色独立通过它的普通桌面 Session 处理队列头，进行中的工具和消息由该角色顺序处理。人类消息刷新房间额度，时间经过也可刷新。额度只计已发布的角色发言。默认六轮，刷新、自动唤醒均为十分钟，主人可配置。

沿用公开房间归档和每角色收到的消息事件。模型输入取未提交的在场消息，优先保证触发本轮的消息在输入中。后续回合读取其余积压。在场状态和会话的生命周期各自推进。角色退出时结束该次到访的触摸和位置事件，已投递的消息及会话供后来接续。

权限执行点位于工具调用与本机操作。观察开关明确支持在场角色看完整桌面，主动要求和自主观察走同一条路径。窗口和浏览器操控绑定角色及具体目标。用户取消授权时结束受影响操作。在独立测试实例验证收件、操作回执和失败恢复。

## 端到端验收

- 让角色先后进门、离席并回到小窝，核对每一条消息的接收者及同一角色在模型端的会话引用。忙时连发、超过一页的积压与迟到结果也纳入检查。
- 在同一角色、同一 Session 比较观察授权前后工具目录及调用结果。获准后在主动和自主回合分别取到完整桌面，再接着聊天和移动。用双屏环境验证取图范围。
- 分别授权窗口和浏览器，验证连续操作、明确取消、旧目标消失、未确认结果及目标重新选择。记录实际 macOS 和 Windows 验收范围。
- 用假时钟检查六轮接话、两种刷新路径、十分钟自主唤醒、休息和角色选择下次唤醒。摸头和拖动触发正常活动，拖动报告实际起点及终点。执行其他动作时收到新事件要排队。
- 通过真实框架接口验证同伴自然接话、主人格双向留言、查看或照料花园、记忆与现有权限允许的意图操作。资料源及所处会话一并核对。
- 用既有配置和数据库副本测试升级，比较角色身份、会话引用、公开历史与显式用户设置。按贡献指南跑完整校验和多平台 CI，更新使用文档及日志。实际部署按仓库的更新约定核对能力变化。
