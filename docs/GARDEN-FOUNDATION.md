# 小窝花园

在主 SQLite 增加一座九宫格共享花园。维护者可在隔离测试里通过 `runtime.home.garden` 运行种植、浇水、施肥、收成、铲除枯株、售卖和赠礼。管理员和角色的操作共用库存和公共账户。初始化时写入 1,000 元及一笔对应账目。

## 内部调用

- `initialize(now, settings)` 显式创建花园。已建园时返回当前状态。现有实例打开数据库时创建空表，保留原有配置和数据。
- `read(now)` 返回当前花园时钟、九块地、可用产物、最近账目、赠礼与操作记录。读取按结算时钟推算作物。
- `act(now, actor, { requestId, action })` 在同一 SQLite 事务检查余额、库存、植株 ID、角色回合额度并保存结果。来源入口绑定身份和回合，转发调用前负责权限检查。重复请求返回原回执。购买使用总报价，合并买种与播种使用种子单价。
- `configure(now, expectedRevision, settings)` 更新运行配置。速度倍率与角色每轮操作次数从保存后生效。成熟时长、种植时锁定的用水与品质规则适用于新播种。市价按交易当时的配置核对。

桌面花园页由后续批次接入。角色工具使用 `garden_read({ view })` 和 `garden_act({ requestId, kind, args })`。动作种类为字符串，按种类在服务端以严格 schema 校验 `args`，天气与事件可沿用动作封装。框架注入源会话与执行身份。运行配置和授权条件在服务端读取。后续私聊委托默认有效期为 24 个花园小时，从全园时钟读取到期时间。

## 时钟与作物

桌面小窝有效的连接心跳推动花园时钟。连接退出、租约过期、全局暂停或花园停用停止计时。单个角色暂停时，保持连接的花园继续运行。关停或失联的时间不会在重启后补算。心跳运行检查点合并写入 SQLite，倍率切换、成功经营操作与正常关停同步保留花园进度。异常退出从最后一个持久检查点恢复。

速度范围为 0.125× 至 16×，默认 1×，支持 4× 测试。每 24 个花园小时进入下一花园日。倍率只在推进花园时钟时乘一次。一次浇水加 35，水分上限为 100。水分不足 20 时半速，为零时停长。连续 48 个花园小时无水后枯萎，铲除后可立即补种。成熟时固定品质，肥料按该作物需肥次数分摊加分。天气、遮雨棚效果和每日事件在后续批次接入。

## 管理台与主人格经营

进入管理台「花园」，可预览开园入口。管理员确认初始资金后显式开园，由系统写入一笔建园账目。九块地、仓库、活动、账本和赠礼记录都从主 SQLite 读取。使用桌面小窝保持花园时钟运行，页面上的状态提示会说明当前暂停原因。管理员可在九宫格播种、浇水、施肥、收成和清理枯株，在仓库购买种子或肥料、出售和赠送产物。

展开「花园设置」可即时调整倍率、花园暂停、每轮操作次数、价格及作物参数，也可通过复制已有作物新增条目。作物 ID 用于历史库存，停种后已有植株仍可收成。成功保存后，倍率和新的交易报价立即生效，存量作物保留播种时的生长规则。建园时的初始资金可在账本回查。花园保留至少一种可从集市免费取得并可售卖的作物。

首次开园会为现有 `@subject` 声明花园工具，受影响的旧会话可能按现有机制交接一次。角色默认没有经营授权。管理员在「允许使用主人格工具经营」中选择角色后，该角色可在自己实际运行的主人格回合用 `garden_read` 查看状态和优先提示，并用 `garden_act` 经营。权限与额度逐次校验，调整配置、停园和撤权不切换工具声明。普通聊天与日常任务继续使用各自已有的能力边界。气候、事件、QQ 图文分享和桌面花园页按后续阶段接入。

浏览器验证可用本机 Chromium 运行 `QQ_TEST_GARDEN_BROWSER=/path/to/chromium node --test test/garden-management.browser.mjs`。管理 API 和隔离主人格验证见 `test/garden-management.test.mjs`。

## 验证与恢复

运行 `node --test --test-timeout=120000 test/garden.test.mjs`。测试覆盖九宫格初始化、旧库兼容、在线 SQLite 备份恢复、零余额回本、共享库存竞争结果、幂等回执、生长分段、调速与暂停。使用一份主 SQLite 的一致备份保留共享花园。单角色记忆导出维持原有角色边界。
