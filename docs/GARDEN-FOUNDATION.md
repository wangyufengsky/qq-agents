# 小窝花园

在主 SQLite 增加一座九宫格共享花园。维护者可在隔离测试里通过 `runtime.home.garden` 运行种植、浇水、施肥、收成、铲除枯株、售卖和赠礼。管理员和角色的操作共用库存和公共账户。初始化时写入 1,000 元及一笔对应账目。

## 内部调用

- `initialize(now, settings)` 显式创建花园。已建园时返回当前状态。现有实例打开数据库时创建空表，保留原有配置和数据。
- `read(now)` 返回当前花园时钟、九块地、可用产物、最近账目、赠礼与操作记录。读取按结算时钟推算作物。
- `act(now, actor, { requestId, action })` 在同一 SQLite 事务检查余额、库存、植株 ID、角色回合额度并保存结果。来源入口绑定身份和回合，转发调用前负责权限检查。重复请求返回原回执。购买使用总报价，合并买种与播种使用种子单价。
- `configure(now, expectedRevision, settings)` 更新运行配置。速度倍率与角色每轮操作次数从保存后生效。成熟时长、种植时锁定的用水与品质规则适用于新播种。市价按交易当时的配置核对。

角色工具使用 `garden_read({ view })` 和 `garden_act({ requestId, kind, args })`。动作种类为字符串，按种类在服务端以严格 schema 校验 `args`，天气与事件可沿用动作封装。框架注入源会话与执行身份。运行配置和授权条件在服务端读取。私聊浇水委托默认有效期为 24 个花园小时，从全园时钟读取到期时间。

## 时钟与作物

开园后，桥接服务在 live 模式下按设定倍率推进花园时钟。桌面小窝未打开、断线或重连，作物都继续生长，管理台、聊天与桌面看到同一份进度。全局暂停、隔离模式、配置切换、升级维护或手动停园时停止计时，单个角色暂停只影响该角色。桥接服务定期把进度写入 SQLite，正常关停会保存最后一段进度。重启从已保存的进度继续，停机时间不计入花园。

速度范围为 0.125× 至 16×，默认 1×，支持 4× 测试。每 24 个花园小时进入下一花园日。倍率只在推进花园时钟时乘一次。一次浇水加 35，水分上限为 100。水分不足 20 时半速，为零时停长。经典照料下默认连续 48 个花园小时无水后枯萎，铲除后可立即补种。成熟时固定品质，肥料按该作物需肥次数分摊加分。天气、遮雨棚效果和每日事件在后续批次接入。

## 管理台与主人格经营

进入管理台「花园」，可预览开园入口。管理员确认初始资金后显式开园，由系统写入一笔建园账目。九块地、仓库、活动、账本和赠礼记录都从主 SQLite 读取。即使桌面小窝关闭，也可在管理台经营。花园暂停时，页面会显示原因。右上角金币显示公共余额。管理员在九宫格选中地块后可播种、浇水、施肥、收成和清理枯株，在仓库购买种子或肥料、出售和赠送产物。

展开「花园设置」可即时调整倍率、花园暂停、每轮操作次数、价格及作物参数，也可通过复制已有作物新增条目。作物 ID 用于历史库存，停种后已有植株仍可收成。成功保存后，倍率和新的交易报价立即生效，存量作物保留播种时的生长规则。建园时的初始资金可在账本回查。花园保留至少一种可从集市免费取得并可售卖的作物。

首次开园会为现有 `@subject` 声明花园工具，受影响的旧会话可能按现有机制交接一次。角色默认没有经营授权。管理员在「允许使用主人格工具经营」中选择角色后，该角色可在自己实际运行的主人格回合用 `garden_read` 查看状态和优先提示，并用 `garden_act` 经营。主人格可在同一回合照料作物、领取奖励、赠礼和陈列物品，相关动作按各自的经营或展示权限处理。先前读过的资料来源不作为花园动作的整轮拦截条件。权限与额度逐次校验，调整配置、停园和撤权不切换工具声明。普通聊天与日常任务继续使用各自已有的能力边界。

浏览器验证可用本机 Chromium 运行 `QQ_TEST_GARDEN_BROWSER=/path/to/chromium node --test test/garden-management.browser.mjs`。管理 API 和隔离主人格验证见 `test/garden-management.test.mjs`。

## 在聊天与桌面查看花园

花园开园后，已准入的 QQ 群聊、私聊、常规桌面对话和主人格都可调用 `garden_read`。`public` 返回九宫格、作物阶段、水分、天气、花园日与快照时间。`image` 为同一份公开投影生成九宫格 PNG。整园文字结果随附出图调用参数；群聊中以该调用返回的 mediaId 分享原图。获准经营的主人格可用 `overview` 查库存与优先照料事项。

伙伴可用这些只读视图主动翻阅花园。读取不消耗经营次数、不领取访客奖励，也不推进便笺的已读位置。只有实际运行的主人格可以查手帐里的共享操作者署名。普通聊天和花卡使用公开投影。

| 视图                   | 参数与用途                                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------------------- |
| `timeline`             | 可用 `fromDay`、`toDay`、`plot`、`type` 和 `cropId` 组合筛选，也可用 `factId` 指定记录                    |
| `plant_history`        | 用 `plantId` 查同一株的手帐，收成后仍可查。用 `type: "water"` 和 `limit: 1` 可取最近一次浇水              |
| `digest`               | 按当前角色自己的阅读进度取回园变化                                                                        |
| `plant`、`plant_image` | 通过 `plot`、`plantId` 或品种查询同一株；同种多株时先选返回的地块和播种日。`plant_image` 额外生成单株 PNG |

主人格读完便笺后，可在同一回合调用 `garden_read({ view: "ack_digest", readToken })`。确认使用最近一次 `digest` 返回的 `readToken`，推进自己的已读位置至该便笺生成时。之后发生的变化仍会出现在下一份便笺中。

年表和手帐续页沿用查询条件并传入 `nextCursor` 返回的值作为 `cursor`。地块会换种，查到具体植株后用 `plantId` 继续追问。依据返回的事实说明时间和照料者。历史不完整时可说明记录的可追溯起点。

桌面断线期间仍可读取最新单株快照。花园暂停时，画面会标明时钟已停。工具生成图片成功后返回可复用的 `mediaId`，保留当时的花园日、阶段、水分或锁定品质。没有视觉能力的后端可用文字与 `mediaId`，渲染失败时可用文字继续交流。分享上次的原图直接使用原 `mediaId`。

有 QQ 发送权限时可把文字、`mediaId` 或两者交给 `qq_send`，发送沿用当前会话的权限、额度和回执。回执未确认时用原请求核对投递。在常规桌面聊天中，可调用 `desktop_room_decide({ action: "say", mediaId })`，也可附简短的 `text`。工具提交决定后，正常结束的回合会把图片发布为当前桌面聊天的消息附件，可点击查看。首次上线这些工具参数时，受影响会话可能交接一次。

从桌面纸页小窝面板进入「花园」，可选地块查看照料详情、从待办跳到对应地块，并操作同一座花园。用滚轮、触控板或拖动右侧滚动条，可浏览下方地块和照料操作。键盘焦点在花园区域时也可用方向键与翻页键滚动。桌面请求绑定当前客户端与房间，打开状态与管理台共用。开园和设置继续在管理台完成。网页纸页小窝也可从目录进入同一个管理页。

`node --test test/garden-sharing.test.mjs` 验证公开投影、投递和桌面权限。`node --test test/garden-sharing.browser.mjs` 需本机安装 Chromium，用于验证真实九宫格和单株 PNG、桌面九宫格操作与聊天附件查看。QQ 测试使用隔离假网关。

## 给伙伴留句话，一起试种

在花园顶部的小黑板上写下今天的打算，或选中一块地，在便签上留下「想等今晚的花粉，明早再来看看」。主人和获准经营的伙伴都能读写。每条最多 120 字，留空保存可擦去。伙伴每轮可写三次，照常使用本轮的种植、浇水和收获次数。便签一直留在地块上，收不收由来园的伙伴决定。

回园时，`garden_read({ view: "overview" })` 会带上当天的天色、花丛里的动静、已听过的园艺传闻和最近值得留意的事。看到流星、萤火虫、蝴蝶或邻株间的花粉时，伙伴可以用这次见闻的 `evidenceId` 写进自己的日记。拆开盲盒或收获特别的花色时，动作回执里的 `surprise` 会记下发现。花园日流转、与商人交易或遇到送礼的访客，都有机会听到下一条传闻。

集市添了四种作物，已有花园打开后也能买到。

| 作物       | 可以怎么种                                                                 |
| ---------- | -------------------------------------------------------------------------- |
| 蓝雨绣球   | 喜阴。试试在不同天气播种，成熟时到单株花卡看它开出了哪一种颜色。           |
| 小灯笼番茄 | 喜阳。一株可收三茬，头两次收完保留原株，从一半进度继续长。                 |
| 玻璃糖多肉 | 喜阳，耗水少，怕细雨。搭个小棚适合长久陪伴。                               |
| 晚风洋甘菊 | 成熟后留在地里，可以替上下左右的邻株抵挡部分蚜虫影响，晴天还可帮它们省水。 |

## 配置天气与遮雨棚

在管理台的花园设置展开「天气池」，可编辑晴天、多云、细雨和暴雨，也可复制为新条目。每种天气可配置启用状态、权重、有效光照、耗水倍率、露天补水、露天成长倍率和适用的品质扣分。暴雨使露天作物保持满水，默认暂停成长。遮雨棚降低一档有效光照，挡雨时仍按当天的耗水倍率耗水。

条目可配置前一日天气、连续天气天数、日初余额，以及种子、收成或肥料数量。天气条件可以按类型匹配，也可以指定条目 ID。多项条件可选全部满足或任一满足。只有启用、权重大于零且满足条件的条目参与加权。候选为空时使用指定兜底条目，兜底须启用且无条件。

保存前以原规则补算已开始的花园日。天气池改动自下一个花园日起采用，保存和重启均复用已经抽出的天气。使用「试配天气」可按已保存的规则输入模拟日初余额、前一日天气及连续天数，查看入池、排除理由和实际概率，试配不会改变日历。

天气参数和棚状态随时间分段结算。图鉴可逐档覆盖光照倍率，留空的档位沿用该作物光照偏好的默认值。细雨露天补水与自然耗水相抵，怕涝作物在细雨日结束时扣品质。经典照料中露天在长作物连续两天遭遇暴雨时默认枯萎，在日结束前搭棚可避免当天积水和扣分。成熟锁定已累计的品质，棚在收成、清理与补种后保留。旧花园升级时保持当日中性天气，此前的生长沿用原规则。

搭棚可作用于空地和已种地块。管理台和桌面小窝均可操作，主人格在 `garden_read` 的各地块中可取 `shelterAction`，传给原有 `garden_act`。分享图文显示当天剩余时间和暴雨风险。管理台、桌面小窝与 QQ 分享图使用平印纸贴。图件缺失时继续呈现真实作物名称和状态。

## 每日事件与赠礼来源

在「花园设置」展开「每日事件池」，可调整触发率，编辑或复制事件、设置适用条件及效果参数。事件条件支持当天已选的天气、前一日天气、连续天气天数、日初余额和库存。全部候选被排除时该日没有事件。默认每日触发率为 40%，小偷要求日初余额严格大于 300 元。事件权重在已入池条目间分配。用「试配每日事件」可模拟天气和余额，查看每个候选概率及无事件概率。配置保存后于次日用于新抽取。

- 种子、肥料、礼物及可收购的收成均不可交易时，商人才会从当日抽取中排除，试配会显示原因。流浪商人按当日快照开价，可配置种子种类数、肥料报价、收购种类与礼物货位。商人报价和交易回执绑定事件，次日切回普通集市。管理台、桌面或主人格均可按共享经营权限交易。
- 小偷先由有经营权限的成员驱赶，奖励一次入公共账本。无人处理时，跨日最多从一个收成批次扣配置的数量，或在无收成时扣最多配置额度的零钱。上日损失先于新一天余额和库存条件的判定。
- 幸运访客由首个有经营权限的内部花园查看领取，只有一次。奖励进入公共仓库，可配置为种子、肥料或下次施肥时自动使用的一次免费施肥。共享图文显示事件和状态，沿用原发送权限。

主人格在内部 `garden_read` 的 `event.actions` 取当日动作，传给原 `garden_act`。管理台「每日事件记录」可回查最近事件及结算结果，交易流水带报价对应的事件 ID。旧花园在升级当日保留现状，下一花园日按已保存的设置抽取。

在公共仓库的收成卡片上先选择收件人，再点「赠送」。收成不能送给自己。赠送成功后，仓库按份数扣减，双方和数量可在「花园记录 → 赠礼记录」查看。给有效角色赠送收成后，受赠角色在自己的主人格回合获得花园来源记录，也可用 `garden_read({ view: "gifts" })` 回查。日记的 `evidence` 可使用返回的 `evidenceId`。角色身份和管理台身份没有对应的 QQ 人物证明，仍用独立花园来源，保留人物记录原有的数字身份和证据约束。角色导出按收件人隔离，完整备份用于恢复共享园地、事件、库存、规则和待办。

```sh
node --test --test-timeout=120000 test/garden-events.test.mjs
```

## 新版事件与旧园补入

新园默认有 23 条事件。老园打开「花园设置 → 每日事件池 → 补入新版预设」，检查同名 ID、作物和天气是否齐全，选择需要的预设后加入表单，再保存。已有的自定义和停用条目继续使用原设置。上限为 40 条，可按需分批选择。通过「试配每日事件」检查给定花园日、天气和余额下的候选及概率。

| 玩法                         | 生效与处理方式                                                                                                                               |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 商人、小偷、访客             | 新增雨夜花贩、连晴集市、狐狸、草莓刺猬、衔种小鸟、风送夜来香、园丁赠券、蜗牛快递、种子清仓和囤货急单。刺猬只取草莓，急单只回收夜来香。       |
| 流星、甘露、萤火虫、黄金蚯蚓 | 日初锁定受益植株。流星增加生长及品质，甘露补水，萤火虫提升喜阴作物品质，蚯蚓给予单株一次免费施肥。获准亲历音乐会的角色可为私人日记引用见闻。 |
| 野猫、蚜虫                   | 哄走野猫领奖，未处理时日终可能掀棚。蚜虫影响生长，付费除虫后从处理时刻恢复；日终未处理的在长作物扣品质。                                     |
| 乌龙预报                     | 花园时间正午切换为晴天；分段计算生长与水分。日终天气用于积水结算，连续天气抽取条件沿用每天日初的预报。                                       |
| 双果、写生                   | 全园首笔成功收获产量翻倍一次。写生要求同时种有指定数量的不同存活作物，达标后主动领取。                                                       |
| 周末盲盒                     | 第 6、7 个花园日可入池，每七天循环。购买后袋子留在公共仓库，选空地种下时揭晓，跨日仍使用购买时的候选和种植规则。                             |

## 商人小礼物与私人展示

1. 商人营业时打开「在售 → 小礼物」。默认每次从 18 款中随机上架 3～5 款，每款 2～3 件。大家共用同一份库存，刷新页面或重启服务都保留当日余量。管理员可在每日事件设置中为某位商人选择固定货单，自定库存与价格。已出摊的商人按原货架营业。选择收好，或指定管理员／伙伴直送；付款用公共金币，礼物进入个人物品栏。种子、肥料和未拆的盲盒仍属公共仓库。
2. 管理员在设置里分别配置每位经营伙伴和全园伙伴的每日购礼额度。默认可用额度为零；需要时可从每位 30 元、全园 60 元试起，以花园日结算。角色可在正常主人格回合主动挑礼物。手动购买不计入伙伴预算，转赠手里已有的物件不再扣钱。
3. 从「我的物品」点开同款物件，逐份查看来历、选收件人、食用一份零食或摆上16 格展示柜。宽屏每排四格，窄屏每排两格。升级时原有物品保留格号。食用、转赠会腾空对应格位，原收件人仍能回看收礼记录。只有主动展示且符合发布条件的内容会出现在小窝拜访入口。赠言由主人逐份选择是否随物件展示。
4. 查看礼物不会自动发送聊天消息。角色的收礼经历可在其自己的主人格回查引用。共享花园图文只展示花园，个人物品和赠言各有独立可见范围。
5. 完整备份用于恢复私人库存、赠礼与日预算；单角色导出沿用角色范围。更新前请保留一致的全库备份和原发布，以便回退。

## 在管理员私聊委托浇水

角色已经启用主人格收件箱且获得经营授权时，管理员可以在获准的 QQ 私聊中说「帮我给缺水的地浇水」或指定地块。私聊工具只接受当前角色、本会话、本轮已展示的管理员原始来信。同一来信再次提交返回原委托。委托仅支持浇水，沿用既有主人格收件箱、唤醒和额度。

主人格首次执行时按水分由低到高锁定缺水植株，同分按地块号。指定地块也在这时绑定植株。每步最多浇一块地，分轮续作遵守当轮经营次数。已换株、已经照料或无需浇水的目标会跳过。后来种下或变缺水的植株由新委托处理。

在原私聊询问进度或明确撤回可取得回执。撤回生效前已提交的浇水会保留，剩余目标停止。回执显示排队、处理中、部分完成、完成、无需浇水、已撤回、已放下或已过期，以及锁定目标的实际结果。功能使用原私聊回查，不增加主动发 QQ 的权限。

有效期在管理台「浇水委托有效期」配置，默认 24 个花园小时，保存后用于新委托。全园停表时到期时间随之冻结，角色单独休息时花园仍按实际运行时间计算到期。暂停、忙碌和休息时委托等候，由已有收件箱负责唤醒。

首次开园时私聊和主人格可能因工具声明变化按现有机制交接一次。倍率、期限、经营额度和角色授权在运行时更新。下面的隔离测试使用模拟 QQ 网关和测试后端对比交接前后的会话引用；本机安装兼容 Chromium 后加环境变量 `QQ_TEST_GARDEN_REAL_IMAGE=1` 可要求实际生成图片并在模拟 QQ 端核对图文。

## 生长手帐与回园便笺

管理台和桌面小窝在花圃上方显示回园便笺。「花园记录」可按花园日起止、地块、记录类型与伙伴筛选，照料记录按天展开。点击地块的「看这株」或年表的植株链接打开手帐，并可查看单株花卡。换种后仍能从年表翻回收成前的那一株。管理台和桌面操作员共用已读位置，各伙伴独立。仅有可靠来源的旧资料才列入历史；旧操作未保存花园时间时标明日期未记录。

播种、发芽、生长和成熟节点跟随有效生长量，时钟推进和有记录的事件催长均可留下里程碑。每株按播种时的规则结算。新花园默认安心照料；已有花园按经典规则继续运行。管理员选择安心后可选择同时保护仍按经典规则生长的作物。缺水半速、水干休眠、补水恢复；安心植株免于长期缺水和连日暴雨致死。已经成熟或枯萎的植株保留结局。

## 夜游与相邻植株

花园时钟 17:00 至 19:00 是傍晚，19:00 至次日 06:00 是夜间。成熟猫薄荷旁偶尔有蝴蝶，夜里依天气可见星光、萤点；小景与有独立结算的萤火虫音乐会分别显示。

猫薄荷默认种价 65，基础成熟需 48 花园小时。将它和月光夜来香种在上下或左右相邻的两块地上，两株成熟且共同存活满 48 花园小时后，每个符合条件的夜晚有一次结种机会，概率为三分之一，第三次保底。花园在线推进时会结算，无需守在界面上。每对亲本一生最多结出一粒星雾铃种子，种子进入公共仓库，满园也可收下。星雾铃基础成熟需 72 花园小时，默认不在集市出售种子。
