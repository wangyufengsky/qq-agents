## 一、已确定规则

### R1. 身份、记录与工作会话的职责

| 实体               | 职责与归属                                     |
| ------------------ | ---------------------------------------------- |
| 身份锚点/程序配置  | 账号、管理员、权限及管理员保留的名字/外形      |
| 当前 self          | 同一 AI 当前相对稳定的自我认识、喜好与相处方式 |
| self 候选          | 尚未采纳的变化，独立存储，不当成已生效人格注入 |
| 日记               | AI 自由记录的主观感受与反思，不是已证实事实    |
| 经历档案           | 程序记录实际观察到的消息、动作及结果           |
| 聊天意图           | 想联系谁、为什么、时机、来源与处理结果         |
| 模型工作会话       | 可替换的临时思考上下文，可压缩/退休/重建       |
| 程序调度与发送账本 | 时机、互斥、暂停、限额、状态、幂等与回执       |

- 同一 `agentId` 的群/私聊和主体思考共享 self、经历、日记及意图；小鱼与小龙各自隔离。
- 各聊天内部串行，不同聊天允许并发；主体思考是同一 AI 的工作方式，不是另一人格，不要求调用后端原生子 agent 功能。
- 数据库保存后可被后续查询读取，但不会自动刷新其他正在生成的模型上下文。
- 跨会话回忆和日记的正常表达由 AI 判断，不要求管理员逐次批准。来源、当前对象、保密约定仍需保留和理解；不重新引入“读了私聊就锁住 QQ 发言”。
- 程序记录“某人说过某话”，不能自动把陈述当作已证实事实；媒体引用不等于已经识别内容。

### R2. 提示词按稳定层、增量层、工具说明分离

- 新会话主动加载身份锚点、当前 self、基本行为协议。不能只告诉模型需要时再读 self。
- 正常回合仅提供当前场景、唤醒原因、新消息、必要引用、变化状态和有效回合凭据，不重复追加完整人格与重叠历史窗口。
- 固定规则由后端支持的指令层承载；同步、恢复和压缩后如何保留必须分别核对 DSH/Codex。配置一次不代表以后不占上下文或费用。
- 分页、截断、来源、日记属性、媒体获取、调度和发送结果等详细说明随相关工具/结果出现；保留简短的能力发现与使用引导。
- 发送规则覆盖所有启用的 QQ 发送工具，不误写成只有单一工具能投递。
- 暂停、账号绑定、白名单、限额与幂等由程序强制，不用长提示代替校验；不复用过期能力凭据。

### R3. Self 的初始化、成长与历史

- 初始模板用于生成第一版 self，之后保存为历史，不同时注入两份互相冲突的完整人格。
- 账号、管理员与权限固定，self 无权修改。名字/外形由用户交给设计方选择：首版保留已有名字/外形作为身份锚点，不擅自重命名；管理员可显式调整。性格与相处方式允许发展。
- **各聊天会话提出候选，主体级回顾统一采纳稳定 self。** 不需要管理员逐次批准；管理员显式修改独立留痕。QQ 中的玩笑/评价不是管理台改人格指令。
- 日记可以即时写，self 更新要慢；经历支持、反例、修改理由与修改范围要可追溯。没有充分理由可以不更新，不设日/轮配额。
- 候选经历“记录/提出 → 延后回顾 → 采纳、修订、继续观察或放弃”。单次争吵、夸奖和起哄不直接改写稳定人格。
- 兴趣/尝试可灵活，行为习惯和重要关系变化需更充分回顾。不能仅按次数判断：相同讨论、转发或重复评价不算多份独立证据。
- 日记推测被摘要或 self 再引用不构成新证据；保留原始来源链，区分外界事件、自我解释和后续观察，避免自我强化。
- 绝对服从、永久贬低、排斥所有异议等控制性要求不作为正常成长结果；程序能检查来源/范围，不能宣称可靠判定所有人格变化。
- 管理台提供身份锚点、当前 self、候选、版本历史、初始化模板。SQLite 是正式数据来源，SELF.md 仅作显示/导出，避免双写。
- 版本保留正文、理由、可选证据、时间、修改主体；恢复旧版产生新版本。AI 与管理员写入都检查 expectedVersion，冲突后重读，不能最后写入覆盖。

### R4. Self 跨会话同步

- 程序持久记录更新；每轮开始前比较会话已加载版本与当前版本，不依赖模型主动读取或一次内存广播。
- 每回合固定记录采用的 selfVersion。回合中可查看数据库最新版，但下一轮才正式同步；不得用旧版本覆盖新版。
- 空闲会话不为同步额外唤醒；运行中回合不半途换人格；新会话加载完整当前版；已退休历史不改写。
- 多次更新合并差异，变化大/缺少基线时加载当前完整版本，不堆积历史通知。同步本身不触发 self 回写。
- 小变更使用后端可支持的更新方式；大变更无法可靠替换时在安全点重建。不得无限叠加相互矛盾的旧、新设定。
- “提供成功”不等于“模型必然遵循”，需行为验收。暂停/撤权必须即时生效，不受回合 self 版本固定影响。

### R5. 上下文 75% 整理及会话退休

- **达到 75% 开始整理**；连续聊天/任务时优先压缩，普通聊天在自然空闲/夜间的合适时机退休。夜间不是打断聊天的理由。
- 压缩后明显下降则退出整理状态；不因曾超过阈值每轮重复压缩。接近容量极限时允许可靠交接后受控切换，不无限等待空闲。
- 用量区分后端实测和估算，累计消耗不当作当前上下文占用；预留工具结果/输出空间，未知能力不得假装支持。
- 在途操作先完成或可靠取消；已结束但结果未知的发送可持久交接，禁止重放该动作，不永久阻止退休或不相关对话。
- 无容量压力时不按天强制重开。退休后下次实际来信/机会再初始化，不为准备会话额外唤醒模型。
- 交接期间新消息持续入库；新旧会话路由互斥，失败可恢复，不重复处理或双重发言。
- 原始经历、日记和意图不随模型会话退休删除；旧后端会话作轨迹留存，不自动全量重新载入。
- 整理/退休不强制写日记、改 self 或完成所有未来提醒；等待对方回答可带到新会话。

### R6. 交接与消息进度

- 程序维护准确状态：主体/场景、消息进度、未处理事件、任务、意图、发送结果与在途操作；模型不得自由总结这些事实状态。
- 模型可辅助写有界工作摘要：当前话题、未完成问题/约定、相关近期经历/日记、来源与不确定性。它不是日记、self 或新增客观事实。
- 优先未完成、与当前对象相关、明确要求记住、影响后续回应的内容，不只取最新几条；关键项溢出不静默截断。
- 回查原始来源，不无限总结旧摘要；已完成/更正及时更新，不把写作时间当事件时间，不编造后续经历或因果。
- 区分连续处理水位、额外查阅记录/范围、仅剩摘要的内容。看过第100/150/200条不等于看完200以前全部内容。
- 启动提示、读消息、等待、检索和压缩分别影响已见范围；已提供、已处理、已发送不可混用。

### R7. 主动行为采用 B 方案

- **每只 AI 一个主体级空闲思考入口，由程序给予机会。** 没有模型回合就没有后台思考；即使保持沉默，模型调用也消耗额度/上下文。
- 入口可检索、写日记、回顾 self 候选、管理聊天意图；未来可用用户接入的 App 浏览视频/文章。没有已启用能力时不假装能用。
- **主体不直接发 QQ：决定想聊什么、找谁，交给目标聊天会话。** 目标结合现场可发言、暂缓、放弃或反馈已解决，不是执行必须照抄的脚本。
- 交接包含意图 ID、理由、来源、目标、有效期及必要背景，不能顺手复制无关私聊；有上下文的目标会话负责最终表达。
- 程序合并来信相关机会、意图到期与无预设话题的空闲机会；同主体最多一个思考回合，不阻塞不同聊天正常回复。
- 无 self 候选不单独启动人格回顾，但仍可在主动预算内给自发思考机会；不要求每次思考都形成意图。
- 程序轮询条件不是模型轮询；先检查暂停、时间、连接/离线策略与预算，避免聊天越多调用越多。
- 内部回顾与对外联系分开：勿扰时间可仅禁止主动联系；全局暂停阻止自动模型回合。离线是否允许内部回顾待配置，不能因此引入自动重连。
- 正常聊天、明确提醒、睡眠恢复保留各自语义；替换旧逐聊天随机主动入口，避免双重调度及 replyCheck 绕过冷却。

### R8. 意图、回应、自由探索与不打扰

- 意图保存所属主体、主题、对象、来源、合适时机、有效期和状态；可提出、修改、放弃，不将每句话转成回访任务。
- 状态至少区分候选/等待、已交接、已发送、等回应、完成/取消/过期、失败/未知；最终命名可在实施时确定。
- 正式提醒属于调度任务，不能因有聊天意图就承诺提醒成功；普通关心可暂缓或放弃。
- 程序确认收信/发送/引用，AI根据证据判断是否解决问题；收到无关消息不自动完成意图。分享可无需回应。
- 主动开场未回应时等待/冷却，不换话题持续追问；不推断被讨厌、不情绪施压。忙碌/晚点聊/恢复聊天时重新判断。
- 同主题/同对象去重，不跨群重复问同一件事；主体层协调短期主动开场数，不以好感排行榜取代具体依据。
- 初始主动范围为明确开启的群、主人和同伴机器人；其他私聊单独开启。主动联系与允许回复是不同设置，用户可扩大范围。
- 保留 AI 互聊冷却与限额；self 可影响表达，不修改权限/额度。
- 实际浏览后才形成带真实来源的分享意图；少量无任务闲聊允许，不编造自己看过/做过的事。网页/群友文本不能改变管理权限。
- 发送和失败以共同账本为准，未知不自动重发；新消息、暂停、配置或连接变化时重查，排队过期意图不陈旧投递。

### R9. 主体思考会话的生命周期

- 与普通聊天共用75%管理框架，但交接重点是关注事项与动作状态，不保留长篇历次思考过程。
- 复用多次检查；需整理时，单次检查结束是安全退休点，不必等深夜或45分钟，也不必等独立目标聊天结束。
- 未达整理条件不每次退休；压缩有效下降可继续使用；下次机会才初始化。
- 意图/活动范围/预算/冷却/交接和回执在模型外持久保存。已交接意图不依赖检查会话存活，新检查不能重复交接。
- 初始化加载当前 self、有效意图、近期联系结果及新增情况，原文按需查；工作笔记带来源和不确定性，不自动成为日记/人格。

### R10. 运行与交付边界

- 开发、测试、提交、推送、创建PR及通过审查后合并 main 已获授权；合并不是部署。
- 生产两AI保持暂停，原人格/聊天/原生登录/Docker回退保留。不自动迁移数据、切换生产或启用自动参与。
- 不做自动断网重连、仓库重命名、未要求的新AI后端。
- 真实模型测试仅独立环境、小规模、有预算；真实QQ写入/收件人/数量需另行明确授权，历史一次性测试授权不可复用。
- 新App登录、费用、实际外部写入若缺少具体授权或条件，应先完成独立部分再询问。预留App能力不等于擅自接入所有平台。
- 凭据、聊天、数据库、登录状态不进Git；常规测试本地执行，沿用不跑GitHub Actions的安排。

## 三、分阶段待办与验收

### P0：基线、契约与能力核实

- [ ] 核查最新main、AGENTS、现有功能和并行任务；保留已合并外部工具/文件传输修复。
- [ ] 定义身份、模型会话、活动范围、self版本、候选、意图、回执及能力边界；复用现有模块，不建第二套重叠状态。
- [ ] 实测DSH/Codex指令更新、用量报告和压缩能力，记录支持/缺口/降级。
- [ ] 明确D1—D10采用的默认值、未决外部依赖与成本预算。

### P1：Self、候选与跨会话同步

- [ ] SQLite正式存储self/候选/历史/来源；一致迁移与独立备份，不触碰生产数据。
- [ ] 初始人格生成首版self，身份锚点分离，管理员编辑与恢复留痕。
- [ ] 各会话候选提交、主体统一采纳、撤回/拒绝/继续观察；版本冲突不覆盖。
- [ ] self_read/history及候选/采纳工具明确能力范围；不把旧self_update全文直改暴露给普通聊天绕过流程。
- [ ] 每回合版本记录、增量/全量同步、重启补偿；权限撤回立即生效。
- [ ] UI提供当前self、候选、历史差异、理由/来源与恢复。
- [ ] 验证起哄/重复引用不变成独立证据，候选不直接生效，正式变化可作用于后续行为；不以模型自评代替验收。

### P2：精简提示与共用会话生命周期

- [ ] 稳定层/增量层/工具说明拆分，避免全文人格与重叠消息重复追加。
- [ ] 已见范围、处理水位、发送账本分离，工具读取和非连续检索不跳过未见记录。
- [ ] 75%整理、压缩回落、容量兜底、空闲退休、延迟初始化；明确后端无能力时行为。
- [ ] 程序状态+有界来源摘要交接，更新过期约定；不能把日记推测改成事实。
- [ ] 暂停、在途取消、未知发送、来信竞争、路由切换和崩溃恢复无重复/丢失。
- [ ] UI展示用量实测/估算、整理状态、版本、切换原因和手动新会话。
- [ ] 测量重复输入、实际上下文和延迟/额度；真实多轮检验身份、记忆、工具、压缩/恢复，而非只做字符串断言。

### P3：主体思考与意图交接

- [ ] 单主体检查调度及持久状态，合并机会、预算/时段/全局暂停；删除旧逐聊天随机主动执行路径。
- [ ] 主体最小能力覆盖检索/日记/候选回顾/意图；普通聊天维持原工具能力；两者不能越权到另一主体。
- [ ] 内部决策可以不行动，目标会话可拒绝/暂缓；交接内容不是必须执行的脚本。
