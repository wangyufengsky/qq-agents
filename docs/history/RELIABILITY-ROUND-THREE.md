# 第三轮：发送预算、文件库恢复与静默语义

本轮改变投递额度的作用范围，并为损坏文件和相等静默时间提供明确处理。全部回归使用合成消息、临时数据及假 QQ 网关，不代表生产部署或真实平台验收。

## 发送额度与迁移

`behavior.maxSendPerMinute` / `maxSendPerHour` 现在是**角色总额度**，由该角色的全部群和私聊共享。文本、文件、语音和其他进入统一投递入口的动作使用同一预算。管理台“作息与定时”明确显示范围，并新增分钟额度输入。

可选 `conversationMaxSendPerMinute` / `conversationMaxSendPerHour` 额外限制单会话；留空表示不加这一层限制。连续回复批次仍由 `maxConsecutiveSends` / 兼容字段 `maxSendsPerTurn` 控制。唤醒额度保持原有会话范围，未改为角色总额。

预算记录放在该角色的 `internal:send-budget` 状态中，版本为 1，与 outbox 预留、会话计数及投递尝试记录在同一事务提交。网关失败、未知回执仍计费；相同 requestId 的已确认回执查询不再次计费。预算耗尽返回 `SEND_RATE_LIMIT` 或 `CONVERSATION_SEND_RATE_LIMIT`，损坏预算返回 `SEND_BUDGET_CORRUPT`，不按空记录重新发放额度。

首次预留时汇总所有旧群聊、私聊近一小时的 `sendTimes`，不只统计当前白名单会话。相同毫秒的多次投递保留次数。每次进程启动后的第一次预留会按时间戳的重复次数合并角色历史与会话历史，防止重启或旧代码运行后再次升级遗漏计数；重合记录不重复收费。会话计数继续维护，暂停、取消和重置会话均不清除额度。

角色状态随现有导出/恢复保留；恢复的是备份时刻的状态，不包含备份之后的发送，不能通过恢复旧备份获取额外额度。数据库表结构与 `user_version` 不变。恢复、回滚前需停止该实例，避免多个版本同时写同一数据目录。

## 文件库损坏与配额

列表将单个损坏条目隔离，正常条目继续列出、读取和下载。返回 `corruptCount`、有界 `corrupt` 列表及 `nextCorruptOffset`，区分元数据损坏/缺失、内容缺失、完整性异常、权限失败和不安全路径。缺少保护字段的旧元数据也按保护信息不完整处理，不自动视为公开资料。读取内容仍验证 SHA-256；普通列表只检查元数据、文件类型及长度，不逐个读取完整文件做哈希。

配额使用目录中实体的逻辑字节数，包括内容、元数据、损坏和孤儿文件、遗留临时文件及拦截记录。JSON/bin 同 ID 配对按一个占用条目计数，其他遗留文件单独计数；损坏条目不会释放额度。目录或无法统计的条目会使 `usageComplete=false` 并阻止新增写入，管理员需检查这些异常。现有库可能因统计更完整而超过额度；不会自动删除文件。新增写入也检查元数据上限，避免成功上传后形成无法读取的超大元数据。

管理台提供经管理员认证、按角色互斥的 `POST /api/files/recovery`：

- `action: "repair"`，携带 `agentId`、`fileId`、`name`：只修复损坏项，验证现存内容为普通单链接文件，SHA-256 与 fileId 相符且大小符合策略后重建元数据。不能从缺失或已改动的内容恢复原文件。
- 修复后的元数据标记 `protectionUnknown: true`，并设置 `protectedOperations: true`。原来源标签无法可靠恢复时保守保留披露限制；再次上传同样内容不会去掉限制。通过文件或图片入口使用时继续携带保护，发送仍需当前上下文的披露批准。
- `action: "remove"`，携带 `agentId`、`fileId`：管理台经用户确认后移除该损坏条目的内容和元数据，先持久化 `.blocked` 拦截记录再删除。正常文件不能通过此接口移除。同内容再次导入被拒绝，防止以“删除再上传”清除未知保护；拦截记录仍占用少量空间和一个条目。删除中途失败时返回诊断，列表显示 `FILE_REMOVAL_INCOMPLETE` 并允许继续清理，拦截不解除。

“隔离”是列表与使用入口中的逻辑隔离，不自动移动、删除原文件。未知文件名、临时文件及异常子目录不会被上述接口批量清理。API 不返回本机完整路径或原始文件系统异常。修复、移除均不发送 QQ 消息。

文件库须独立备份整个目录，保留 `.json`、`.bin`、`.blocked` 和其他原件；数据库导出本来就不包含附件实体。旧版本不识别 `.blocked`，也不验证新增恢复状态，因此**不能让旧版本直接接管已执行恢复/移除的新文件库**。如需回滚，先停机、关闭文件能力，保留新版完整目录，在隔离目录使用可信备份演练恢复，核对保护标签后再开放；不要仅删除拦截记录来恢复上传。

## 静默时段

新建或保存普通角色静默时段时，起止相同必须明确写 `allDay: true`；非全天时段必须起止不同。`allDay` 保留“从选中日的开始时刻到次日同一当地时刻”的含义，`00:00 → 00:00` 表示日历整日。例如周一 `08:00 → 08:00` 表示周一 08:00 到周二 08:00，不能简单改成周一零点到午夜。DST 日按当地时间边界计算，可能是 23 或 25 个实际小时；空 `days` 不生效。

调度器新增 `scheduler.quietAllDay` 明确表示全天群定时免打扰。启用免打扰且未选全天时，起止相同会被配置校验拒绝；`quietEnabled=false` 时保持关闭。私聊定时任务沿用原策略，不被群定时免打扰覆盖。

加载磁盘旧配置时只做以下兼容转换，不直接覆写配置文件：

1. 角色旧相等时段增加 `allDay: true`，保持原有生效范围。
2. 调度旧相等时段明确为 `quietEnabled: false, quietAllDay: false`，保持原先“不静默”的效果。

`GET /api/config` 提供本次加载的 `migrationWarnings`，管理台概览显示说明。首次正常保存会持久化明确选项；配置 revision 仍以规范化后的内容计算。新 API 保存不自动把误填的相等时间解释为全天。平台自主浏览时段的全天语义保持原样。

## 验证、升级与回滚

回归覆盖跨会话并发预算、角色隔离、可选会话额度、失败/未知计费、事务回滚、时间窗口、旧计数迁移、重启/导出恢复、再次升级及损坏预算；文件元数据损坏/缺失/错误结构、孤儿占用、权限、符号/硬链接、修复保护、删除前写入失败、管理员接口与真实管理台脚本；静默迁移、全天/空 days、跨周、时区及 DST。

部署前备份数据库、配置及完整文件库，核对角色总额度是否满足所有会话的合计需求，并刷新管理台。配置格式仍为 version 1，但旧代码的严格 schema 不认识新增可选字段；回滚需使用适配旧版本且保留预期静默效果的配置副本。不要清空发送历史。数据库保留新版预算行及会话计数，测试验证旧版仅新增会话计数后再升级仍受角色总额约束。

合成回归未执行真实 QQ 出站、生产重启或跨平台生产容量验收。有界导出、浏览游标存储、到期索引、精细化配置影响范围及 Runtime 拆分仍属于后续工作。
