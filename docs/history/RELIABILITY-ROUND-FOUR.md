# 第四轮：有界导出与浏览游标治理

本轮覆盖管理台、HTTP、CLI 导出和 App 分页存储。验证使用临时数据库、合成消息和假平台；不启动 QQ，不调用模型，不代表生产部署或真实平台验收。

## 导出与恢复

管理员 `GET /api/export?agentId=…` 和 `npm run export -- --data DATA_DIR --agent AGENT_ID --file PRIVATE.json` 使用同一导出实现。工作线程从数据库创建一致性快照，逐行写入完整临时 JSON，再交给下载方。传输复用一个 64 KiB 缓冲区，等待写入回调后才复用，慢客户端不会使待发送数据持续累积。保留的小规模同步 `AgentMemory.export()` 仅供内部兼容与测试，HTTP、CLI 不再调用它。

复制快照时短暂固定 SQLite 读事务，避免持续写入使增量备份反复重做；快照复制完成立即关闭在线连接，编码与下载仅访问临时文件。快照预算为 10 秒，整个导出含下载最长 120 秒。备份期间 WAL 仍可能增长，超过预算明确失败，不在在线库上维持整个下载时长的读事务。实现依据 [Node SQLite backup API](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html#sqlitebackupsourceDb-path-options)；超大列预检使用 [SQLite octet_length](https://www.sqlite.org/lang_corefunc.html#octet_length)，根据列元数据取得字节数，避免预检本身加载整段正文。

默认上限：每个 MemoryStore 同时一个导出；整个数据库快照 2 GiB；选定角色 JSON 512 MiB；单行 UTF-8 JSON 8 MiB。快照包含整个源库，最终文件只含选定角色，所以源库整体过大时单角色导出也会被拒绝。临时目录权限 0700，文件 0600，最多需快照加导出文件的磁盘空间。失败、断开、受控停机和 CLI SIGINT/SIGTERM 会取消并清理临时文件；强制杀进程或断电可能留下系统临时目录，须停机确认归属后清理。CLI 使用独占创建，拒绝覆盖既有目的文件；失败删除本次不完整目的文件。

新版格式为 `version: 2`，保留 `agentId`、`exportedAt`、`tables`，新增 manifest：固定表顺序、逐表记录数和 SHA-256。摘要输入为 `JSON.stringify([version,agentId,exportedAt]) + "\n"`，随后依次加入表名和换行、每行 `JSON.stringify(row)` 和换行。表顺序见 `src/memory/export-format.mjs`。对象属性顺序属于该编码契约，重排字段或加工内容后需重新生成导出；校验和用于完整性检查，不是可信来源签名。

恢复先校验完整性再开事务写入，仍要求目标角色为空，保留原有跨角色 seq 水位重映射、别名和观察记录验证。旧 `version: 1` 可继续恢复，但没有新版完整性清单。旧代码不接受 v2；应使用本轮或更新版本恢复。测试覆盖事件与日记修订、Self、意图引用、会话状态、消息别名和观察记录，并核对各表往返内容。恢复 CLI 本轮仍整体解析 JSON，尚未做流式恢复；附件、媒体、配置和凭据仍须独立备份，数据库导出不包含这些实体。

网页端通过管理员请求取得 60 秒有效、单次使用、绑定角色的下载票据，随后由原生表单 POST 下载。票据只放 POST 正文，不放 URL，也不能用于管理员或模型工具认证。最多保留 8 个未过期票据。网页不再把导出读进 `response.json()` 或 Blob；下载结果以浏览器下载列表或失败窗口为准。

## 浏览游标

游标元数据存入角色独立的 `internal:app-cursor:<id>` 行，待读正文逐项存入 `internal:app-cursor-item:<id>:<index>`。原 `internal:app-browsing` 保留调用预算等轻量状态。数据库 schema 仍为 6，新行随正常导出、恢复保存，不引入第二份正文状态。

每个游标最多 8 MiB，每角色合计 32 MiB（按实际存储 JSON 的 UTF-8 字节计算）；最多 20 个活动游标、100 个后端页、10000 个去重键，单个平台批次最多 100 条。TTL 为 1 小时；运行时每分钟清理过期元数据与正文，访问时也检查。会话列表、生命周期扫描和调度恢复在 SQL 层只取聊天／主体会话，避免再次读取内部正文。

同角色续读串行；保存观察记录、消耗旧游标和创建下一游标在同一个事务内完成。重复并发消费只成功一次。身份、平台、操作、请求参数和浏览器 epoch 绑定仍生效。额度不足返回 `APP_CURSOR_BUDGET`，停滞分页返回 `APP_CURSOR_STALLED`，批次过大返回 `APP_RESULT_BUDGET`；不提交半页成功记录，不把未完内容标成结束，原游标在 TTL 内保留。平台读取失败或超限仍消耗已经发生的调用预算。

重启后可续读已缓存正文；如果浏览器滚动位置已失效，会返回 `completion: "interrupted"` 和明确说明，不能声称读完来源。普通结束为 `end`，还有下一页为 `more`。

旧版内嵌游标会事务化迁移，保留调用计数、未读正文、去重键、过期时间和 epoch；已超出新字节额度的存量允许逐步读完，但不允许继续增大。首次迁移旧大字段仍需一次解析，后续不再整体重写。运行时清理也迁移未再次打开的旧角色。回退旧代码前应先停机备份，禁用浏览能力并演练回退；旧代码不理解新行，不能假定它能继续已有分页。恢复旧备份会失去备份后的进度，不能直接把新行伪装回旧状态绕过额度。

## 验证

执行 `npm run verify`。性能验收命令：

```sh
node --expose-gc scripts/export-benchmark.mjs --synthetic --count 100000
```

脚本只生成合成数据库，在隔离运行时持续请求 `/api/status`、写入模拟到达消息并下载导出；下载客户端位于单独进程，RSS 统计包含服务与导出工作线程，不混入客户端下载内存。采样间隔 5 毫秒，状态／到达写入约每 15 毫秒一次，报告为本机实测而非所有环境保证。

本轮 693 项测试、197 个 JavaScript 模块语法检查通过。Node v24.19.0、Apple M1 Pro 的 100000 条记录验收：文件约 79 MiB，耗时 2.00 秒，额外 RSS 57.78 MiB，状态接口 p95 2.38 ms，到达写入 p95 1.16 ms，事件循环 p99 11.71 ms。达到方案中的 64 MiB / 100 ms / 50 ms 目标。真实消息接入、平台浏览与生产重启验收仍单独进行。
