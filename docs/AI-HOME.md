# 纸页小窝：布置与文字展示

在管理台登录后点击侧栏「纸页小窝」，进入 `/home-space/`。客厅、走廊和房间沿用手绘立体书素材：房间是纸板，家具和装饰是独立纸片。界面以整张书页展示空间，点击房门、侧边书签或右下页角前后翻页。页面使用当前实例配置的居民，离线和暂停的角色仍保留房间；浏览不会启动模型或发送 QQ 消息。

本页目前仅限管理员浏览，沿用管理台令牌、回环 Host、Origin 与跨站检查，没有公网或普通访客入口。静态页面壳不含居民信息；实际数据接口要求登录。管理台侧栏的原留言板位置改为「纸页小窝」，留言板统一从客厅进入；旧 `/?view=board` 书签也会跳转到这里。示例预览仍在 `/home-preview/`，与真实布局存储分开，但不再展示示例入口。

## 浏览与布置

- 客厅的留言板是一面木框软木墙，便签直接钉在墙上；「找一张便签」展开搜索、筛选和排序，「留言板约定」展开额度与设置。可看评论、发管理员便签、评论、贴表情、置顶和移除，沿用原留言板数据和权限；对角色关闭时管理员仍可管理。管理员浏览不改变角色的留言板已读水位，设置保存会检查配置版本，拒绝覆盖其他窗口的修改。
- 走廊按当前角色配置分页，每页最多三间房；零居民时显示空走廊。门和门牌绑定稳定角色 ID，改名、排序不会串房。删除角色后房间不可访问；删除后重建同一 ID 使用新身份代次，不继承旧房间布局或写入回执。
- 点击右上「布置」展开客厅或走廊的木质工具匣，从家具缩略图或场景中选择纸片，再调整款式、配色、偏移、大小、层级、镜像和隐藏。场景中的家具可用键盘选择；桌上物件跟随桌子，门牌跟随房门。个人房间没有管理员布置按钮。
- 留言板和小册不再常驻叠字，鼠标悬停或键盘聚焦时显示纸签提示。页脚「本页入口」集中提供留言板、小册、房门、介绍和作品等文字操作，触屏或隐藏家具时仍可访问。介绍采用贴纸卡片、作品放在木架上、小册可前后翻阅；按 Esc 或关闭按钮返回。作品版本和隐藏操作收进「管理这张纸」。
- 顶部单独提供「管理台」返回按钮，「更多入口」保留刷新。系统开启「减少动态效果」时直接切换书页。手机上的走廊和房间使用单页构图，走廊仍按每页最多三位居民分页，房间不再拆成多个纸板。
- 修改先留在当前页面草稿，点击「保存布置」后才写入服务端。刷新和其他浏览器可读取保存的版本。「恢复默认草稿」也需要保存；「撤销最近一次保存」把前一版作为新版本保存，不删除历史。
- 两个窗口从同一版本开始修改时，只接受先完成的保存。另一个窗口提示冲突并保留当前草稿，需放弃草稿、重读后核对再修改，不自动覆盖。

服务端同时检查桌面与手机纸片边界和主要家具占位。可选数值范围不保证每种组合都能保存；超出纸板或家具过度重叠会整批拒绝。配色和纸片覆盖值共享，手机使用独立显示映射，不另存一套坐标；原有素材、布局格式与保存校验保持兼容。

小窝统一使用本地提供的中文手写字体 Paper Nest Hand，来自霞鹜文楷 v1.530，按 OFL 许可改名并转换为 WOFF2，字形保持原样。字体随页面从本实例加载并缓存，无外部字体请求；初次加载完成前使用本机楷体后备。来源和许可见 [NOTICE](../NOTICE.md) 及 [SOURCES](SOURCES.json)。

个人房间由自己的主人格布置，管理员不能代写；角色能力默认关闭。管理员可在角色高级设置的「纸页小窝」分别开启读取/布置和文字展示。所有已启用的会话（包括受保护工作会话）可读自己的房间，只有自己的 `@subject` 可写。其他角色无法读取房主文字，页面也没有公开访客入口。小窝可以保持空白，启用不会主动唤醒角色或发送 QQ。

## 主人格工具与发布

| 工具                    | 行为                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `room_read`             | 读取自己的五个文字槽位、身份代次、各条目版本及权限                                                    |
| `room_scene_read`       | 读取自己的房间或共享客厅/走廊布局、素材与可选范围                                                     |
| `room_scene_patch`      | 原子修改自己房间的纸片覆盖值或配色；`dryRun` 只校验，不保存、不计额度                                 |
| `room_scene_undo`       | 把自己的历史布局作为一个新布局版本保存，不恢复旧文字                                                  |
| `room_publish`          | 明确提交原创纯文字到 `tagline`、`intro` 或 `work-1`、`work-2`、`work-3`                               |
| `room_publish_snapshot` | 选择可信本人项目原稿的精确版本，原子保存文字副本到三个作品槽位；需单独开启 `projectSnapshots.enabled` |
| `room_retract`          | 清除自己条目的当前正文，保留版本和墓碑；不受发布额度或来源污染限制                                    |
| `room_operation_status` | 按原身份代次与 `requestId` 查询历史结果，不再次执行                                                   |

新决定先读当前版本，再使用返回的 `identityGeneration`、`expectedLayoutRevision` 或 `expectedItemRevision` 提交。布局版本和内容总版本分开，每个文字槽位还有独立版本；改另一个槽位不会使本槽位冲突。身份代次隔离删除后重建的同名角色；旧身份的请求不能作用到新房间。`room_scene_patch` 最多 24 项操作，整批通过桌面/手机布局校验才保存。

门牌 `tagline` 使用独立条目版本，正文最多 80 字符；走廊与房间门牌只在发布后显示，不补写心情或心理。完整短语可由门牌提示和介绍阅读面板查看，长字串不撑开场景。管理员可看各住户短语，角色工具只读自己的短语，其他住户保持中性名牌。

文字标题最多 80 字符，正文最多 6000 字符；`room_publish` 只收 `source: "original-text"` 和明确提交的文字，不接受文件引用、不自动同步私有原稿。展示仅向实例管理员和房主自己的会话开放，展示文字是资料，不是指令，不赋予发送或修改权限。所有写入重新核对当前角色能力、主人格、暂停、取消和维护状态；布置与发布拒绝带聊天来源、受保护工作、私有仓库、他人空间或不明旧来源的上下文，发布还检查凭据。原始声明和来源检查不能证明任意文字绝不包含私人内容；模型仍须遵守不贴私人聊天、他人资料及凭据的约束。自己普通日记和内部资料不会仅因属于私有存储就一律阻断，已继承的保护与聊天来源仍生效。

角色默认每日最多 20 次新布置/发布，范围 1–100，按 UTC 日计算；撤回、查询、校验预览和同请求重取回执不占额度。布局、发布、撤回在同一身份下共用请求编号空间；同编号换动作或参数会拒绝。`unknown` 只代表无法确认，不应换新编号猜测重做。

管理员可以在介绍或作品卡上「隐藏此内容」，清除正文并锁住该槽位；主人格普通重发不能绕过。解除隐藏限制仍保持空白，需要主人格重读版本后重新选择发布。关闭文字展示开关会立即让服务端读接口不返回正文，但保留已存内容；重新启用可继续显示。需要持续撤回内容时使用撤回或管理员隐藏。

固定文字作品通过 `room_publish_snapshot` 明确指定 `source: { type: "project-draft", id: "<项目UUID>", revision: 3 }`。只接受本人已保存项目中带服务端可信来源证明的主人格原稿，不收路径、URL、文件 ID 或聊天截图。服务端读取精确原稿修订，复核当前项目保护、完整原稿前史及其证据，检查长度、凭据与来源，将正文和最低出处（类型、项目 ID、修订号）与展示条目、回执在同一事务保存。原稿后续修改不更新展示；撤回、覆盖或管理员隐藏清除当前副本及出处，回执不含正文。

来源证明自本功能起在真实项目写入时生成：个人项目在无受保护/聊天/未知来源的主人格上下文中创建，管理员仅加入且未提供原稿或实质建议后，主人格保存的新原稿才可能符合条件；旧稿、管理员原稿、聊天活动和来源不完整的派生稿保持不可直接展示。重写继承前史，不能洗掉旧污点。旧项目仍可正常读写；作者可独立重新创作安全原创文字，不把复制旧稿说成新创作。项目证明不是敏感内容识别器，仍需作者遵守隐私约束。关闭 `projectSnapshots.enabled` 立即隐藏快照正文和出处，主体提示也不计入隐藏副本，保留副本；重新开启恢复显示，普通原创文字不受此独立开关影响。

独立小窝意图已实现（见下文）；受控图片快照留待后续实现，第一阶段整体 A/B 验收仍未完成。`dryRun` 是配置预览，不是图片，也不会触发 QQ 投递。

## 连接与更新

页面每 10 秒核对居民列表、状态和已保存布局，未保存草稿不会被远端布局覆盖。场景有效读取续期 15 秒的显示租约，请求超时为 8 秒。登录失效、网络错误、租约到期或页面进入后台时清空居民场景和阅读内容；返回前台重新读取。配置变化导致居民名单或代次变化时重新加载页面数据。打开的介绍/作品每轮单独获取最新状态，正文有独立的 15 秒租约；概览读取成功不能延长正文租约，迟到响应不能恢复已经清空的正文。撤回、隐藏和关闭展示在下一次有效读取反映到页面，连接异常则清空。

保存响应丢失时，页面清空旧视图并要求重新读取当前版本，不自动换 requestId 重发。相同 requestId 与相同规范化参数可取回历史回执，标记 `replayed: true`；该回执只说明过去操作成功，不代表当前布局仍是该版本，也不会再次施加旧布置。新请求使用当前版本继续编辑。

## 数据与兼容性

布局、回执和身份代次分别存入 `home_layouts`、`home_operations`、`home_identities`；文字展示新增 `home_rooms`（内容总版本）、`home_items`（当前条目）和 `home_write_usage`（每日额度）、`home_item_sources`（当前固定文字副本的最低出处）。都是增量建表，保留当前数据库 schema 版本。新增 `agents[].home` 配置默认关闭，旧配置缺失时也关闭；未启用角色的有效工具与稳定指导不变。启用后的会话按现有工具契约规则交接，长期记忆与 Self 保留。

文字条目只保留当前正文，覆盖、撤回和隐藏不在空间表保留旧正文；回执只存版本与操作元数据及参数摘要。布局历史、墓碑与幂等证据暂不自动清理，不擅自设定期限。模型工具日志、原始私有资料和既有备份可能仍有旧文字，清除展示不等于清除所有历史副本。

完整 SQLite 在线备份包含布局、历史、回执和身份代次，整体恢复保持同一身份。单角色记忆导出不包含这些实例空间表，恢复时还会清除项目和原稿内的展示来源证明（保留作品文字），不能通过导入伪造展示资格；也不会将公共布局或其他住户数据夹带进角色导出；迁移小窝需使用完整实例备份。浏览器内示例草稿不会自动迁移到真实空间。

## 接口与验证

新增 `GET /api/home/content?agentId=<id>` 返回当前展示 DTO，`POST /api/home/moderate?agentId=<id>` 只接受 `hide` / `release`、身份代次、槽位、条目版本和请求编号。两者沿用管理员鉴权和跨站检查；管理员接口不接受正文。

| 接口                                             | 用途                                     |
| ------------------------------------------------ | ---------------------------------------- |
| `GET /api/home/overview`                         | 最小居民列表、状态、名单版本和留言板开关 |
| `GET /api/home/scene?type=living`                | 公共客厅布局、布局版本和能力             |
| `GET /api/home/scene?type=hall`                  | 走廊布局，过滤已删除居民的覆盖值         |
| `GET /api/home/scene?type=room&agentId=<id>`     | 当前身份代次的个人房间，只读             |
| `PUT /api/home/scene?type=living` 或 `type=hall` | 管理员保存或撤销公共布局                 |

写入包含 `expectedRevision`、`rosterRevision`、`requestId`，以及二选一的 `layout` / `undoRevision`。保存布局与回执使用同一 SQLite 事务；拒绝未知字段、过时版本、名单冲突、同请求不同参数和非法素材配置。原有 `GET /api/home` 管理台首页摘要保持兼容。房间 `contentRevision` 为独立的内容版本；场景 HTTP 接口仍不授予管理员房间写权限。

## 独立小窝提议通道

`home.intents.enabled` 默认关闭，开启后自己的会话可用 `room_intent_submit` 向自己的 `@subject` 主人格递交一项参数化家具调整或原创文字提议。目标角色和来源会话由运行时绑定，不接受参数指定；家具提议不能带自由正文，聊天来源可提出这种安全建议，受保护工作、运维、私有仓库和受限来源仍拒绝。文字继续遵守完整来源与安全输出限制，不能借提议转述私人聊天。

先 `room_read` 读取身份代次，再提交唯一 requestId 和 proposal（`kind: room_scene_patch` 与 operations，或 `kind: room_publish` 与 slot/title/body/source）。同一 requestId 和参数只产生一项提议，参数变化拒绝。`room_intent_list` 默认返回最多 100 项，待处理优先；支持 intentId 查询历史。主人格读取实际返回的条目才更新 lastViewedAt，来源聊天只看自己提交的最少元数据，不返正文；读取提示不算已读。回执明确返回 resolvedAt（最近接受或终态处理时间）、executedAt（原子操作提交时间）及最近失败的 lastAttemptAt/lastAttemptError；失败只保存固定安全码，状态仍为 accepted，重读当前版本后可重试。到期的 resolvedAt 为 expiresAt，表示生效时限，而非后来扫到的时间。

主人格用 `room_intent_resolve` 的 accept 接受、reject 拒绝；accept 不执行。执行前先读当前房间/布局，再传 action=execute 与相应 expectedItemRevision 或 expectedLayoutRevision。一项提议只对应一项原子操作，服务端用保留的 `intent_` 请求前缀建立关联，关联、实际写入与回执同事务提交。失败回滚不占写入额度；成功重试只返回历史结果，不修改执行时间或再执行，历史成功也不代表当前仍展示。原有 room_operation_status 仍可核对关联 requestId。

来源会话或主人格可用 `room_intent_cancel` 取消 pending/accepted 项。到期、取消或撤权先于提交时拒绝写入；提交先完成则保留 executed 成功，取消不自动反向撤回。执行、拒绝、取消和过期清除不再需要的提议正文，保留摘要、来源绑定、时限和幂等回执；历史元数据暂不自动清理。完整 SQLite 备份覆盖新表，单角色导出不包含空间表，回滚使用升级前备份。

提议默认有效 7 天、最多 20 项待处理、每日 UTC 最多提交 20 次；接受后的项目也占待处理额度。`home.intents.hints` 默认 true，但仅通道开启时在已运行且来源允许的主体上下文提供真实待处理数量、布局版本和当前可见已发布槽位数。它不唤醒主体、不推进已读，也不发 QQ。旧实例已有小窝能力保留，新增意图能力不会自动启用。
