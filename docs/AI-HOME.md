# 纸页小窝：居民与公共空间布置

在管理台登录后点击侧栏「纸页小窝」，进入 `/home-space/`。客厅、走廊和房间沿用手绘立体书素材：房间是纸板，家具和装饰是独立纸片。页面使用当前实例配置的居民，离线和暂停的角色仍保留房间；浏览不会启动模型或发送 QQ 消息。

本页目前仅限管理员浏览，沿用管理台令牌、回环 Host、Origin 与跨站检查，没有公网或普通访客入口。静态页面壳不含居民信息；实际数据接口要求登录。示例预览仍在 `/home-preview/`，与真实布局存储分开。

## 浏览与布置

- 客厅的留言板打开现有完整留言墙，可搜索、筛选、看评论、发管理员便签、评论、贴表情、置顶和移除。与管理台原留言板共用数据和权限；对角色关闭时管理员仍可管理。管理员浏览不改变角色的留言板已读水位。
- 走廊按当前角色配置分页，每页最多三间房；零居民时显示空走廊。门和门牌绑定稳定角色 ID，改名、排序不会串房。删除角色后房间不可访问；删除后重建同一 ID 使用新身份代次，不继承旧房间布局或写入回执。
- 管理员可展开客厅或走廊下方「布置公共空间」，选择纸片款式、配色、偏移、大小、层级、镜像和隐藏。桌上物件跟随桌子，门牌跟随房门。隐藏家具后，场景下方的文字入口仍可用。
- 修改先留在当前页面草稿，点击「保存布置」后才写入服务端。刷新和其他浏览器可读取保存的版本。「恢复默认草稿」也需要保存；「撤销最近一次保存」把前一版作为新版本保存，不删除历史。
- 两个窗口从同一版本开始修改时，只接受先完成的保存。另一个窗口提示冲突并保留当前草稿，需放弃草稿、重读后核对再修改，不自动覆盖。

服务端同时检查桌面与手机纸片边界和主要家具占位。可选数值范围不保证每种组合都能保存；超出纸板或家具过度重叠会整批拒绝。配色和纸片覆盖值共享，手机使用独立模板映射，不另存一套坐标。

个人房间目前供浏览，管理员不能代写。房间写入的内部基础仅接受有效 `@subject` 上下文，检查身份代次、暂停、取消、过期与保护状态；本 PR 不注册角色工具或 HTTP 房间写入口。公开介绍、作品、发布/撤回、意图与受控看图尚未接入，界面显示空内容，不把私有记忆或管理员文字当作角色自愿发布。第一阶段整体 A/B 验收尚未完成。

## 连接与更新

页面每 10 秒核对居民列表、状态和已保存布局，未保存草稿不会被远端布局覆盖。每次有效读取续期 15 秒的显示租约，请求超时为 8 秒。登录失效、网络错误、租约到期或页面进入后台时清空居民场景和阅读内容；返回前台重新读取。配置变化导致居民名单或代次变化时重新加载页面数据。

保存响应丢失时，页面清空旧视图并要求重新读取当前版本，不自动换 requestId 重发。相同 requestId 与相同规范化参数可取回历史回执，标记 `replayed: true`；该回执只说明过去操作成功，不代表当前布局仍是该版本，也不会再次施加旧布置。新请求使用当前版本继续编辑。

## 数据与兼容性

布局写入实例 SQLite 中的 `home_layouts`，操作回执在 `home_operations`，身份代次在 `home_identities`。三表为增量创建，保留当前数据库 schema 版本，不改配置默认值、角色工具目录或原生会话契约。旧版本忽略新表；回退仍应使用升级前的完整备份。

当前仅保存受控素材 ID、样式覆盖值和版本，不保存介绍、作品正文或截图。布局历史和幂等证据当前不自动清理，不在本次实现中擅自设定过期天数；清理与拒重窗口需在后续发布功能中一并设计。

完整 SQLite 在线备份包含布局、历史、回执和身份代次，整体恢复保持同一身份。单角色记忆导出不包含这些实例空间表，也不会将公共布局或其他住户数据夹带进角色导出；迁移小窝需使用完整实例备份。浏览器内示例草稿不会自动迁移到真实空间。

## 接口与验证

| 接口                                             | 用途                                     |
| ------------------------------------------------ | ---------------------------------------- |
| `GET /api/home/overview`                         | 最小居民列表、状态、名单版本和留言板开关 |
| `GET /api/home/scene?type=living`                | 公共客厅布局、布局版本和能力             |
| `GET /api/home/scene?type=hall`                  | 走廊布局，过滤已删除居民的覆盖值         |
| `GET /api/home/scene?type=room&agentId=<id>`     | 当前身份代次的个人房间，只读             |
| `PUT /api/home/scene?type=living` 或 `type=hall` | 管理员保存或撤销公共布局                 |

写入包含 `expectedRevision`、`rosterRevision`、`requestId`，以及二选一的 `layout` / `undoRevision`。保存布局与回执使用同一 SQLite 事务；拒绝未知字段、过时版本、名单冲突、同请求不同参数和非法素材配置。原有 `GET /api/home` 管理台首页摘要保持兼容。`contentRevision` 当前为 0，`publish` 为 false，不表示发布功能已完成。

```sh
node --test --test-timeout=120000 test/home-persistence.test.mjs test/home-scene.test.mjs test/board.test.mjs test/board-console-ui.test.mjs
npm run verify
CHROME_PATH="<浏览器可执行文件绝对路径>" node test/home-space.browser.mjs
```

浏览器验收使用临时数据库、假传输和合成居民，检查保存/刷新/撤销、版本冲突、0/1/2/3/4/7 居民、稳定房门、375/390px 手机布局、完整留言板、旧管理台入口、失去登录与网络中断。`HOME_SPACE_OUTPUT` 可指定截图和报告目录。不等同于真实 AI 主人格布置、QQ 内置浏览器或公网访问验收。
