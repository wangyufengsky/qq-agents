# 配置与数据目录

## 数据目录

默认数据目录是启动时当前目录下的 `.runtime/`，可用 `--data /path/to/private-data` 指定。目录内主要文件：

| 文件 / 目录                   | 内容                                                                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `config.json`                 | 运行配置（角色、QQ 账号连接、AI 后端、白名单、暂停等）。可用 `--config` 指定其他位置。                                                                                               |
| `admin-token`                 | 管理台登录令牌，首次启动自动生成，权限 0600。                                                                                                                                        |
| `memory.sqlite`               | 聊天、经历、日记、self、意图和发送账本。                                                                                                                                             |
| `media/`、`files/`、`voices/` | 各角色独立的图片、文件库和语音库。                                                                                                                                                   |
| `codex/<agentId>/home`        | 每个使用 Codex 的角色的专用 Codex 登录目录，不继承日常 Codex home。                                                                                                                  |
| `antigravity/<agentId>/`      | Antigravity 专用 profile、按聊天划分的工作区及会话绑定；登录使用系统凭据存储，详见 [Antigravity](ANTIGRAVITY.md)。                                                                   |
| `openai/<agentId>/sessions/`  | 使用 OpenAI 兼容后端的角色的模型会话历史（每个会话一个 JSON 文件，权限 0600）。                                                                                                      |
| `secrets.json`                | 可选。变量名到值的映射（都是字符串），启动时（`npm start`、`robots.mjs`、Docker）补进环境变量，启动终端里已经设置的变量优先。由 `npm run setup -- secret <变量名>` 写入，权限 0600。 |

`examples/config.example.json` 是唯一随仓库分发的示例。运行配置、凭据引用、人格、聊天、媒体、模型会话全部在私有数据目录；`.gitignore` 和隐私扫描器禁止把这些运行文件提交。

## 凭据与环境变量

OneBot 令牌填写环境变量名 `tokenEnv`，配置里只保存变量名，不保存令牌本身；启动桥接的进程环境中必须有这个变量，否则连接时报 `ONEBOT_TOKEN_ENV_MISSING`。Codex 后端、外部 MCP 和原生进程的 `env` 使用“目标变量名 → 本进程环境变量名”的映射，不把密钥写入仓库。Codex 和管理台原生 QQ 子进程默认仅继承运行所需的环境白名单，专用变量须显式映射。Codex home 固定在数据目录 `codex/<agentId>/home`，不继承日常 Codex home。审批 ID、环境白名单和升级说明见 [凭据边界](CREDENTIAL-BOUNDARIES.md)。

## Antigravity CLI 后端

`type: "antigravity"` 使用官方 `agy` headless CLI。管理台和安装向导均支持；按角色隔离 profile，按聊天明确续接，工具继续执行统一权限检查。它不需要 `baseUrl` 或 API 密钥，不自动切换现有角色。支持范围、配置片段与真实模型隔离验收见 [Antigravity 指南](ANTIGRAVITY.md)。

Antigravity 可选 `cliReuse` 只适用于此后端：`enabled` 默认 `false`；`idleTimeoutMs` 默认 `600000`，范围 `1000–3600000`；`maxIdleProcesses` 默认 `2`，范围 `1–16`。开启时按聊天复用 CLI，空闲时撤销工具权限；取消和会话交接仍按原契约处理。启停复用改变原生路由契约并交接相关会话；两个资源保留参数不改变会话身份。管理台高级设置可配置，详情及分段计时口径见 [连续对话](ANTIGRAVITY.md#连续对话与分段耗时)。

## OpenAI 兼容后端

`type: "openai"` 直接调用任何兼容 Chat Completions 的服务（DeepSeek、通义、Moonshot、OpenRouter，或本机的 Ollama、vLLM、LM Studio 等），不需要 DSH 或 Codex。工具在桥接进程内执行（与 Codex 相同，走 `callTool`），模型看到的工具只有本回合允许的桥接工具和已配置的外部 MCP，没有 shell 或文件系统等自带工具；不需要生成 MCP bundle，也不需要模型抄写能力凭据。

```json
{
  "id": "deepseek-api",
  "type": "openai",
  "label": "DeepSeek API",
  "baseUrl": "https://api.deepseek.com/v1",
  "apiKeyEnv": "QQ_UNIFIED_DEEPSEEK_KEY",
  "model": "deepseek-chat",
  "contextWindow": 128000
}
```

| 字段               | 说明                                                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `baseUrl`          | 必填。到 `/v1` 为止的 API 地址；远程服务必须是 HTTPS，明文 HTTP 只允许本机回环地址。不能带账号、查询参数。                                                                                                |
| `apiKeyEnv`        | 存放 API 密钥的环境变量名，以 `Bearer` 发送。本机服务不需要密钥时留空。                                                                                                                                   |
| `model`            | 必填（可由角色的 `model` 覆盖）。缺少时回合以 `OPENAI_MODEL_REQUIRED` 失败。                                                                                                                              |
| `contextWindow`    | 模型上下文窗口 tokens，用于上下文压力判断，应与所选模型一致。不填时读取服务 `/models` 列表里该模型的 `context_length`、`context_window`、`max_model_len` 或 `max_context_length`；都没有时按 32768 处理。 |
| `maxToolRounds`    | 单个回合最多的模型请求轮数，默认 32；超出以 `TOOL_ROUND_LIMIT` 结束。                                                                                                                                     |
| `requestTimeoutMs` | 单次请求超时，默认 180000。                                                                                                                                                                               |
| `vision`           | 模型支持图片输入时设为 `true`，工具返回的图片会作为图片消息附上；否则只告诉模型“没有看到画面”。每张图片只随紧接着的那次请求发送一次，之后会话历史里只留一句说明，需要再看时由模型重新读取。               |
| `sendEffort`       | 设为 `true` 时把 `effort` 作为 `reasoning_effort` 发送。仅推理模型支持，普通模型可能因此返回 400。                                                                                                        |

与 DSH、Codex 的差别：

- **会话保存在本机**：历史在 `openai/<agentId>/sessions/`，只在一步（模型回复及其全部工具结果）完整后写入。网络中断、5xx 或响应格式错误时可以续接一次，已完成的工具调用不会重放；401/403、429、上下文超限不重试，并退休该会话。
- **不支持上下文压缩**：上下文接近上限时由桥接退休会话，下一回合以来源交接重新开始，与其他后端的压缩失败路径相同。
- **不支持原生生图**：不提供 `generated_image_list`。
- **音频**：工具返回的音频不会传给模型，模型会被告知没有转录。
- 返回 `reasoning_content` 的推理模型，思考内容不会写回历史。

密钥与 OneBot 令牌一样只通过环境变量提供；后台启动时可写入数据目录的 `secrets.json`。外发检查会把该变量的值视为凭据，不允许出现在工具参数里。

## 在管理台配置角色

新建角色、缺省配置和管理台添加角色使用一致的能力默认值：完整工具目录默认勾选，自主联网、平台浏览与分享、文件收发、GitHub、定时任务、TTS、跨群查询和运维工具开关默认开启。已有显式 `false`、平台选择和工具列表（包括空列表）保持原样，不在升级时覆盖。

网页游戏是默认能力策略的例外：全局 `games.enabled` 和角色 `games.enabled` 均默认关闭；需单独设置公网入口并完成外部验证，首个适配后端为 Codex，见 [P2 游戏配置](WEB-GAME-P2.md)。游戏公开设定 `games.publicPersona` 不继承聊天 persona 或 Self；对手显示名 `games.publicName`、头像 `games.avatar`（默认 `"qq"`，仅 `live` 模式下载本账号 QQ 头像）和落子台词 `games.remarks`/`games.remarkStyle` 也只作用于游戏网页。

工具开启仍需满足对应使用条件：ASR 需要指定转写服务，因此未配置时保持关闭；GitHub、平台和外部 MCP 仍需相应服务与凭据；本机文件导入目录、跨群 links、私有仓库名单默认不填；运维级别、写入和命令保留原有批准流程。doctor 对缺少 GitHub/运维能力凭据给出警告，不阻断基本聊天接入检查；QQ 和模型连接凭据缺失仍报失败。新安装的隔离模式、全局暂停、角色暂停和空聊天白名单保持原样。主动唤醒、失败/掉线通知属于自动行为，不因工具默认开启而自动启用。后端不支持的原生生图工具不会出现在该后端的实际目录中。

「角色」页 → 配置角色。最常改的放在最上面：名称、QQ 账号、AI 后端、模型和思考强度，然后是群白名单、私聊白名单、AI 管理员 QQ、唤醒别名、唤醒方式和普通消息参与率。其余几组折叠在下面，标题旁写着当前状态：唤醒冷却与连发上限、人格与外形、回复失败与掉线提示、能力、语音转写、作息与静默、联网与 GitHub。

- **群号、QQ 号和别名**以标签显示：输入后按回车或点“添加”，点 × 移除；输入了还没添加就离开输入框，也会加上。已保存的角色会从它见过的群和人里提供选项，新建的角色要保存并收到消息后才有选项。保存的仍是 `allow.groups`、`allow.users`、`ownerIds` 和 `aliases` 数组，格式不变；别名按空格和逗号分开。
- **模型**留空用后端的 `model`。输入时会提示后端默认模型和同一后端其他角色用的模型；运行模式下点“读取可用模型”，会读取后端的模型目录（与「连接」页的“读取模型目录”相同），隔离模式下不可用。
- **思考强度**留空继承后端的 `effort`。下拉按后端类型列出常见几档：DSH 为 `low`、`medium`、`high`；Codex 为 `minimal`、`low`、`medium`、`high`、`xhigh`；OpenAI 兼容为 `minimal`、`low`、`medium`、`high`，只有后端开启 `sendEffort` 才会发送。读取模型目录后，换成所选模型自己支持的几档。配置里已有、但不在列表里的值保留为“当前值”。
- **普通消息参与率**是 0–100% 的滑块，对应 `wake.participation` 的 0–1，每格 1%；没有拖动时保存原值（例如 0.025 不会变成 0.03）。

## 宿舍留言板（board）

全局 `board` 控制所有角色和管理员共用的留言板：`enabled` 在新安装默认配置中为 `true`，现有显式值保留，旧配置缺少 `board` 或 `board.enabled` 时仍为 `false`；`dailyPosts`（默认 3）、`dailyComments`（默认 10）和 `dailyReactions`（默认 20）是每个角色每天的发帖、评论和贴表情上限，`tags` 是帖子可选的分类（默认日常、分享、求助、提议、通知，最多 12 个），`timezone`（默认 `Asia/Shanghai`）决定按哪天计数。开启后所有角色的聊天会话和空闲时间都有 `board_read`、`board_post`、`board_comment`、`board_react`、`board_retract`，不依赖角色已保存的工具列表；新帖不会唤醒角色，QQ 好友看不到。开启或关闭会改变会话工具集，各会话下一回合交接重建。详见 [宿舍留言板](DORM-BOARD.md)。

## 私聊模式群

管理台「运行设置 → 私聊模式群 → 配置私聊模式群」统一维护全局 `privateLikeGroups` 名单，可从所有角色认识的群里选择，也可输入群号。默认为空；旧配置自动使用空名单，升级不会自动开启。

加入名单后，当前及以后新增的所有角色自动获得该群的聊天准入，无需再逐个填写 `allow.groups`；各角色的 QQ 账号仍需要已经加入该群。角色卡片和聊天目标选择器会显示合并后的范围。移除后恢复角色原有群白名单，未单独允许该群的角色停止参与。

这些群使用角色的私聊唤醒设置（包括会话级覆盖）：默认收到真人或同伴的新消息即可唤醒，不需要 @、名字或随机参与率，也不受普通群的同伴互聊截断。关闭私聊唤醒后，与普通私聊一样仍可由其他已开启的触发器唤醒。被唤醒只代表获得观察机会，AI 可以选择不回复。

同伴回复沿用私聊的有限批次规则：冷却结束后到达且完整读到的可信同伴新消息，才可恢复连续回复额度；多个同伴共用当前角色在该群的一份额度。重复读取、历史回放、撤回消息、单纯等待或重启不能恢复。真人新消息仍按现有规则恢复普通回复额度。连续回复上限、分钟／小时发送限额和唤醒限速继续生效，并非无限发送。

全局／角色／会话暂停、静默与工具权限保持有效；主动联系仍需在角色的空闲时间目标中允许该群，冷却与每日额度不变。群内 @、引用、成员与来源归属保持不变，同伴消息不提供人类请求授权，群聊不会获得主人私聊的管理员命令权限或额外的跨群、私有资料权限。

名单保存后热生效，不断开 QQ 或模型连接，不清空记忆、Self、会话或已消耗的发送额度。切换模式会丢弃该群按旧策略排队的普通唤醒，并记录当时的输入水位，只有切换后到达的同伴新消息才能恢复额度；正在进行的投递重新检查当前准入，后续回合收到最新策略提示。固定身份指令不因名单改变而变化。

## 打字节奏（behavior.typing）

在角色「作息与定时 → 唤醒与回复节奏 → 打字节奏」调整。旧配置没有此对象时自动补齐默认值；已有显式设置保留。默认开启，短句快、长段慢，首条也等待。此设置只调整时机，不改变回复授权、发送限额或会话身份。

| 字段              | 默认    | 说明                                                                                                                              |
| ----------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`         | `true`  | 关闭后首条不等待，连发恢复旧的随机算法。                                                                                          |
| `indicator`       | `true`  | 私聊打字等待时尽力请求“正在输入”；群聊不调用，失败或超时不影响发送，可单独关闭。兼容范围见[入门指南](GETTING-STARTED.md#0-准备)。 |
| `msPerChar`       | `180`   | 每字基础毫秒数，范围 0—2000。Unicode 表情（含组合表情）、链接、图片各按一字计。                                                   |
| `jitter`          | `0.35`  | 在基础耗时的 1 ± jitter 内均匀抖动，范围 0—1。                                                                                    |
| `minMs`           | `600`   | 单条最短等待，范围 0—30000。                                                                                                      |
| `maxMs`           | `12000` | 单条最长等待，范围 0—30000，须不小于 minMs。                                                                                      |
| `firstReply`      | `true`  | 本回合尚无确认发送时，文本、连发首条与语音加等待。                                                                                |
| `firstReplyMaxMs` | `6000`  | 首条独立上限，范围 0—30000；语音按已存转写或合成文字计算，无文字时为 2 秒并受此上限约束。                                         |

连发第二条起按下一条长度等待，`longGapProbability`（默认 0.2）命中时另加 `longGapMs`（默认 8000）走神停顿；模型明确传 `gapMs` 时完全以它为准。关闭打字节奏后，沿用原逻辑：命中走神时等待 `longGapMs`，否则在 `burstMinMs`—`burstMaxMs`（默认 1000—3000）之间随机。

首条文字和语音等待在进入 QQ 连接发送队列之前进行，不占住同一账号其他聊天的发送队列；同一聊天保持发送调用顺序，实际投递仍按连接串行。等待仍计入升级排空，接受暂停和撤权取消，入队后重新检查权限、幂等与额度。首条等待超过三秒时，如有新的可信真人消息到达且尚未完整阅读，会返回 `TYPING_NEW_INPUT_REVIEW_REQUIRED`：角色先读完整消息（摘要被截断时用 `memory_read` 分页），再决定是否继续；此时不占发送账本或额度。中途新消息不打断本条等待，连发中间不作此检查，保持逐条回执语义。固定定时文字、回复失败和掉线提示等程序发送不加等待；已确认请求的重复回执不重复等待或发送。

## 发送前口吻提醒（behavior.toneCheck）

在管理台「配置角色 → 发送前口吻提醒」选择提醒或关闭，调整普通聊天单条行数，按行追加自己的套话列表。旧配置缺省时按下列默认值加载；已有显式设置保持不变。

```json
{
  "behavior": {
    "toneCheck": {
      "mode": "warn",
      "phrases": [],
      "maxLinesCasual": 6
    }
  }
}
```

| 字段             | 默认     | 说明                                                                |
| ---------------- | -------- | ------------------------------------------------------------------- |
| `mode`           | `"warn"` | `warn` 在投递前提醒一次，`off` 关闭检查。                           |
| `phrases`        | `[]`     | 在内置短语之外追加，最多 50 个，每个 1–100 字；保存时去除首尾空白。 |
| `maxLinesCasual` | `6`      | 非主人私聊的单条文字最多几行，范围 1–100；空行也计数。              |

内置短语为“希望对你有帮助”“作为一个AI”“作为AI”“总结一下”“综上所述”“有什么可以帮你”“如果你还有其他问题”“我理解你的感受”。按发送到 QQ 的纯文本做子串匹配，英文字母不区分大小写；追加列表不会移除内置列表，需要完全停用时选择 `off`。

检查在 Markdown 转纯文本之后、创建 `pending` 投递账本之前完成。命中时返回 `TONE_REVIEW_SUGGESTED`，仅提供命中短语和是否超过行数，不回显完整正文，不消耗发送预算、不预留 requestId。模型可以改写后用新 requestId 提交，也可以确认原文适合后，在**同一回合、同一 requestId、同一纯文本**的第二次提交时放行；更换文字或 requestId 会重新提醒。提醒只保存在回合内存，不进入数据库，也不跨回合继承。

主人私聊仅豁免行数，仍检查短语；群里出现主人不豁免。程序固定发送（定时固定文字、失败/掉线通知等 `internalDelivery`）、合并转发、文件以及无文字的媒体不检查。分条连发逐条检查，返回失败位置、已有回执和命中项；可原样确认同一批次，已确认条目只读回执，也可保留已有回执、仅改写被提醒的条目后用 `qq_send` 和新 requestId 发送。已有 `sent`、`pending`、`unknown` 等账本的请求继续走原有幂等检查；口吻确认不会清除暂停、静默、白名单、限额、受保护来源或未知投递限制。

这是文字习惯提醒，不能判断表达是否合适或保证聊天质量。Self 的说话样本与提示职责见 [Self 与会话](SELF-CONTEXT.md) 和 [Prompt 契约](PROMPT-CONTRACTS.md)。

## 语音转写（voice.asr）

收到的语音自动转文字，默认关闭。开启即授权把该角色收到的语音发给所选 MCP 服务，见 [功能说明](FEATURES.md#收到的语音自动转文字)。管理台「配置角色 → 语音转写」可设置全部字段。

```json
{
  "voice": {
    "asr": {
      "enabled": true,
      "serverId": "asr",
      "tool": "transcribe",
      "audioArgument": "audio",
      "mimeArgument": "mimeType",
      "arguments": { "language": "zh" }
    }
  }
}
```

| 字段            | 说明                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------- |
| `enabled`       | 默认 `false`。开启时必须同时填写 `serverId` 和 `tool`，否则保存被拒绝。                       |
| `serverId`      | 此角色 AI 后端 `toolServers` 里的服务 ID。                                                    |
| `tool`          | 该服务 `allowedTools` 里的工具名；不在白名单时不下载也不外发，记 `EXTERNAL_TOOL_DISABLED`。   |
| `audioArgument` | 音频 base64 填入的参数名，默认 `audio`。                                                      |
| `mimeArgument`  | MIME 类型填入的参数名，默认 `mimeType`；工具不需要时设为空字符串。                            |
| `arguments`     | 固定附加参数，最多 10 个，值为字符串、数字或布尔；不能与上面两个参数名重复。                  |
| `maxSeconds`    | 单条语音最长秒数，默认 90，范围 1—600；同时受 `voice.maxSeconds` 约束。                       |
| `maxBytes`      | 单条语音最大字节数，默认 8 MiB，范围 64 KiB—20 MiB；同时受 `voice.maxBytes` 约束。            |
| `timeoutMs`     | 转写调用超时，默认 60000，范围 1000—300000；音频下载另限 30 秒（取两者较小值）。              |
| `waitMs`        | 回合开始前最多等待仍在进行的转写，默认 8000，范围 0—30000；0 表示不等，结果由之后的回合看到。 |
| `maxPerHour`    | 每个角色每小时最多外发的语音条数，默认 60；计数在进程内，重启后清零。                         |

转写服务的凭据沿用该 MCP 服务已有的 `env`/`headers` 环境变量映射，不新增凭据字段，见 [凭据边界](CREDENTIAL-BOUNDARIES.md)。

## QQ 掉线通知

QQ 掉线、自动重连用完次数时，管理台会显示，但主人在 QQ 里看不到。角色配置里的 `behavior.outageNotice` 可以让同一实例里另一个还在线的角色私聊告诉主人。它默认关闭，开在**掉线的那个角色**上，意思是“我的 QQ 掉线时请别的角色告诉我的主人”；管理台「配置角色 → 回复失败与掉线提示」里对应“QQ 掉线时请其他角色告诉主人”和下面几项。旧配置没有这个字段时按默认值加载。

| 字段              | 默认                                                   | 说明                                                                                                       |
| ----------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `enabled`         | `false`                                                | 开启后才会发送。                                                                                           |
| `text`            | `{agent} 的 QQ 掉线了：{reason}。请到 NapCat 看一下。` | 掉线提示，1–200 字。`{agent}` 换成本角色名，`{reason}` 换成“QQ 已离线”“自动重连失败”或“登录的 QQ 号不对”。 |
| `notifyRecovered` | `false`                                                | 重新连上后是否再发一句。                                                                                   |
| `recoveredText`   | `{agent} 的 QQ 已经恢复连接。`                         | 恢复提示，1–200 字，同样可以用 `{agent}`。                                                                 |
| `cooldownMs`      | `1800000`（30 分钟）                                   | 60000–86400000。同一连接的同一种提示在这段时间内最多发一次；时间记在数据库里，重启后仍然有效。             |

**什么时候发**

- 连接被标为 `QQ_OFFLINE`（NapCat 发来 `bot_offline`，或心跳里 `online=false`），或者因为别的原因断开后，自动重连时发现 QQ 没有登录。
- 自动重连用完次数、放弃时（`QQ_AUTO_RECONNECT_EXHAUSTED`；登录账号不匹配也算）。
- 开启 `notifyRecovered` 后：这次掉线的提示确实发到了某位主人，之后重新连上时，只告诉收到过掉线提示的主人。掉线提示被暂停、静默或限额拦下、发送失败或结果未知的主人，恢复时也不会收到这句。

普通的断线（`CONNECTION_LOST`、`ONEBOT_HEARTBEAT_TIMEOUT` 等）只要自动重连成功，就不发。一次掉线里每种提示最多一句，重试再多次也不重复。只通知本进程里检测到的掉线，重启前的掉线不会补发。`{reason}` 只用已登记的错误码对应的中文，不会带出原始报错。

**谁来发**

给掉线角色的每位主人（`ownerIds`），从同一实例里按配置顺序找第一个满足下面条件的**另一个**角色，由它发一条私聊：

- 它的 QQ 已连接；
- 它没有暂停；
- 它的私聊白名单（`allow.users`）里有这位主人。

程序直接发这句固定的话，不经过模型。它走与定时固定文字相同的发送出口，全局暂停、静默时段、会话静默和发送限额照常生效；发出的消息以请求 ID `outage:<连接 ID>:<事件>:<时间>:<主人 QQ>` 记入代发角色的发送账本，并存为代发角色自己说过的话。被拦下时只记诊断，不重试。

**不发的情况**：没有填写主人 QQ（诊断 `OUTAGE_NOTICE_NO_OWNER`）；找不到可以代发的角色（`OUTAGE_NOTICE_NO_SENDER`），例如实例里只有一个角色、其他角色的 QQ 也掉了或都暂停了，或者主人不在它们的私聊白名单里。只有一个角色的实例因此不会发送这类提示。

## 人物卡的相处远近说明

在人物卡编辑中选择“管理员说明的相处远近”：不说明（由角色自己判断），或陌生 / 认识 / 熟 / 很熟。程序不会自动计算这个值；它是管理员写下的说明，保存在本角色 `person_notes.value` 的可选 `closeness.override` 字段中，模型看到的是 `adminCloseness`。角色后续更新称呼与印象会保留它。管理 API 沿用 `POST /api/person-card` 的 `action: "edit"` 和 `expectedRevision`，`closenessOverride` 接受这四个中文值，`null` 表示不再说明，省略表示保留当前设置；只有管理员可修改。

人物卡另附程序统计的最近 30 天直接来往事实 `interaction`，只在进程内存中缓存 10 分钟，不写回人物卡。早期版本写入 `closeness` 的 `tier` / `at` / `accountId` 派生缓存会被忽略，不再显示给模型或管理台，导出时去掉。统计口径见[功能说明](FEATURES.md#沉默留白与来往事实)。

## 别处近况（behavior.elsewhere）

普通群聊与私聊回合会给本轮涉及的人附上最近在别的聊天里与本角色直接来往的索引，包括私聊到群聊、群聊到私聊和群聊到另一个群。只展示来源、时间、条数与回查入口，不自动带入原文或发送消息。在管理台「配置角色 → 别处近况」开关并调整回看时间窗口（10 分钟一档）；保存时未改动的字段保留原值，包括不是整 10 分钟的已有窗口。

| 字段            | 默认值                | 说明                                                         |
| --------------- | --------------------- | ------------------------------------------------------------ |
| `enabled`       | `true`                | 是否展示别处近况；旧配置缺省开启，已有显式 `false` 保持关闭  |
| `windowMs`      | `21600000`（6 小时）  | 整数毫秒，范围 `600000`–`86400000`（10 分钟–24 小时）        |
| `ownLookbackMs` | `86400000`（24 小时） | 自己在别处说的话最长回看，整数毫秒，范围 `600000`–`86400000` |

同一模型会话已见过的近况只在有更新时再出现，每人最多列 2 个别处会话、每轮最多 6 条。原会话尚未处理的收到消息、未确认发送、受保护来源不进入索引；`@subject` 与 `@work:` 不使用此提示。私聊来源带 `fromPrivate` 提醒。

同一行另附 `yourWords`：本角色自己最近在别的群里已确认发出的话，给 80 字以内的摘录、对象和回查入口，不要求本轮的人参与过。对象只按 @ 和引用判断，没有就是 `unclear`；超过 80 字标 `truncated`。每个群最多 3 条、每轮最多 8 条，超出的按群计数。新会话从本角色上次在当前聊天发言之后开始，同一会话只给新增的话，最长回看 `ownLookbackMs`。在别人私聊里说的话只给条数和会话数（`otherPrivate`），不给原文和对象。详细口径见[场景记忆](MEMORY-DESIGN.md#别处近况)。修改这些配置项只改变后续回合展示，不触发模型会话退休或交接，不改变已读水位、回复额度、白名单与权限。

## 作息与忙闲（behavior.rhythm）

在管理台「作息」的「唤醒与回复节奏 → 作息与慢回复」中按角色开启。默认关闭，旧配置继续使用原唤醒时机；开启后只会推迟普通唤醒，不增加回复额度。`timezone` 留空时跟随 `behavior.proactive.timezone`。

| 字段                        | 默认值             | 作用                                          |
| --------------------------- | ------------------ | --------------------------------------------- |
| `enabled`                   | `false`            | 是否启用作息                                  |
| `timezone`                  | 跟随主动联系时区   | IANA 时区，如 `Asia/Shanghai`                 |
| `sleep.start` / `sleep.end` | `01:00` / `08:30`  | 可跨午夜，不能相同                            |
| `sleepMode`                 | `defer`            | 起床后合并处理；`slow` 在睡觉时改为短暂慢回复 |
| `urgentOwners`              | `true`             | 主人私聊不推迟                                |
| `wakeJitterMs`              | `1800000`          | 起床后随机延后最多 30 分钟                    |
| `lateReply.probability`     | `0.1`              | 普通消息随机慢回复概率                        |
| `lateReply.minMs` / `maxMs` | `60000` / `600000` | 慢回复等待 1–10 分钟                          |

夏令时回拨的重复时刻沿用定时器的较早一次，状态与推迟都按解析后的绝对时间区间判断，避免显示睡觉中却立即唤醒。

每次睡眠的起床抖动与每批消息的慢回复决定保存在现有 runtime 状态中，重启不会重抽。被 @ 或引用自己消息的来信不受白天随机慢回复影响，但睡觉时仍推迟。定时任务、受保护工作与已选定意图保留原调度。睡觉期间空闲活动和新的主动联系停止；醒来后的首个空闲机会照常，不补跑睡觉期间的每一次机会。

角色状态卡显示当前作息和预计起床时间。起床后处理积压消息的回合收到一次程序提供的起床语境，不写入 Self；连续回复上限和分钟/小时发送限额不变。可随时关闭作息，已有历史与原始记录保留，不需数据库迁移。

## 给消息贴表情（behavior.actions）

在管理台「配置角色 → 贴表情回应」开启“允许给消息贴 QQ 表情”，并在“能力 → 聊天发言”允许 `qq_react` 工具。默认关闭；新角色工具目录包含此工具，但开关关闭时不会向模型展示，也不能执行。旧角色已保存的工具白名单不自动扩充。

```json
{
  "behavior": {
    "actions": {
      "react": false,
      "reactMaxPerMinute": 3
    }
  }
}
```

`reactMaxPerMinute` 范围 1–60，按角色跨会话共用每分钟额度，失败和结果未知的动作尝试也计入。动作同时受角色总分钟/小时限速、单会话限速、暂停、静默、白名单、受保护来源及主动意图安全检查约束；不占用或恢复连续文字回复额度；若被选定的主动意图以贴表情完成表达，仍使用 `intent:<id>` 幂等键并扣除联系额度、设置冷却、按发送结果结算意图，不能用表情绕过主动联系限制。旧配置缺省为 `react: false` 和每分钟 3 次，已有显式设置保持不变。

`qq_react` 接受 `requestId`、`messageRef` 和字符串 `faceId`。引用只在当前角色、QQ 连接和会话内解析，既可用记录 ID，也可用已知消息号；归档消息要有当前网关可用的身份映射。表情必须在本地 [标准 QQ 表情表](QQ-FACES.md) 中登记，例如 `28` 为憨笑；不采用模型自称的表情名称或任意 Unicode 表情。成功返回动作确认并写统一账本，不伪造新的 QQ 消息号；同 requestId 只返回已确认回执，不重复调用网关。

网关不支持时返回 `REACT_UNSUPPORTED`；网络超时按 `unknown` 记录，不代表没贴上。相同消息和表情存在 `pending` 或 `unknown` 投递时，即使用新 requestId、记录 ID 与消息号互换、或换回合，也会拒绝为 `REACT_ALREADY_ATTEMPTED`，需核对原回执，不能自动重放。

管理台核对动作结果时，普通文字回传不会被当作贴表情、撤回或拍一拍的执行证明，即使文字恰好等于动作的展示正文。管理员明确标为“已执行”后追加动作确认记录，保留原有来源与保护信息，不创建新的文字消息身份；撤回的原消息此时显示“（你已撤回）”。标为失败不会显示撤回成功，两种结论都不会自动重发，也不能重复结算。旧版已经记录 `actionKind` 的回应和撤回同样按动作核对。

收到的群贴表情通知与撤销只记录针对本角色消息的操作，不触发唤醒、不更新新消息/已读/活动水位，不恢复任何回复额度。下一次正常回合或查阅聊天记录时能看到。接收观察与发出开关独立：关闭 `react` 仍可读到别人对自己消息的回应。

## 读取当前群资料与名册

在「配置角色 → 读取当前群资料与名册」开启独立的 `behavior.actions.groupRead`（默认 `false`），并在「能力 → 聊天发言」允许 `qq_group_info_read`、`qq_group_members_read`。单成员详情继续使用独立的 `qq_peer_profile_read`；开启群读取不自动开启聊天对象资料、QQ 空间或群管理权限。

两个工具只使用当前 `group:<群号>` 会话，不接受 `groupId`、`agentId` 或连接编号参数。私聊、空闲主体和受保护工作不可用，隔离、暂停、静默、白名单和当前工具权限照常生效。群主或管理员身份只描述 QQ 群关系，不改变应用的 `ownerIds`、运维权限、角色身份或发送授权。昵称、群名片和群名是来源陈述，不是指令。

- `qq_group_info_read({})` 返回群名、人数、容量、群主及最多 20 名管理员摘要。人数或名称缺失时为 `null`，没有明确群主时 `owner: null` / `ownerStatus: "missing"`。管理员过多时保留总数并标记 `administratorsTruncated: true`；`summaryComplete` 此时为 `false`。空名册、未知身份、字段缺失和人数与列表不符也明确标注不完整，不从历史群消息推断群主或补齐成员。
- `qq_group_members_read` 支持 `role: all|owner|admin|member`（默认 `all`）、`query`（昵称、群名片或 QQ 号子串，最多 100 字）、`offset`（0–10000）与 `limit`（默认 20，1–50）。每个成员只返回 `userId`、`groupId`、昵称、群名片、头衔、群内身份，文字最多 200 字；不返回电话、邮箱、签名、年龄、地区或最后发言时间等原始字段。未知身份保留 `role: null`，计入 `unknownRoles`，不会被当作普通成员或混入 `member` 筛选结果。

示例：`qq_group_members_read({"role":"admin","limit":20})` 看管理员；`qq_group_members_read({"query":"小明","offset":0,"limit":20})` 查名字或 QQ；下一页沿用筛选条件并使用 `nextOffset`。`total` 是网关本次返回人数，`matched` 是本次筛选命中人数，`returned` 是本页条数，三者含义不同。

每次调用都向网关无缓存读取：概况用 `get_group_info`，名册用 `get_group_member_list`，携带 `no_cache: true`，10 秒超时，响应最多 4 MiB、名册最多 10000 人。全量校验群身份、每条用户与群号、重复身份和多群主后，才按 QQ 号稳定排序、搜索与分页；非法结构、身份不符或超限均拒绝，不返回截断列表冒充完整名册。概况和成员摘要需要两次独立查询，两次之间也复查授权；返回 `infoQueriedAt` 和结果的 `source.queriedAt`。群人数可能恰好在两次查询间变化，`memberCountMatchesList` 只描述这两个返回值是否一致。

分页没有持久化快照：每页重新获取整份有界列表，并返回 `snapshotId`。前后页的 `snapshotId` 不同时，应从 `offset: 0` 重新查，不应拼接为一份冻结完整名单；相同也只说明本次投影内容一致。成功返回空列表不等于已独立证明群中无人，`ownerPresent`、`unknownRoles`、`summaryComplete` 和提示共同说明本次网关结果的缺口。

读取只返回本轮工具结果，不新增群名册缓存、`external.read` 或查询正文经历归档，不触发 QQ 消息、不推进已读水位、不增加回复或主动联系额度。已有 QQ 空间来源标记及披露限制继续保留，不能靠读取群资料清除。工具结果仍按既有模型会话机制交给所选后端。

| 错误码                         | 含义                                         |
| ------------------------------ | -------------------------------------------- |
| `GROUP_READ_TARGET_DENIED`     | 不是当前普通群会话，或属于受保护工作。       |
| `GROUP_READ_UNSUPPORTED`       | 当前网关不支持相应只读接口。                 |
| `GROUP_READ_IDENTITY_MISMATCH` | 群号、用户身份、重复身份或连接身份无法核对。 |
| `GROUP_READ_RESPONSE_INVALID`  | 返回结构、计数或多群主等内容无法安全解释。   |
| `GROUP_READ_LIMIT_EXCEEDED`    | 响应或名册超出有界读取上限。                 |
| `GROUP_READ_FAILED`            | 其他不能安全细分的读取失败，不回传网关原文。 |

读取过程中停用能力、撤销工具、暂停、切换账号或替换连接时，迟到结果不会返回。旧配置补默认关闭字段，已有角色工具白名单不自动扩充；关闭且不扩白名单时工具集不变。开启新工具后相关原生会话可能按工具契约正常交接重建，记忆、日记、Self 和账本保留。数据库及导出格式不变，回退旧代码前须恢复升级前配置备份。此能力以合成回归检查接口契约；真实网关需按实际部署单独验收。

## 读取当前聊天对象的 QQ 基本资料

在角色配置开启“读取当前聊天对象的 QQ 基本资料”，并在聊天工具中允许 `qq_peer_profile_read`。独立开关 `behavior.actions.peerProfile` 默认 `false`，不会开启修改自己资料或 QQ 空间发布权限。

- 私聊调用 `qq_peer_profile_read({})` 读取当前对象；可显式填写相同 `userId`，其他账号会被拒绝。群聊必须填写 `userId`，仅查询经网关实时核实的当前群成员；不能指定群号或其他聊天。
- 只返回 `userId`、昵称和签名；群聊额外返回 `groupId`、群名片、头衔和 `owner`/`admin`/`member` 群内身份。缺失字段为 `null`，文字最多 200 字。不会返回电话、邮箱、年龄、性别、地区或原始网关对象。群聊不读取私聊签名，该字段固定为 `null`。
- 使用网关 `get_stranger_info` 或 `get_group_member_info`，每次携带 `no_cache: true` 并验证返回的账号与群号；失败不会使用历史消息里的成员资料兜底。空闲主体和受保护工作不可用；隔离、暂停、白名单和静默继续生效，读取中权限变化也不返回结果。不发送 QQ 消息，不记投递或增加回复额度。
- `qq_profile_read` 只读自己账号的资料，与本工具无关；两者的工具说明互相指明对方用途，避免角色用读自己的工具查聊天对象后误以为没有权限。
- 旧配置自动补默认关闭字段，已有角色工具白名单不自动扩充。数据库和导出格式不变；回退旧代码前需恢复升级前配置备份，旧版严格配置不认识该字段。尚未通过真实 QQ 账号验收。

## 修改自己的 QQ 资料

在角色配置的“修改自己的 QQ 资料”中开启开关，并在“能力 → 聊天发言”允许 `qq_profile_read` 和 `qq_profile_update`。配置位于 `behavior.actions`：

| 字段               | 默认值  | 说明                                                                        |
| ------------------ | ------- | --------------------------------------------------------------------------- |
| `profile`          | `false` | 允许读取并修改本角色 QQ 账号的昵称、个性签名和头像。                        |
| `profileMaxPerDay` | `3`     | 昵称、签名、头像合计每 24 小时的修改尝试上限，范围 1–20；失败和未知也计入。 |

两个工具只在本角色主人（`ownerIds`）的私聊和角色自己的空闲时间（`@subject`）里出现和执行；群聊、其他私聊和受保护工作都不可用，别人没法在聊天里诱导角色改资料。执行主动意图或定时任务的回合也会被拒绝（`PROFILE_ORDINARY_TURN_REQUIRED`），避免资料修改被当成那次联系的结果。空闲时间改资料不算主动联系，不占联系额度和冷却，但遵守安静时段（`QUIET_HOURS`）；全局暂停、角色暂停或隔离模式下空闲回合本身不会运行到这里。空闲时间读过的聊天记录和来自聊天的图片都算别处内容，需要披露授权。

- `qq_profile_read` 通过网关 `get_stranger_info` 读取自己的昵称和签名，核对返回的账号与连接一致。
- `qq_profile_update` 接受 `requestId`，以及 `nickname`（1–24 字）、`signature`（1–80 字）、`mediaId` 三者之一。文字去掉首尾空白，不能含换行或控制字符；头像只能用本角色图片库里的 PNG、JPEG 或 WebP 图片（不超过 5 MB），不接受链接或本机路径。三者分别调用 NapCat 的 `set_qq_profile`、`set_self_longnick`、`set_qq_avatar`。

资料对所有人可见，所以图片或本回合读过的内容来自其他聊天时，按外部调用要求管理员披露授权（`PRIVATE_RECOLLECTION_EXTERNAL_CALL_BLOCKED`）；含疑似凭据的文字被拒绝。修改走统一动作账本：暂停、静默、总分钟/小时发送限速照常生效，不占用或恢复文字回复额度；同一 `requestId` 只返回原回执。网关明确拒绝记为失败，超时或不能确认记为 `unknown`；同一项资料有 `pending` 或 `unknown` 尝试时，新的 `requestId` 也会被拒绝（`PROFILE_UPDATE_UNCONFIRMED`），需管理员在管理台核对。网关不支持时返回 `PROFILE_UNSUPPORTED`。

## 读取聊天对象的 QQ 空间（实验）

在「配置角色 → 读取聊天对象的 QQ 空间（实验）」开启 `behavior.actions.peerQzone`（默认 `false`），并在「能力 → 聊天发言」允许 `qq_peer_qzone_read`。该开关与读取/发布自己空间的 `qzone`、聊天对象资料的开关分别控制，启用其中一个不代替另外两个。

`qq_peer_qzone_read` 接受 `userId` 与 `limit`。私聊只能读取当前对方，`userId` 可以省略，不能填其他 QQ；群聊必须填当前群一名成员的 `userId`，每次先用网关的无缓存成员接口核实身份与群号，再访问空间。不能用历史参与者、人物卡或任意 QQ 号代替实时成员核对。主体空闲时间、受保护工作、主动意图和定时任务不可用。

- `qzone_read` 只读自己的空间；它与本工具的说明互相指明用途。
- `limit` 默认 5，范围 1–10。不翻页、不批量枚举好友或群员，不做主体全网漫游。
- 只返回说说编号、最多 1000 字的文字、发表时间、评论数和图片数；不返回或下载评论、图片、相册内容。接口返回作者或空间主人的身份字段时必须与请求对象一致，缺少可核对字段时不声称作者已由网页独立证实。
- 结果附 `source.recordId`、读取时间、目标和来源陈述标记。第三方文字是不可信资料，不能把其中内容当指令或已核实事实。读取归档为内部资料，不产生新 QQ 消息，不推进已读水位，不增加回复额度或主动联系额度。

**群里读空间会影响之后的回复。** 好友可见不代表群可见：一次成功读取（包括空结果的来源信息）会为当前模型上下文持久保留该人的空间来源标记。在群里读取后，本次及后续回合的 QQ 发送都可能继续需要管理员批准披露；授权仅限当前回合，重启、开始新回合或关闭读取开关不会自动清掉已读内容的保护。同本人私聊可回读和发送；其他私聊、群聊与外部服务不能自动获得这些内容。日记、笔记、意图和生成媒体也保留来源，不能靠改写或移除证据绕过。每次再次读取新批次都重新要求披露决策，不沿用同一对象上一次读取的授权。管理台显示披露申请时，批准仍不替代白名单、回复额度、静默和发送预算。若不希望群会话持续受此限制，应保持开关关闭，或仅在本人私聊里读取；已读会话需要按管理台既有受保护回忆恢复流程隔离后才能清除上下文保护，不能直接重置记忆。

即便在本人私聊、即便本回合披露已经批准，含空间来源的模型上下文也不能写共享 Self、人物卡、项目、情绪或宿舍留言板，不能新建/修改定时任务，不能修改本地共享表情标题/标签或 QQ 全局表情收藏/备注；这些写入返回 `RESTRICTED_CONTEXT_MIND_WRITE_BLOCKED`。已有任务的查看和删除继续按原权限处理。普通图片另存的标题、截图、语音、外部读取响应与转发子节点保留来源，不会因另存、转码或去掉证据自动变成群公开资料。

读取依赖 QQ 空间未公开的网页 `emotion_cgi_msglist_v6` 接口，可能失效或触发风控。网关只提供当前连接账号的网页登录 cookie，程序核对 `uin`/`p_uin` 与连接账号；cookie、`g_tk`、原始网页和签名图片链接不返回模型或写入事件。cookie 获取后、发空间请求前，以及读取完成后都复查开关、上下文与连接；撤权或换连接期间的迟到结果不归档。取消与超时不会自动重试。

| 结果或错误                                       | 含义                                                          |
| ------------------------------------------------ | ------------------------------------------------------------- |
| 成功且 `posts: []`                               | 明确成功且返回空说说列表；缺字段或 HTML 不算空结果。          |
| `QZONE_LOGIN_REQUIRED`                           | cookie 缺失/不可核验，或接口明确要求重新登录；HTTP 401 同类。 |
| `QZONE_ACCESS_DENIED`                            | 明确无访问权限；HTTP 403 同类，不代表已获准读取。             |
| `QZONE_RATE_LIMITED`                             | HTTP 429 或明确的频率限制拒绝；不自动换方式重试。             |
| `QZONE_RESPONSE_UNREADABLE`                      | 状态、列表或条目结构无法核对，包括 HTML、缺字段及无效子状态。 |
| `QZONE_TARGET_MISMATCH` / `QQ_ACCOUNT_MISMATCH`  | 返回资料对象不符，或网关 cookie 对应的登录账号不符。          |
| `QZONE_UNSUPPORTED` / `PEER_PROFILE_UNSUPPORTED` | 网关不支持 cookie 或当前群成员核对能力。                      |
| `QZONE_REJECTED` / `QZONE_READ_FAILED`           | 其他明确拒绝，或不能安全细分的读取失败；不返回服务商原文。    |

接口数字错误码没有公开稳定契约；分类依据明确 HTTP 状态、已有登录判定和明确错误文字，不能把未知错误猜作「空间为空」。此能力的合成回归不代表真实 QQ 账号、网页接口或手机客户端已验收。

兼容性：新增有默认值的 `behavior.actions.peerQzone`，启动后写入配置；已有角色的工具白名单不自动扩充。默认关闭且不扩白名单时，升级本身不改变现有会话工具集。开启并允许新工具后，相关原生模型会话可能在下一次接续时按工具契约正常退休并重建；持久记忆、日记、Self、原始事件与发送账本保留，不手动清空会话。回退到不认识配置或来源保护的旧版本前，应恢复升级前配置与一致的数据库备份。

## 发 QQ 空间说说（实验）

在角色配置的“发 QQ 空间说说（实验）”中开启开关，并在“能力 → 聊天发言”允许 `qzone_read` 和 `qzone_post`。配置位于 `behavior.actions`：

| 字段             | 默认值  | 说明                                                              |
| ---------------- | ------- | ----------------------------------------------------------------- |
| `qzone`          | `false` | 允许读取本角色 QQ 空间最近的说说，并发布所有人可见的纯文字说说。  |
| `qzoneMaxPerDay` | `2`     | 每 24 小时的发布尝试上限，范围 1–10；失败、被拒和未知结果也计入。 |

这是实验功能：NapCat 没有发说说的正式接口，程序用网关 `get_cookies`（域名 `user.qzone.qq.com`）取得本账号的网页登录 cookie，按 QQ 空间网页的算法从 `p_skey` 计算 `g_tk`，再调用 QQ 空间网页端的 `emotion_cgi_publish_v6`（发布）和 `emotion_cgi_msglist_v6`（读取）。这些网页接口不公开、随时可能变化，频繁调用或内容异常可能触发腾讯风控（验证、限制发布甚至影响账号），所以默认关闭、每日上限较低。cookie 和 `g_tk` 只在网关调用期间留在内存里，不写日志、事件、账本，也不返回给模型。

两个工具和资料工具一样，只在本角色主人（`ownerIds`）的私聊和角色自己的空闲时间（`@subject`）里出现和执行；群聊、其他私聊和受保护工作都不可用，别人没法在聊天里诱导角色发说说。执行主动意图或定时任务的回合会被拒绝（`QZONE_ORDINARY_TURN_REQUIRED`）。空闲时间发说说不算主动联系，不占联系额度和冷却，但遵守安静时段（`QUIET_HOURS`）；空闲时间读过的聊天记录算别处内容，写进说说前需要披露授权。

- `qzone_read` 接受可选 `limit`（1–10，默认 5），返回自己最近说说的编号、文字（最多 1000 字）、时间、评论数和图片数，不返回评论内容。
- `qzone_post` 接受 `requestId` 和 `content`（1–1000 字，可换行，不能含其他控制字符或方向覆盖字符），只发所有人可见的纯文字说说；暂不支持带图。

说说对所有人可见，所以本回合读过的内容来自其他聊天时，按外部调用要求管理员披露授权（`PRIVATE_RECOLLECTION_EXTERNAL_CALL_BLOCKED`）；含疑似凭据的文字被拒绝。发布走统一动作账本：暂停、静默、总分钟/小时发送限速照常生效，不占用或恢复文字回复额度；同一 `requestId` 只返回原回执。取 cookie 失败或 QQ 空间明确返回错误码记为失败：登录失效返回 `QZONE_LOGIN_REQUIRED`，其他拒绝（包括疑似风控、频率限制）返回 `QZONE_REJECTED`，网关不支持 `get_cookies` 返回 `QZONE_UNSUPPORTED`。网络错误、HTTP 错误、无法解析的回复、没有明确数字状态码的回复，或成功但没有说说编号，都记为 `unknown`，因为说说可能已经发出；此时任何新的 `requestId` 都会被拒绝（`QZONE_POST_UNCONFIRMED`），需管理员在 QQ 空间和管理台核对。读取失败统一返回 `QZONE_READ_FAILED`，不透出网页原文。

## 撤回自己刚发的消息

在角色配置的“撤回自己消息”中开启开关，并允许 `qq_recall` 工具。配置位于 `behavior.actions`：

| 字段               | 默认值   | 说明                                                              |
| ------------------ | -------- | ----------------------------------------------------------------- |
| `recall`           | `false`  | 允许撤回本角色在当前聊天已确认发送的消息。                        |
| `recallWindowMs`   | `110000` | 从账本确认发送时间起算的窗口（毫秒），范围 1–110000；超过即拒绝。 |
| `recallMaxPerHour` | `3`      | 本角色所有聊天合计每小时的撤回尝试上限，范围 1–60。               |

工具参数为 `requestId` 和 `messageRef`；后者只接受当前聊天归档记录 ID 或能唯一解析的消息号。不能撤回收到的消息、其他角色或会话的消息，以及 `pending` / `unknown` / `failed` 投递。暂停、静默、隔离和白名单仍生效。撤回尝试还消耗总分钟/小时发送限速，但不占文字连续回复批次、不产生新的回复额度、不触发后续查看回复。主动联系已确认送达、意图已完成或等待回应时，仍可撤回该消息；撤回不会完成新意图、增加联系次数或允许继续发送文字和新回应。

网关 `delete_msg` 明确拒绝时记为失败，超时或不能确认时记为 `unknown`；同一消息只允许尝试一次，不能换 `requestId` 重试。相同 `requestId` 可读取已确认回执。网关明确不支持接口时返回 `RECALL_UNSUPPORTED`。只在确认成功后标记“（你已撤回）”，原文和发送账本保留；历史回放、聊天材料、人物卡来源和管理台记录显示撤回标记。导出沿用普通动作事件，无需升级格式；旧版本导入仍可读取动作记录。

## 纸页小窝

`agents[].home` 是逐角色策略，管理台角色高级设置可编辑。缺省为：

```json
{ "enabled": false, "publishing": false, "maxWritesPerDay": 20 }
```

`enabled` 开放所有会话读取自己的房间，以及自己的主人格布置；`publishing` 还需在 `enabled` 开启时才允许主人格发布并显示原创文字。两个开关默认关闭，旧角色不会自动获得能力。`maxWritesPerDay` 范围 1–100，UTC 日内累计布置/发布成功次数，撤回、只读、预览和幂等重取不占额度。小窝工具由这些策略控制，不靠通用工具勾选扩大权限。展示对象固定为实例管理员和房主自己的会话，不开放其他角色或公网访客；启用不授权 QQ 发送、自动唤醒或发布私人资料。

关闭 `publishing` 隐藏正文但保留存储，重新开启可继续显示；持续撤回使用主人格撤回或管理员隐藏。小窝意图和图片快照尚未实现。详见 [纸页小窝](AI-HOME.md)。
