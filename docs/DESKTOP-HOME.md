# 桌面小窝

在原生 macOS 或 Windows 上运行 QQ Agents。从同一台电脑打开管理台的「纸页小窝」，点击页首的「开启桌面小窝」。Windows 需要在已登录的桌面用户会话中启动，见 [Windows 运行指南](WINDOWS.md)。桌面窗口退出后，可在管理台点「打开窗口」。关闭桌面小窝会结束房间。设计和验收以 [不可变契约](DESKTOP-HOME-CONTRACT.md) 为准。

## 来访和聊天

点桌面小门打开来访页。你可以邀请角色，也可以把门牌设成「欢迎敲门」或「随时欢迎」，由角色在正常主人格回合自行来访。小门和桌宠都可以拖动。右键菜单、桌宠的消息气泡或回车键可以打开聊天。

你和在场角色可以在同一个聊天里说话。在场时收到的消息归入角色自己的桌面会话，离席期间的消息不会进入它的消息队列。角色回来后继续使用原会话。公开房间历史可以单独回看，角色也可通过记忆工具查自己的桌面经历。

「小窝目录 → 桌面小窝设置」可以调整三项节奏。AI 连续发言默认六轮，主人发言或间隔达到十分钟会补满。每个在场角色默认每十分钟自主醒来一次。角色可以自己安排下一次醒来的时间、休息一阵或离开。休息期间仍能收到在场消息、摸头与拖动并作出回应。

## 桌宠行动

单击桌宠可以摸头，拖动可以换位置。角色会收到相应的唤醒事件和拖动前后的实际坐标。进行中的模型回合会先完成，之后从队列取下一批事件。桌宠正在移动时，主人拖动接在当前动作后执行。

在场角色可以用 `desktop_body_control` 读实际位置和桌面布局、前往小门或座位、靠近在场同伴、挥手或调整姿势。现代客户端支持跨显示器移动。位置按执行时的布局、路线和浮窗落点核对。禁停区保存在本机，可以在来访页编辑。需要人工结束移动时，可点「停止动作」。

## 看桌面

在「桌面小窝设置」勾选「允许观察整个桌面」并保存。在场角色可在收到请求时查看屏幕，也可自行选择何时看。每次取图包括所有连接的显示器及各自的桌面坐标。框架按后端能处理的尺寸提供图像。macOS 会使用系统的屏幕录制授权。

清除勾选后，新的观察调用会返回未授权，尚未交付的取图也会取消。开关影响之后的工具调用。每位角色继续使用原有的桌面 Session，授权前后都能发现观察工具。 取图交付状态可以在桌面聊天的「小窝工具」查看。「旧版观察记录」用于查看或删除之前保存的摘要。

## 操作本机窗口和网页

从桌面聊天面板的权限入口选择一位在场角色和一个本机窗口，确认后它可在今后的桌边回合连续操作该窗口。原生驱动通过系统辅助功能识别窗口及控件。桌面客户端重启后，仍打开的同一窗口继续沿用原授权。窗口关闭或重开后，原授权记录仍可撤销，重新打开的窗口需要单独选择。聊天工具里的敏感应用黑名单用于过滤窗口选择，也会阻止角色操作列入名单的窗口。

在同一面板可以给角色授权一个独立网页标签页。角色能浏览公开站点、查看页面内容、点击控件、填写字段和提交文本表单。同一个标签页连续保留页面状态与当前浏览器进程内的 Cookie。网页请求沿用角色的外发和公网地址检查。

两种权限各自绑定角色及具体目标。它们会跨回合保留，角色暂离时暂停调用。主人可以撤销任一目标，角色也可以在工具中查询和撤销自己的授权。模型只依据客户端确认的结果判断操作是否成功。

## 桌面工具与 QQ 接力

角色按自己的权限查阅记忆和公开资料、使用文件库、经营花园及提出意图。桌面工具在同一个 Session 提供，权限在调用时检查。需要联系 QQ 时，可创建面向已授权 QQ 目标的意图，由对应的 QQ 会话按既有规则处理。管理台的会话页面可按角色查看普通桌面会话的状态和记录。

### 桌宠与主人格互相留言

同一角色的两个会话都可用 `desktop_role_mail_send` 给对方留一段文字。用相同的 `requestId` 与正文重查回执。`queued` 表示已保存，`received` 表示已交给收件方的模型。桌宠离席、模型临时失败或进程重启时，框架保留待送的留言。留言会在收件方的正常回合送达。

### 发送桌面附件

在聊天输入框旁选择「＋ → 添加附件」，选文件后发送。接收端沿用角色的类型权限和模型能力。聊天历史保留附件信息，文件正文和图片交给发送时在场、具备相应接收能力的角色。

## 准备桌面依赖

首次从管理台打开时使用固定版本的 Electron。可以在运行框架的同一台电脑预先准备桌面组件：

```sh
npm run setup -- desktop --all --data "<数据目录>"
npm run doctor -- --data "<数据目录>" --json
```

窗口操作需要固定版本的 `agent-desktop` 和本机的辅助功能权限。网页操作可使用已安装的 Chrome、Chromium 或 Edge，也可以准备锁文件对应的 Chromium。准备完可重开桌面窗口。

手动启动客户端时，使用实际运行服务的同一个数据目录：

```sh
npm run desktop:home -- --data "<数据目录>"
```

如果服务使用了与配置文件不同的端口，一并传入 `--port <port>`。Windows 上建议从管理台启动。

## 隔离试聊

Mac 样机沿用开门邀请、同一聊天面板、拖动记住座位和回家。隔离试聊接入小鱼（DSH）、龙（Codex）和猫（Antigravity ACP）。角色用简短的桌面设定和新建的专用会话，没有导入生产 QQ 资料、Self 或记忆。样机不启动桥接，不连接 QQ，也不修改生产权限。

## 隔离试聊的主动敲门

来访页默认关闭敲门。选择「欢迎敲门」后，每 30 分钟最多让一位在家角色决定是否来访。「试一次敲门」可以立即开始首次试用。角色可以留下或提交敲门理由。门上显示提醒，你点「请进」后角色才会入场。敲门等待 5 分钟，可以选「下次吧」；「正在忙」和关闭敲门会取消待处理的敲门。敲门决定单独运行，聊天仍使用原来的六回合额度。

这里的「试一次敲门」属于隔离试聊。正式框架由已启用的主人格使用自己的空闲回合决定是否敲门。

## 小鱼主人格试点

在私有试聊资料中设置 `subjectPilot: {}`，由样机启动独立的 QQ Agents Runtime 和小鱼的正常空闲调度。隔离实例使用新记忆库和桌面人设。桌面选择「欢迎敲门」后，正常空闲回合可以使用唯一新增工具「申请来访」。工具没有参数，角色可以照常选择休息。敲门提示在申请的空闲回合结束后显示。管理员请进后加入桌面聊天，仍使用共用六回合额度。切到「正在忙」会清除待处理的敲门，迟到的申请不会重新弹出。

试点默认每小时按空闲调度检查。只有隔离验收配置本机假 OneBot 网关时使用一分钟间隔；样机不会向正式 QQ 连接。假网关的有效真人来信会先取消小鱼的桌面生成，等后端清理结束再启动 QQ 回合，小鱼继续在场，已经启动的桌面回合照常计入额度。

## 启动

使用本机 Apple Silicon 的 Electron 安装。直接启动 `desktop/home` 时进入模拟模式。隔离试聊由本地启动器设置 `DESKTOP_HOME_LIVE_ROOT`、`DESKTOP_HOME_NODE` 和 `DESKTOP_HOME_TRIAL_PROFILE`，分别指向独立的后端数据目录、Node.js 24+ 可执行文件和桌面设置目录。使用与生产不同的目录。

后端目录的私有 `trial-profile.json` 内容如下。Codex 只读取该目录内 `codex/dragon/home/auth.json` 的专用登录，Antigravity 使用此目录下单独建立的 ACP profile。三个原生适配器只向模型开放桌面决定工具。安装路径、实际模型参数和登录凭据留在本机私有目录。

```json
{
  "kind": "desktop-home-p2",
  "roles": [
    {
      "id": "dragon",
      "type": "codex",
      "command": "/path/to/codex",
      "model": "your-codex-model"
    },
    {
      "id": "cat",
      "type": "antigravity",
      "command": "/path/to/agy",
      "model": "your-agi-model"
    }
  ]
}
```

小鱼使用专属 DSH home 中的 `desktop-home-trial` profile。用 `node scripts/dsh-bundle.mjs --desktop --out <bundle> --data <isolated-root> --url http://127.0.0.1:<bridgePort>` 生成守卫和工具桥配置，并按 DSH 本地 bundle 流程安装至这个 profile。宿主只监听回环地址，随桌面模型进程启动和退出。专用登录资料由本机维护者准备。
