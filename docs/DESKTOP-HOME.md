# 桌面小窝

## 正式框架

在原生 macOS 或 Windows 上运行 QQ Agents，从同一台电脑进入管理台的「纸页小窝」，点击页首的「开启桌面小窝」即可打开 Electron 桌面窗口。Windows 请在已登录的桌面用户会话中启动 QQ Agents，见 [Windows 运行指南](WINDOWS.md)。首次启动需要下载固定版本的 Electron。已开启但窗口已退出时，点击页首的「打开窗口」。点击「关闭桌面小窝」会结束房间并退出桌面客户端。

桌面窗口用书签切换「来访」和「聊天」。点击桌面小门打开来访页，按住小门拖动可挪到其他位置。小门会记住上次位置，换屏后自动收在可用桌面内。点击在场角色打开聊天，拖动角色可换座位。

来访页按角色生效的模型选择纸片形象。DeepSeek 用小鱼，Codex 或 GPT 用小龙，Gemini 用猫猫。没有识别到这些模型名称时，DSH、Codex 和 Antigravity 分别使用这三种后端的默认形象。桌边仍使用管理台配置的角色名称。

在场角色的浮窗有六套姿势，分别对应回复 QQ、桌边聊天、观察桌面、操控桌面、待机和睡觉。看屏和操作姿势只在当前请求执行期间出现，睡觉由角色作息或自主休息决定。每个状态会播放不到两秒的短动作，保持当前姿势几秒后再重复。系统开启「减少动态效果」时只切换静态姿势。聊天页显示在场角色、聊天记录和正在思考的角色。

在「小窝目录 → 桌面小窝设置」调整共用回合上限与补满间隔。回合上限可设 1–24，默认 6。补满间隔可设 0–1440 分钟，默认 60，设为 0 时只在管理员发新消息时补满。额度设置保存后立即生效。旧实例的桌面小窝默认关闭，升级时自动创建桌面历史表。

也可在运行 QQ Agents 的同一台电脑上，从项目根目录手动启动桌面客户端，将 `<data>` 换成实际服务的数据目录：

```sh
npm run desktop:home -- --data "<data>"
```

若服务启动时指定了不同于配置的端口，手动启动客户端时一并传入 `--port <port>`。Windows 上的数据路径如果包含命令行特殊字符，使用管理台启动。

客户端使用数据目录中的桌面专用凭据连接本机 Runtime。已配置的 Codex、Antigravity 和使用 `qq-unified` 预设的 DSH 可参加。桌面使用角色的当前 Self、模型和思考档位，每个角色有自己的 `@desktop` 对话会话。桌边始终按本机群聊运行，在场角色可以自然接话、旁听或回家。选择「欢迎敲门」时，已启用正常主人格回合的角色可自行申请来访。符合唤醒条件的 QQ 来信会先取消同一角色的桌面生成，小窝保留其在场状态。设计与验收范围见[桌面对话 Agent 三阶段计划](plans/desktop-dialogue-agent.md)。

## 准备桌面依赖

在原生 macOS 或 Windows 的 QQ Agents 代码目录运行准备和检查命令。省略 `--all` 会按已有配置准备已启用的项目。

```sh
npm run setup -- desktop --all --data "<数据目录>"
npm run doctor -- --data "<数据目录>" --json
```

- **桌面小窝和看桌面**需要固定版本的 Electron。管理台优先使用已准备的 Electron，未准备时沿用首次打开时下载的入口。
- **操作窗口**使用固定版本的 `agent-desktop`。Electron 和 `agent-desktop` 都会校验官方 SHA-256，按系统和版本存到数据目录的 `updates-runtime/desktop-dependencies/`。也可通过 `QQ_AGENTS_AGENT_DESKTOP_EXECUTABLE` 使用管理员配置的绝对路径。该路径优先。
- **操作网页**优先复用管理员指定的浏览器或系统已安装的 Chrome、Chromium、Edge。缺少浏览器时，准备命令安装与锁文件中 Playwright 对应的 Chromium。

软件准备可以重复运行。准备后重新打开桌面窗口，让客户端使用新的本机驱动。系统权限、角色工具开关和每次的操作目标仍在各自的入口管理。

## 桌面工具与 QQ 接力

在桌面小窝设置中勾选角色的「允许在桌面使用额外工具」。基础记忆工具沿用角色原有权限。勾选后，角色可按自己的权限使用公开网页读取、已启用平台的搜索、附件查看和文件库，也可将文本草稿存进自己的文件库。角色可写日记、修订自己的日记、提出 Self 候选，并查看可见的项目进度。Self 候选仍由主人格回顾。记忆和附件仍按资料来源与保护规则读取。需要联系 QQ 时，角色可以向自己的主人格提交提议，待审阅后由目标 QQ 会话决定是否发送。桌面可查看主人格的决定和已登记的投递状态，显示「接受」时尚不能确认消息已发出。工作接力可引用同一角色在桌面保存的工作笔记。

管理台的「会话状态」和「会话」页可按角色查看桌面模型会话与本机可读取的会话记录。桌面回合与 QQ 会话各自续接。

## 发送桌面附件

聊天面板的「附件」打开本机文件选择器。选择文件后点击「发送」。至少有一位在场角色勾选了「允许在桌面使用额外工具」，且具备对应接收能力时，才可发送该类型的附件。

- TXT、Markdown、CSV 和 JSON 须为 UTF-8 文本，每份最多 12 KiB。角色须开启文件接收。
- 静态 PNG、JPEG 和 WebP 每份最多 2 MiB。角色须开启图片输入，后端须为 DSH、Codex 或 Antigravity ACP。

聊天记录和历史只保留文件名、类型、大小和附件 ID。当前房间最多暂存最近八份附件的内容，只在发送当时有对应权限的角色这次到访期间提供。角色离席后重返、其他角色后来入场或查看历史时，框架只提供附件信息。

## 让角色移动自己的桌宠

在「小窝目录 → 桌面小窝设置 → 允许控制自己的桌宠」勾选角色并保存。角色到访后，可以在聊天面板说「@角色名 去小门旁边」或「坐回座位」。小门和座位须在角色当前显示器上。手动拖动角色保存座位。角色移动时不会改写座位。

拖动桌宠会立即打断移动，松手后要发新的桌边指令才能恢复控制。撤权、暂停、离席、关闭小窝、QQ 抢占或客户端失联会使原动作失效。模型只有收到客户端确认才会知道动作完成；失联可能留下结果未确认，再次下指令会从当前位置开始。桌宠控制独立于看屏、操作应用和无人值守活动。

## 安静陪伴

在「小窝目录 → 桌面小窝设置 → 允许在场时自主活动」按角色开启。获准角色在可见的小窝里会在空闲时自己决定走动、转向、等待或回家。走动仍需允许它控制自己的桌宠。每位角色至少间隔两分钟，每小时最多四轮，聊天使用原有额度。活动回合只处理桌宠本身，不发言、不取屏幕画面。

桌边新消息和 QQ 来信优先。聊天面板的「暂停自主活动」会停止当前活动，暂停适用于本次打开的小窝。重新打开小窝会重建到访状态，丢弃旧的等待和命令。隐藏小窝、锁屏、离席、撤权或作息休息也会使正在运行的活动失效。手动拖动会立即打断移动。

## 看桌面

在管理台的桌面小窝设置中开启「允许在本机授权看桌面」。桌面聊天面板里选择一位在场角色和一个本机窗口或显示器。角色须已获准使用桌面额外工具，并使用开启图片输入的 DSH、Codex 或 Antigravity ACP 后端。macOS 可能要求在系统设置中授予屏幕录制权限。Windows 请在已登录的桌面用户会话中操作。

授权后，角色可以在当前桌面回合调用 `desktop_screen_view` 取得一张 JPEG 截图。截图只交给该回合的模型。QQ Agents 不把截图写入房间记录或文件库，并在回合结束后退休包含画面的桌面模型会话。模型服务自身的会话记录遵循其保留规则。角色可在桌面回答你，取得画面后的本轮只保留桌面发言和历史、记忆读取能力。

Antigravity ACP 在当前桌面回合的下一次模型请求中接收图片。框架在交付前重新检查授权，截图不写入本机临时文件。

可以在聊天面板撤销授权或重新选择目标。角色离席、房间关闭或客户端失联后授权失效。被 QQ 来信打断的回合会取消本次取图。只有当前选中的窗口或显示器会被取图。

## 操作本机窗口

在管理台桌面小窝设置中开启「允许在本机授权操作窗口」，并按上文准备 [agent-desktop v1.2.0](https://github.com/vercel-labs/agent-desktop/releases/tag/v1.2.0)。macOS 需要授予启动上下文辅助功能访问权限，Windows 需要已登录且解锁的交互式桌面。

桌面聊天面板中选择一位已获额外工具权限的在场角色，再选择一个信任的应用窗口。角色用 `desktop_native_control` 获取该窗口可访问性元素的快照和本回合引用，再点击、滚动或替换文本字段。每次操作后重新观察。文本替换使用控件接口，适用范围由应用支持的辅助功能决定。敏感输入框、坐标点击和系统快捷键不在这套工具范围内。

macOS 全局窗口列表超时时，面板会先让你选应用，再查找该应用的可操作窗口。

撤销授权、角色离席或关闭房间会停止待处理动作。QQ 抢占会撤销当前回合引用并中止本机操作。已发出的动作可能已经到达应用，回执为未确认时，先观察窗口确认状态。

## 操作网页

在管理台桌面小窝设置中开启「允许在本机授权浏览网页」。在桌面聊天面板里为一位已获额外工具权限的在场角色选定使用 HTTP 或 HTTPS 默认端口的网站来源，例如 `https://example.com`。本机须有支持 Chromium 沙箱的浏览器，按上文准备，也可通过 `QQ_SCREENSHOT_BROWSER` 指定路径。

角色用 `desktop_browser_control` 在新的独立浏览器会话里导航、读取页面、点击链接或控件，以及填写当前页面的字段。每次导航或操作后重新观察，元素引用限于生成它的当前回合和页面状态。首版支持静态公开 HTML、同一来源内的导航和页面内操作。页面脚本、登录会话、跨站跳转、下载和表单提交暂未接入。框架回读字段验证填写结果，成功时返回 `filled: true`。填写内容留在当前页面。隔离渲染可能拦截写全站点来源的样式、字体或图片，样式重定向后的内部相对路径仍按原样式地址解析。

站点授权限定可访问的网站来源。角色给出的导航网址继续经过框架的外发检查，包括自主网络权限、预授权网址和记忆来源规则。

角色可关闭浏览器。撤销、离席和关闭房间会释放该浏览器，QQ 抢占会取消在途操作。网页内容只给当前桌面回合，包含观察结果的模型会话会在本轮结束后退休。浏览器的空白会话可随授权重新打开。

## 隔离试聊

Mac 样机沿用开门邀请、同一聊天面板、拖动记住座位和回家。隔离试聊接入小鱼（DSH）、龙（Codex）和猫（Antigravity ACP）。角色用简短的桌面设定和新建的专用会话，没有导入生产 QQ 资料、Self 或记忆。样机不启动桥接，不连接 QQ，也不修改生产权限。

## 房间规则

- 管理员邀请由角色的主人格决定同意或婉拒。角色忙时等待当前回合收尾，仍按现有主人格运行、暂停和休息规则检查资格。取消邀请、五分钟到期或关闭房间会撤销本次请求，迟到同意不安排入场。聊天额度从角色在场后开始扣除。
- 管理员的新消息补满共用模型回合（默认六次），覆盖上一段未完成的发言安排。已提交的回合收尾后继续，新消息取代的旧回复不显示。每次启动扣一次，沉默、取消和失败也计一次。单次调用可以包含后端内部的工具续推理。
- 定时补满默认距上次刷新 60 分钟，可配置或关闭。定时补满恢复可用额度，下一次聊天仍从新输入开始。
- 每个角色有一个独立的桌面会话。角色离桌后停止派发桌边消息，在途回复不再显示。回来从进门时的消息位置继续。新成员进门不更换其他角色的会话，也不清掉他们已收到的消息。桌面会话沿用框架的容量整理、闲置和失败退役规则，DSH 会话在各角色的桌面工作区。
- 正式框架把公开对话存入现有 SQLite，重新打开窗口可接着查看。角色在场时才实时收到消息，模型提交对应输入后按实际展示的记录登记已读。加入后可用 `desktop_room_history` 分页回看公开历史。回看不会补记离席时的个人经历、唤醒角色或增加回复额度。
- 桌面作为普通群聊来源。角色可用 `memory_search` 和 `memory_read` 查自己的经历，其中 `conversation: "@desktop"` 只查桌面记录。启用「别处近况」时，桌面可提示 QQ 群的近期发言，QQ 和空闲回合也能提示角色在桌面已确认的发言。跨场景使用资料沿用原来的来源保护。角色按框架已有的 QQ 账号绑定识别，管理员可选填 `desktopHome.administratorQq` 显式关联，未配置时桌面管理员使用自己的本地身份。
- 管理台保存额度设置。每次开房仍由管理员邀请角色或接受来访申请。隔离试聊继续用自己的目录管理模型会话和登录。

## 隔离试聊的主动敲门

来访页默认关闭敲门。选择「欢迎敲门」后，每 30 分钟最多让一位在家角色决定是否来访。「试一次敲门」可以立即开始首次试用。角色可以留下或提交敲门理由。门上显示提醒，你点「请进」后角色才会入场。敲门等待 5 分钟，可以选「下次吧」；「正在忙」和关闭敲门会取消待处理的敲门。敲门决定单独运行，聊天仍使用原来的六回合额度。

这里的「试一次敲门」属于隔离试聊。正式框架由已启用的主人格使用自己的空闲回合决定是否敲门。

## 小鱼主人格试点

在私有试聊资料中设置 `subjectPilot: {}`，由样机启动独立的 QQ Agents Runtime 和小鱼的正常空闲调度。隔离实例使用新记忆库和桌面人设。桌面选择「欢迎敲门」后，正常空闲回合可以使用唯一新增工具「申请来访」。工具没有参数，角色可以照常选择休息。敲门提示在申请的空闲回合结束后显示。管理员请进后加入桌面聊天，仍使用共用六回合额度。切到「正在忙」会清除待处理的敲门，迟到的申请不会重新弹出。

试点默认每小时按空闲调度检查。只有隔离验收配置本机假 OneBot 网关时使用一分钟间隔；样机不会向正式 QQ 连接。假网关的有效真人来信会先取消小鱼的桌面生成，等后端清理结束再启动 QQ 回合，小鱼继续在场，已经启动的桌面回合照常计入额度。

## 启动

使用本机 Apple Silicon 的 Electron 安装。直接启动 `desktop/home` 时进入模拟模式。隔离试聊由本地启动器设置 `DESKTOP_HOME_LIVE_ROOT`、`DESKTOP_HOME_NODE` 和 `DESKTOP_HOME_TRIAL_PROFILE`，分别指向独立的后端数据目录、Node.js 24+ 可执行文件和桌面设置目录。使用与生产不同的目录。

后端目录的私有 `trial-profile.json` 内容如下。Codex 只读取该目录内 `codex/dragon/home/auth.json` 的专用登录，Antigravity 使用此目录下单独建立的 ACP profile。三个原生适配器只向模型开放桌面决定工具。安装路径、实际模型参数和登录凭据留在本机私有目录。

```json
{
  "kind": "desktop-home-p2",
  "roles": [
    {
      "id": "dragon",
      "type": "codex",
      "command": "/path/to/codex",
      "model": "your-codex-model"
    },
    {
      "id": "cat",
      "type": "antigravity",
      "command": "/path/to/agy",
      "model": "your-agi-model"
    }
  ]
}
```

小鱼使用专属 DSH home 中的 `desktop-home-trial` profile。用 `node scripts/dsh-bundle.mjs --desktop --out <bundle> --data <isolated-root> --url http://127.0.0.1:<bridgePort>` 生成守卫和工具桥配置，并按 DSH 本地 bundle 流程安装至这个 profile。宿主只监听回环地址，随桌面模型进程启动和退出。专用登录资料由本机维护者准备。
