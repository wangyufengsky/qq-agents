# 聊天接续材料

普通群聊和私聊在新模型会话开场先接上最近一段历史原文，再明确给出本轮新增消息、处理水位、相关人物/心情/约定与其他来源线索，最后提供运行环境和唤醒背景。已有模型会话只补本轮新增消息，不每轮重复回放。主动意图明确是参考，定时任务说明单列。空闲主体和受保护工作继续使用各自的材料布局。

展示投影不修改原始记录、完整 handoff、已读状态或发送账本。消息保留来源 ID、说话者、时间、正文、引用和 @ 对象；截断或遗漏的消息附 `memory_read` 续读入口。展示不等于处理，只有实际处理过的连续部分才能提交 `qq_mark_read`。

`conversation_read` 用 `nextAfterSeq` 继续分页。`readThroughSeq` 从既有已处理水位开始，取本轮完整展示的连续部分。跳页或截断时按 `readGap` 补读。遇到当前不可展示的真实输入，`readGap.reason=restricted_input` 表示处理水位受限，分页仍可继续。受保护的派生档案与自己的发送记录可在时间线查看，入站处理水位按可信输入计算。开场新增消息、`qq_wait_for_messages`、完整的 `memory_read` 和审阅回执使用同一规则。跨聊天和时间邻文只用于查资料。完整展示不自动提交已读，未提交草稿也不会阻止提交。等待新消息时通常省略 `afterSeq`，工具会从本轮已收到的开场或顺序页面尾端继续等待。需要从较早位置开始等待时，可显式传入 `readThroughSeq` 或更早的序号。分页游标 `nextAfterSeq` 继续用于 `conversation_read`，旧阅读缺口按 `readGap` 补读。

普通回复也可随 `qq_send` 提交可选 `readThroughSeq`，使用当前已实际处理的安全连续水位，减少一次独立的已读工具调用。水位在发送前校验，仅在投递确认 `sent` 且回合仍有效后推进；省略字段保持原行为，已读不回仍使用 `qq_mark_read`。发送期间新到的消息不会自动纳入；`pending`、`unknown`、失败或取消不推进。原创建请求的同参数重复调用只查询状态。带检查点的新请求须用相同水位查询，换水位会返回冲突。检查点随草稿保留，同一回合审阅后继续可应用原意图。新回合或重启后的旧意图只供参考。

合并提交仍要求启用 `qq_mark_read`，不能借发送工具绕过已读工具的关闭；已选主动意图的发送仍使用独立已读工具，避免意图账本重写请求编号后绑定错误检查点。带检查点的成功回执返回 `readCheckpoint.applied`；`false` 表示消息已确认发送，但检查点因暂停、权限、输入版本变化或写入失败尚未应用，不应重新发送。在新回合补写前，先完整读到原水位。新请求按真实投递编号保存冻结的输入版本。本机只可修复原请求已冻结的水位。逻辑导入不会恢复此资格。旧账本只有历史水位而无版本证据时，保留已发送回执并报告 `legacy_unverified`。如需推进，请重新阅读并使用 `qq_mark_read`。

开场不再列最近 20 条成功投递或 `summaryOnly` 序号。未解决的 `pending`/`unknown` 独立列出，不能被更新的成功记录覆盖。`qq_delivery_status` 只读查询当前角色、当前聊天的账本，默认仅查未解决结果，按 `nextOffset` 续查；`unresolvedOnly=false` 可查看其他结果。它不能发送、重试或确认状态，也不能指定其他角色或聊天。已有 `qq_send` 权限的聊天自动获得此只读查询能力。

## 发送前审阅

工具结果会区分补读、等待确认和投递结果。超出安全水位时先看 `readCheckpoint`。新草稿如附 `draftRefs`，可按编号和版本继续处理已有草稿。空 `items` 和 `ready` 同时出现时，当前稿件在等待你选择是否提交。

模型通过工具发送当前聊天的回复时，桥接在准备媒体或排队前检查输入，并在预占投递账本的同一事务中再次检查。首次发送若已完整交付开场输入且版本未变，可以一次完成。开场缺页，或生成、准备媒体、排队期间有新输入时，返回保存的草稿与 `preparation`。只有已进入投递的条目才以网关回执为准。

- `preparation.state=needs_input` 时，`missing` 列出仍需补齐的原文及 `memory_read` 入口。旧消息可能因版本更新需要重新读取。撤回只显示通知和消息号。按 `nextOffset` 续读，遇到 `presentationRestart` 从第 0 页开始读取当前版本。补读完成后调用 `qq_draft.prepare`。有权限限制或未解决投递时，`blocked` 给出阻止继续的原因。
- `preparation.state=ready` 表示所需版本的原文已完整展示，附 `token` 等待主体决定。若本次回执已附齐原文，可直接带令牌调用 `continue`。令牌绑定当前回合、稿件内容及版本、输入快照和已读意图。新来信、撤回、改稿或换回合后重新核对。已经展示的同版本原文通常只需读一次。
- 准备和修订回执使用 `actionResult=not_sent`、`attemptedThisCall=false`，旧已发条目仍在回执中。带令牌继续可能返回 `sent`、`partially_sent`、`pending`、`unknown` 或新的准备状态。部分连发停止时保留已确认回执和未提交余项。重用已认领的令牌只查询其执行结果。
- 私聊和私聊模式群将同一会话的新对方输入纳入审阅。普通群也先审阅不能确定是否相关的消息；确实无关时可在 `inputReview.unrelated` 指定该记录的 `id` 和 `reason`，可从 `excludable` 查找记录 ID。排除只用于这次稿件，变更内容或在下一回合发送时重新判断。表情、未提及角色的补充及同伴消息都可能影响回复；同伴输入继续沿用已有额度规则。
- 当前版本可核对已归档消息、上传通知、对本账号的拍一拍、可信原语音的机器转写及网关撤回通知。转写是机器识别，附件登记也只表示消息中有该附件。网关重复推送同一身份继续去重，同号异文留在观测档案，当前网关协议没有可认证的编辑事件。
- 逐条完整展示、审阅发送和提交处理进度分别记账。发送确认只记录本次实际审阅的输入版本。即时网关回执、可信 QQ 回显与管理员核对送达使用同一份发送前冻结的审阅证据。回执先持久化，审阅登记失败时回执仍显示已送达并返回 `reviewRecorded: false`。开场的 `processingPending` 提示仍需处理的输入。普通 `qq_mark_read({throughSeq})` 只提交已处理。明确决定无需回复时，可把工具返回的 `{id,version}` 放进 `noReply`，每批最多 50 项，且须在提交的安全水位内。同一稿件仍保留原审阅范围，后续独立回合可略过已明确不回复的同版本。修改、撤回和迟到转写仍会重新检查。旧库升级和归档恢复见 [迁移说明](MIGRATION.md)。暂停、权限、限速、同伴额度和既有请求的幂等回执分别生效。

### 私聊模式群的优先引用回复

角色开启 `behavior.focusedGroupReply` 后，私聊模式群的回合会单独给出触发本次唤醒的最新有效来信。角色可通过 `qq_send.replyTo` 引用这条消息并发出文字回复。发送审阅覆盖原消息、后续明确引用原消息的来信和对应转写。该范围内仍须完整读到当前版本。原消息撤回会阻止发送。相关补充新增、撤回或有转写变化时，须查看当前版本或撤回通知后再确认。

其他群消息继续留在待处理队列，可在之后按原有水位顺序补读。一次引用回复只在确认送达后记录实际审阅的版本。已读水位仍须连续，不能借引用回复跨过缺口。直接发言、引用其他消息、媒体、定时任务和主动意图沿用常规审阅。该设置默认关闭，可在管理台「作息 → 唤醒与回复节奏 → 高级设置」按角色开启。

### 待发草稿

`qq_send`、`qq_send_burst`、`qq_send_voice`、`qq_send_file` 为当前聊天持久保存拟发送内容。连发第一条出队前整组已保存，后续每条仍独立核对新输入并预占账本。遇到相关补充、撤回、暂停或取消时，剩余未提交内容留在草稿中。已确认、投递中、明确失败和未知都以各自账本回执为准。

- 同一角色、连接、账号和聊天默认同时保留 4 个开放草稿。有效未提交项、投递中或未知项占用名额。不同创建编号的同文稿件各自保留。上限可在角色行为配置中调整。
- 发送参数中的 `requestId` 用于创建或查询稿件。实际投递编号在回执和草稿条目中查看。修订后用原参数查询会返回 `QQ_DRAFT_SUPERSEDED` 和当前版本。查看该版本的条目可核对真正投递的内容。
- 用 `qq_draft` 的 `list` 找到稿件，再按 `read` 和 `position` 展开原稿。`list` 可加 `includeSettled: true` 查看已结束或已导入的稿件。草稿工具随当前已启用的相应发送能力提供，作用域和来源保护沿用当前聊天。
- 用 `revise` 修改尚未提交的一项，或用 `discard` 放弃未提交的余项，填当前 `expectedVersion`。修订后回执带 `revisionApplied=true`、新稿件版本和该版本的准备状态。旧版本无法覆盖新版本。整稿执行期间修改或放弃会返回 `DRAFT_EXECUTING`，包括尚未提交的尾项。未提交稿件七天后过期，已尝试的账本仍可查询。
- 用 `prepare` 核对当前稿件编号和版本。需要在新回合重新绑定已读水位时，先完整阅读，再在 `prepare` 或 `revise` 明确填写 `readThroughSeq`。修订时指定的水位若无法绑定，新稿仍保存，旧水位会清除。准备就绪后，以同一版本和 `inputReview: {token, decision: "continue"}` 提交。省略令牌的 `continue` 只做准备。重复原发送调用只查询已有状态。重启不触发发送，旧主动意图或定时回合的授权也不会随稿件延续。
- 投递结果未知时，这个角色在同一连接和聊天的新投递会暂停，换请求编号、文字或工具同样受限。用 `qq_delivery_status` 查看回执，由可核对的回传或管理员裁决明确结果后，再决定剩余内容。QQ 已确认的消息只补本地归档，不会重发。
- 图片、语音和文件草稿只保存本角色资料库的引用及发送参数，继续时复核所有权、来源及权限。草稿保存、原文展示和档案恢复都不提交已读。

工具参数无效时，按 `INVALID_TOOL_ARGUMENTS.issues` 的路径、错误类别和期望类型或格式修正。路径包含数组下标，`$` 代表根级。错误不回显参数内容。

批次聚合沿用生效配置，最后阶段以单句、碎片连发和持续快聊的测量结果比较批次参数。

## 笔记与人物卡

新聊天会话继续提供最多 8 条未完成工作笔记，保留完整正文、不确定性、记录时间和笔记 ID，不做二次摘要。共同说明这些是工作解释、记录时间不等于事件发生时间；每条仍带必要的纠正提示，来源缺失时明确警告。开场不重复列出 evidence、sources、conversation 和固定状态字段，完整来源及后续页用 `work_notes` 读取。原始笔记、完整交接对象及保护边界不变。

人物卡提供人物标识、昵称、称呼和完整印象，以及最近 30 天直接来往事实、管理员说明的相处远近（有设置时）、来源撤回注记、纠正提示和管理员编辑标记。开场省去 revision、updatedAt；证据与当前版本用 `person_notes(personIds)` 回查，修改前先读取版本。同一会话在人物首次出现、卡片版本变化、管理员说明变化或来源撤回注记变化时提供一次更新，来往计数变化不会重新展示，新会话重新提供。内部版本去重和回合日志仍保留版本，不影响身份、Self、相处边界或约定的接续。

## 指定群的相处记忆试点

新来信直接对角色说话或留给全群时，程序可以带出说话人的适用称呼与边界。明确 @ 或引用帮助确定参与者。没有明确对象的分工请求，只有近几分钟同群刚发言的其他角色唯一时，才补给该角色的相关边界。同一轮逐条判断对角色或全群说的来信。随后出现的旁人对话照常展示，并保留先前请求相关的相处材料。源自其他聊天的往事和原话留给按需回查。

同群来源的明确引用与相关记录合计最多两条普通候选，必要边界和纠正另列。每次从当前版本和来源生成提示，撤回或受纠正的判断标记为需要核对。草稿准备后若这些材料发生变化，回执会附上当前材料并要求重新确认。第一版自动带入的称呼和边界要求可核对的本群来源。历史材料独立于新来信的展示凭据、已读处理和发送授权。

## 连续原文窗口

历史窗口独立从本聊天的已处理水位向前选择，最多检查最近 40 条聊天消息。新消息更新最近来源列表时不会挤掉它。入选消息保留完整 body，不逐条截取相同字数；遇到超长消息或读取边界就停止向前延伸，明确给出缺口和续读入口，不把分隔很远的记录拼成连续对话。

整个历史包（包括元数据）最多 12000 字符，其中连续尾巴最多占 8500，随后为明确引用和起始条件留出空间。每次最多自动补齐 4 个引用，复用连接、会话及消息命名空间校验；有歧义、无权限或找不到原文时明确说明。其余引用或超预算内容给出按需续读入口。

最早几条消息不与尾巴拼成一串。不在尾巴或明确引用里的起始来源，作为单独的 earlier 线索保留。本轮交接中的未完成笔记仍引用该来源时，在预算内展开原文；其余只保留来源 ID、时间、纠正提示和 `memory_read` 入口，不自动带入旧正文，也不按日期删除。继续旧任务却缺少最初条件时，先按入口回查。已完成的笔记不再触发起始来源展开，当前消息的明确引用仍可展开旧原文。所有入口和原文都先通过相同的读取边界检查；原来的来源保留结构继续用于归档和空闲材料。

本轮新消息也优先给全文，仍限制 30 条和 12000 字符。预算容不下单条时附明确的 memory_read 分页入口；仍有待展示消息时给出 conversation_read 游标。检索和普通工具读取的默认摘要行为保持原有约定。

开场输入和工具结果在后端交付时登记展示证据，证据仅覆盖桥接能够确认最终完整交付的内容。已知截断必须补页。OpenAI 兼容后端的同批工具互相不可使用尚未交付的读取结果。历史、引用和起始线索只做读取边界检查与保密来源追踪，不调用 seen/observeInput；因此不会推进水位、恢复回复额度或变成新的用户授权。新消息只有实际展示了完整原文才通过已有的可信输入校验。原始事件、Self、日记和发送账本不迁移、不删除。

回归覆盖大量新消息到来、长消息尾部、预算与分页、明确引用/歧义/跨群同号、无笔记任务条件、保护边界和旧消息不增加授权；同时保留会话退休、语音转写、主体素材和发送去重检查。

## 新消息图片预览

开启角色 `behavior.imageInput.enabled` 后，支持的后端会收到新消息文字及对应预览像素。每个画面标注来源经历 ID 和图片序号；入库原文仍保留“尚未识别内容”的占位，不能凭历史占位宣称看过画面。实际附图及未附图状态以本轮附件为准。

自动附图不推进已读水位、不增加发送额度。单独保存图片输入已提交水位，避免历史回放、会话交接或生成错误续接重复输入旧图；提交前失败可以在下一次正常唤醒时重新准备，提交后不自动重放。原图保留在既有媒体缓存，需要细读或回看时继续走受控图片工具。限制与开启方式见 [配置说明](CONFIGURATION.md#新消息自动看图behaviorimageinput)。
