# 消息链路时序观测

时序观测用于区分聚合、调度限制、模型处理和投递。它默认关闭。运行时继续使用原有批次配置、调度与发送规则，采样不会增加回复权限或发送消息。

## 采集和导出

通过启动进程的环境变量 `QQ_AGENTS_MESSAGE_TIMING=1` 启用。受管启动和本地启停脚本沿用启动进程的环境。每次启动独立采集，恢复默认关闭时移除该变量。先按当前部署的[本机运维](LOCAL-OPERATIONS.md)核对启动入口、实际数据目录、端口和暂停要求。

使用现有管理员凭据从本机访问 `GET /api/diagnostics/message-timing`。例如在 shell 中设置 `QQ_DATA_DIR` 和 `QQ_ADMIN_PORT` 为当前部署的数据目录及管理端口，然后执行：

```sh
umask 077
{
  printf 'x-admin-token: '
  cat "$QQ_DATA_DIR/admin-token"
  printf '\n'
} | curl --fail --silent --show-error --header @- \
  "http://127.0.0.1:$QQ_ADMIN_PORT/api/diagnostics/message-timing" > timing-snapshot.json
node scripts/message-timing.mjs --analyze timing-snapshot.json --out timing-summary.json
```

接口沿用管理台的 Host、Origin 和凭据校验，返回 `Cache-Control: no-store`。快照只包含相对毫秒、进程内临时样本序号、群聊或私聊类别、批次参数、固定阶段和状态。它不保存正文、草稿、角色或 QQ 标识、请求号、绝对时刻及供应商错误。采集只用进程内存，不写日志、记忆库或常规备份。默认最多 512 个完成或在途样本，完成后保留最多 30 分钟，长期在途样本也会过期。导出时在途样本只计数。容量拒绝、淘汰、过期和逐样本省略量单列，分析分母是快照实际保留的完成样本。

## 读懂计时

- 入站起点是本机 Runtime 收到并最终参与该批次的事件。首条和末条只对应本批次请求或延展。未参与聚合的聊天、网关重复推送和在已派发回合中由读取工具见到的后到消息不改写该批次首尾。开始采集时已经在等候的批次可缺少首条和聚合起点。
- `batchStarted` 和 `batchReady` 分别是聚合开始及按实际滑动窗口算出的就绪时刻。派发发生在调度器真正交给回合时。忙碌、作息、冷却或限速可以让实际派发更晚。聚合上限只约束窗口。末条事件若在计划就绪之后才加入队列，末条到就绪计为缺测。
- 忙碌时长来自已有同会话回合的占用和释放。冷却、唤醒限速、作息只记录调度器实际观测到的限制及其有效截止；被更早检查遮蔽的部分留在无法归因时间。墙钟的调度截止转成本进程单调时钟的相对时间。
- 处理开始是回合占用会话。模型输入提交与第一次发送工具请求之间的时长是生成前后路径的可观测区间，可能包含工具交互和适配器开销。只有后端实际报告输入提交时才有该测点。本回合首次新建或修订草稿在保存事务提交后独立打点。仅查看旧草稿或继续发送旧版本可以缺少该测点。草稿工具只有显式继续发送算发送请求。
- 投递分别记录请求进入投递服务、等候前一项同会话投递、进入和离开连接队列、账本预占、调用网关适配器、收到有效网关回执及账本确认。媒体准备和连发模拟间隔单独记录。幂等回执、未确认和明确失败不会产生新的账本确认样本。网关或账本的确认不代表对方已在 QQ 界面阅读。快照记录当次调用的结果，后续 QQ 回传或管理员核对只更新账本。已完成的计时样本不会回填，`unknown` 表示当时未能确认。
- 分布给出有效数 `n`、缺失数 `missing` 和按最近秩计算的 p50/p90。样本少时，p90 可能由一两个观察值决定。各原因的已知区间可以交叠。首条到首次账本确认的独占、交叠和无法归因三部分按实际经过时间只计一次。直接把各原因的分位数相加会重复计算。正常完成且无发送的真实回合记为 `completed-no-send`。主动沉默只在有明确行为依据的合成夹具中单列。暂停、连接中断或后端正忙时，调度可以继续保留未派发的批次；若直到导出或过期都未派发，只计入在途或过期。发送阻止分类只覆盖实际走到的工具或投递检查。连发可以既有已确认的前缀，也因复核或其他限制中止，汇总保留两项结果。

## 复现隔离试验

从源码检出目录安装锁定的依赖后运行：

```sh
node scripts/message-timing.mjs --synthetic \
  --baseline-root /path/to/baseline-worktree --samples 100 --seed 874137 \
  --out paired-timing.json
```

`--repo-root` 可指定另一个已安装依赖的可信源码检出目录，省略时用脚本所在的检出。旧版目录仅用于运行相同夹具。报告分别给出目标源码和基准脚本的提交及修改状态，并给出基准脚本和统计模块的内容摘要。试验使用内存 SQLite、临时配置、假的模型和 QQ 网关，驱动真实入站、调度、回合、工具和投递代码。每格用相同的种子、到达序列、每秒调度相位、模拟模型和网关延迟，审阅重试也使用确定的模拟处理时间。虚拟时间用于比较链路行为，不能反映真实 CPU、服务商生成或 QQ 网络耗时。

三类到达序列分别为单条、四条分段和持续快聊。先比较旧版与新版的 4 秒窗口/12 秒上限，再只改窗口到 2 秒/12 秒，最后只改上限到 2 秒/15 秒。候选只写入试验临时配置。试验分开统计首次确认、覆盖末条的确认和全部输入覆盖后的确认，并同时记录过时提交、每次提交漏掉的输入、截止时仍未覆盖的输入、重复回复和删失。末条已覆盖不代表中间内容已全部处理。若假模型只看到了已答内容而实际还有未覆盖输入，按展示缺口计数。

合成数据只验证此固定脚本下的响应路径和安全回归。真实 QQ、真实模型效果和参数推广仍需要单独验收。
