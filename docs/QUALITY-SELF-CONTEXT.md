# Self、上下文与主体意图验收 · 2026-10-25

实现基线为 main `b60fee1`，保留已合并的外部工具与文件传输能力。本文记录本地验收事实；合并和远程提交以关联 PR 的实际状态为准。合并不部署，生产两角色继续全局暂停且各自暂停；未迁移生产数据库、原人格、登录或 Docker 数据。

## 实现与工程选择

正式规则见 [实施规格](PROMPT-CONTEXT-DISCUSSION.md)，默认值与迁移行为见 [SELF-CONTEXT.md](SELF-CONTEXT.md)。当前实现包括版本化 self、独立候选与延后主体回顾、来源去重、每轮 self 版本记录、增量消息、统一上下文整理/退休、单主体机会与聊天意图、管理台、schema 4 导出恢复。

名字和外形固定在身份配置。旧自由文本模板没有独立外形时，正式 self 替换会被阻止，直到管理员确认原有外形或明确无固定外形，避免猜测式迁移。self、名字、外形或稳定协议变化时，下轮安全重建；当前实现不使用尚未行为确认的原地替换。无变化时继续复用，空闲同步不调用模型。

75% 含输出预留开始整理；回落 60%、保护线 90%、压缩冷却 5 分钟、压力后空闲 45 分钟，均有明确配置边界。无压力不每天重开。主体与普通聊天共用管理框架，主体需要退休时以检查结束为安全点。调用预算与对外联系预算分别保存，普通聊天不被主体检查串行阻塞。

## 本地验证与复审

`npm run verify` 包括语法、完整测试、格式及隐私扫描。最终代码的 227 项测试通过。新增测试覆盖版本冲突、跨聊天隔离、延后回顾、重复来源与日记循环、旧处理水位迁移、非连续读取、暂停/撤权、主体预算、未知回执、重启/并发、锚点变更、工作笔记来源、schema 4 导出恢复和后端协议。

按 code-review 流程分别进行规格和工程标准两路只读审查。修复并回归了：

1. 旧已处理水位缺少 message_progress 时无法继续标读。
2. 主体来信机会未提供给模型且检查失败后丢失。现在原始事件游标按成功批次前移，失败不确认，溢出不丢弃。
3. 受限 Operations 内容经新候选/笔记/意图消除限制。现在只对已有受限运维边界拒绝共享心智写入；普通跨聊回忆不增加逐次 QQ 授权。
4. 活动角色被删除后清理异常、运行槽不释放。
5. 旧模板外形在 self 替换后消失，以及仅修改锚点时旧会话不刷新。
6. 主体初始化缺少目标聊天的近期联系结果，调度任务使用错误归属字段。
7. 发送回执与预算/冷却之间的崩溃窗口。现在网络前在同一事务预留 outbox、预算和冷却；回执和意图同事务；重启从账本幂等恢复，未知联系尝试仍占预算。
8. 旧已完成联系在重启时清掉新的普通回复检查。只在恢复后的主动冷却仍有效时清除该检查。

审查使用临时数据库和模拟传输复现边界。模拟测试没有被当成真实后端行为证据。

## 两后端真实多轮

后端：本机独立 DSH profile，DeepSeek Flash / high；专用 Codex home，gpt-6-astra / high。QQ 接收端全部为本机 HTTP/WS 网关。所有人物、种子、事件和标识均为合成资料，没有向真实 QQ 发送。

每个后端跑五个实际模型回合：普通聊天读取原始资料并提出候选、主体另一个回合回顾并形成意图、目标聊天自主决定并发送一次、忙碌来信后取消且不发送、原生压缩及安全重建后回答原始编号和未知结果。候选回顾延迟在测试中设为 0，但仍是独立后续回合；生产默认延迟由离线时间测试覆盖。

人工阅读的最终回答均正确保留“蔚蓝-47”，并明确发芽结果未得到更新；DSH 还说明自己没有实际看到种子。没有将群友话语、日记推测或一次工具返回当作已经观察到的发芽结果。目标问候使用自身表达，没有照抄一个程序生成的固定话术。

在最终 outbox 事务实现上，又各运行一次实际目标聊天发言，核对单次回环网关回执、意图 completed、contactChargedAt、主体计数和目标冷却。此验证不取代崩溃注入测试；两种证据分别覆盖网络成功路径和事务恢复窗口。

## 复用与每次短会话的有界对比

每后端另做四个无新增事项的主体检查：同样说明下复用两次，对比各自新建两次。共八个模型回合，零次 QQ 投递，self 均保持 v2。原始样本保存初始化/复用标记、提示字符数、用量来源、当前占用、延迟及版本。

| 指标                      | DSH 复用两次         | DSH 每次新建         | Codex 复用两次 | Codex 每次新建     |
| ------------------------- | -------------------- | -------------------- | -------------- | ------------------ |
| 总延迟                    | 13.1 秒              | 13.7 秒              | 30.8 秒        | 29.5 秒            |
| 第二次增量提示字符数      | 315                  | 1,790 + 711 稳定层   | 315            | 1,755 + 883 稳定层 |
| 第二次请求占用 tokens     | 26,734               | 24,647               | 12,597         | 11,902             |
| Codex 会话累计 token 报告 | 不提供同口径账单数据 | 不提供同口径账单数据 | 72,458         | 两会话合计 70,361  |

复用明显减少桥接重复追加的初始化文本，但旧上下文仍参与后续请求，工具 schema 也占空间。该小样本没有支持“复用必然更省钱/更快”，因此采用无压力继续复用、有压力整理的策略。当前占用、累计 token、缓存计费和货币费用不同；没有按占用数字伪造账单或费用估算。

本次实现阶段共执行 32 个桥接模型回合（DSH 17、Codex 15），包括早期失败样本；另外完成 3 次实际原生压缩（DSH 1、Codex 2），以及不产生摘要的能力探测。最终阶段为每后端 5 个完整链路回合、4 个对比回合、1 个最终回执回合；最终回执耗时分别 19.7 / 28.9 秒。没有无限自动重试或真实 QQ 投递。

## 失败与限制

- 早期 DSH 测试 preset 没有注册 compact 命令，返回未识别。随后实际核对安装包服务隔离规则，修正生成器，在新测试 profile 验证原生命令和摘要事件；普通 session/prompt 的 `/compact` 文本不算压缩。
- 重用旧验收数据的一轮 DSH 检查没有再次采纳相似候选，用例因此失败；保留该记录。最终完整验收使用全新的合成数据库，未通过反复强令模型采纳来覆盖失败。
- 最终 DSH 五回合中出现 6 次来源 ID 参数错误，均由程序拒绝，模型随后纠正；Codex 最终该链路的工具调用全部成功。这说明来源校验生效，也说明模型参数可靠性仍有限。
- DSH 把动态 self 放在初始用户包，原生摘要不保证保留其完整约束，所以实际压缩后受控退休，下次再加载当前 self。Codex 稳定层使用 baseInstructions；压缩完成并不保证每种模型都会按预期遵循全部设定。
- DSH 的静态 MCP 目录可能显示普通聊天工具，但实际执行必须通过当前主体能力白名单。未批准工具在程序端拒绝，不能仅用提示约束替代权限。
- 这些是小规模合成场景，没有覆盖长期自然人格发展、所有操纵话术、真实繁忙群环境、生产模型限流、Windows/Linux 或真实 QQ 出站。未接入新的 App、ASR 或常驻图像服务。

## UI 与证据留存

在禁用模型/QQ 的独立本机实例实际操作：编辑 self 成 v2、恢复旧版形成 v3、取消意图、手动退休。重启服务后浏览器和 SQLite 均保留 v3/已取消/已退休；截图单独保存在本机交付目录。身份锚点、候选、历史差异、来源、预算范围、状态及用量来源均可查看。

原始合成模型答复、工具状态、用量、压缩结果、成本样本、最终回执、测试日志和 UI 截图留在本机交付目录，不提交运行数据库、认证 home、令牌或聊天记录。生产暂停状态仅只读核对；未启动 GitHub Actions，仓库没有新增 workflow。
