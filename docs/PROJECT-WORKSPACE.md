# 项目、共同活动与作品

个人项目记录角色自己持续推进的事情；共同活动记录角色与明确参与者一起推进的事情。文件是作品或参考资料，文件的存在或管理员阅读不等于共同参与。

## 第一轮：在线阅读与关联

文件页点击文本文件名即可阅读 Markdown、TXT、JSON、CSV 等 UTF-8 文本。Markdown 支持标题、列表、表格、代码和链接；原始 HTML 作为文字展示，外部图片不加载。可切换原文、复制本页、下载全文、分页及全文关键词查找（最多返回 100 个匹配位置）。分页位置按字符计，不割裂表情字符；跨页段落可能分开显示。

管理员读取由管理令牌鉴权，按角色取文件并验证内容摘要。页面查看不改变模型的已读状态，不写文件，不触发角色回合或 QQ 发送。文件已存在但类型不支持或编码损坏时，预览明确报错，下载仍保留。

文档阅读面板列出所属项目；项目可以直接打开关联作品。关联来自保存的文件引用，不按文件名猜测版本关系。文件内容保持唯一，两个入口使用同一阅读器。

## 第二轮：独立的项目与活动页

选择角色后进入「项目与活动」，按个人项目/共同活动、状态和标题筛选，每页显示 20 个项目。空闲时间页保留运行日志与调度设置，作品与项目放在此处。

个人项目可直接读最近关联的文本作品，查看文件列表及最近 30 步进展。“最近关联”按项目记录排列，不表示凭文件名推断出的最新版。文件阅读器的所属项目链接直接回到这里；读取使用文件库的同一份原文。

共同活动显示参与者、轮到谁、待定问题、当前原稿、每次修订和真实贡献。原稿按字素边界分页，历史每页 10 条；选择旧修订会读取该修订实际使用的草稿，包括沿用的旧稿，作者也跟随原稿。

两份关联文本文件或两次活动草稿可以比较。文件比较每份上限 2 MiB；比较整份正文后省略相同前后部分，不把页面预览当成全文。变化区段每侧最多显示 16000 字符，过长时明确提示继续读原文。这是连续变化区段比较，不是逐行最小差异。比较正文不包含标题变化。

列表、阅读、历史和比较均为只读，不增加模型已读或 QQ 回复额度，不触发角色回合；文件、项目与历史按角色隔离。数据格式保持兼容。

## 第三轮：管理员共同参与

打开项目后，点击「加入并转为共同活动」才会把个人项目变成共同活动。可明确选择一个已关联文本文件作为初始共写原稿；文件原件保持不变，初稿记录来源文件，之后原稿的修订保存在同一项目的版本历史中。未选择文件也可以加入，再共同写稿。导入的正文最多 32000 字符，不允许受保护、保护状态未知或不属于该项目的文件。

已有 QQ 共同活动可点「加入活动」增加管理员参与者，保留原来的聊天和其他参与者。管理员身份独立于 QQ 号；打开、下载或比较文档都不会自动加入。

加入后可提交建议、回应具体待定问题，以及打开当前原稿全文后保存新修订。建议保留原始文字，管理员修改标为管理员编写，角色续稿标为角色编写，来源文件导入标为来源文件；每次操作都有独立修订，旧稿不覆盖。若角色已保存新修订，旧页面提交会被拒绝，输入留在页面供复制和重新核对。同页另一表单还有未提交内容时，成功保存不会整页刷新；提交期间暂时禁用输入，避免把后输入的文字误当作已保存。重试同一提交不重复写历史。

QQ 活动正在等另一位参与者时，管理员可留下建议，但不能替其回应或改稿。管理台创建的活动在角色空闲主体继续；角色只有完整读到尚未处理的管理员文字贡献及其改稿、读完当前原稿后，才能续写。贡献较多时可用 project 的 administratorRead 分批确认已读记录并保存摘要，跨正常回合继续；确认不修改原稿、选项或轮次；未处理完的摘要独立保留，不随最近 30 步进度滚出，后续回合先读当前项目及摘要再推进。一次最多保留 20 条尚未处理完的管理台贡献（含已读待处理），达到上限需等待其处理后再提交。

提交不主动触发模型、不解除暂停、不发送 QQ，也不赋予模型新的回复或发送额度。角色会在之后正常的聊天或空闲回合查看活动；空闲时间未启用或角色暂停时，不会为处理这份贡献强行运行。

活动和原稿保存在已有的 `projects` 与 `activity_history` 数据中，导出恢复包含管理员身份、来源、历史和未处理贡献。没有数据库迁移或配置默认值变化；旧程序不具备管理台活动的推进规则。个人项目原来的文件和进展保持真实归属，加入不把它们改写为管理员作品。
