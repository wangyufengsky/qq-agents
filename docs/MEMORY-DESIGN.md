# 场景记忆与自主表达

本次调整依据管理员明确要求：角色可以自行判断如何在群聊、私聊之间运用自己的回忆及日记，不逐次申请发言授权。主体隔离、来源信息、发送白名单、暂停、限频和幂等继续生效。跨聊天回忆是同一角色读取自己的经历，不共享其他角色的记忆，也不解除受保护工作的读取边界。

## 来源、片段和话题分别表示

- **来源**是稳定的 `agentId + connectionId + conversation`。`conversation` 明确为群聊或私聊及其 ID；群名仅来自已观察消息，带观察时间。缺失时返回空名称，以 ID 展示，不用当前群名冒充当时名称。
- **场景片段**是围绕命中消息的有限原始记录。默认前后各 2 条、相对命中时间不超过 10 分钟，可扩大至各 5 条、最多 1 小时。旧记录没有可靠时间时不自动拼接邻居。
- **话题／因果关系**不由相邻位置推断。明确引用才建立回复边；普通相邻消息仅标记为时间邻居。同一结果页的重叠邻居只返回一次正文，其他片段用 `sharedRecords` 指向已经返回的记录；命中锚点仍各自保留。不同页沿用稳定记录 ID，不跨页伪合并。

## 从私聊回忆群聊

`memory_search` 不填写 `conversation` 时检索当前角色自己的跨会话记录，默认按最新记录优先返回；当前处于私聊不代表搜索只能看到私聊。

- 搜所有群聊事件：`{"query":"游戏","conversationType":"group"}`；搜私聊事件用 `conversationType:"private"`。
- 读取已知来源：`conversation:"group:20000"` 或 `conversation:"private:30000"`，可以同时保留类型筛选，但两者必须一致。
- `conversation:"group"`、`"private"` 和对应通配写法不是具体来源键，返回 `INVALID_MEMORY_SCOPE` 和修正提示，不再静默返回空页。
- 来源筛选针对事件；独立日记仍使用不带来源筛选的 `type:"diary"` 查询，不将日记写作场景等同于叙述来源。

结果的 `scope` 说明查询范围，`hasMore` 表示还有后续匹配记录，`continueWith` 给出保留查询条件的下一次 `memory_search` 调用。旧的 `nextCursor`、`nextOffset` 和 `nextDiaryOffset` 保持兼容。第一页可能全是最近私聊，不能由此断定没有群聊记忆；空结果只对应当前过滤条件。历史原文较长时先按游标续查，再按记录 ID 展开。

`conversation_read` 省略来源时只读取当前聊天；它不负责发现其他群聊。跨聊天检索结果仍经过既有角色隔离及受保护来源检查，历史回查不会推进群聊已读水位或增加回复授权。配置、权限、原始记录、Self、日记和发送账本不迁移或改写。工具 schema 更新后，相关原生会话可能按已有工具契约交接重建，使新参数可用；这不清空持久记忆。

## 别处近况

普通聊天回合在人物卡之后，为本轮发言人、私聊对方、被 @ 或引用的人展示“别处近况”：同一角色最近在其他群聊或私聊里与此人直接来往的索引。群到群同样包括；只是同群旁观、不指向角色的发言不计入。默认窗口 6 小时，可在 [`behavior.elsewhere`](CONFIGURATION.md#别处近况behaviorelsewhere) 调整或关闭。

索引只含来源、最近时间、窗口内条数、谁先开口、最后是谁发言和最后记录的 `memory_read` 回查入口，不附原文或程序生成的摘要。私聊来源进入群聊提示时标记 `fromPrivate: true`，提醒角色不要主动在群里提起私聊内容，除非对方先提；群聊来源如何表达由角色结合现场判断。

只统计角色亲自参与的直接来往：收到消息须已在原会话处理，发出消息须由投递账本确认 `sent`；身份别名和同一请求去重，受保护运维、私有仓库和工作会话记录排除。每人最多 2 个来源，每轮最多 6 条，超出的来源以 `more` 计数。同一模型会话只在别处有更新时再展示，新会话重新展示；实际展示索引记录在 `model_turns`，管理台暂不增加专门界面。

这是回合内展示信息，不写入稳定提示、不替代主动搜索，也不构成新授权；不推进任何会话已读水位，不增加回复额度。会话状态的 `elsewhereShown` 缺省为空，无需数据表或导出格式迁移，开关或窗口变化不使模型会话退休。

## 一次搜索的结果

命中事件保留原 ID、角色所属、连接、会话、人物、时间、原文摘要、是否截断和来源。消息类命中额外返回 `scene`：

1. 来源标识与名称观察时间。
2. 命中锚点和范围设置。
3. 按已归档顺序排列的消息，标记命中项、发言人当时名字、时间、引用和 @。
4. 当前返回片段的参与者及出现次数；不是群成员名单，也不包括只有 @、没有发言的人。另取的引用原文作者不冒充这段时间的参与者。
5. 有界的引用原文和缺失引用提示；只关联同一角色、同一连接、同一会话中的已观察消息，不为补上下文拉取其他聊天。
6. 截断标志与 `conversation_read(aroundId=命中ID)` 的继续读取入口。摘要不是全文，需要时用 `memory_read`。

关键词、人物、来源、时间等条件用于选中锚点；上下文不继续套用关键词和人物条件，因此 A 说 xxx、B 回 yyy 会一起显示。相邻消息不得跨角色、连接或会话，也不得跨很长的时间间隔。转发内部节点不是本群现场发言，不能用它们推导现场参与者。

片段与命中摘要共同计入搜索预算，不能为了附带上下文无限增大结果。预算不足先收缩片段，再退为仅含记录定位信息的结果，并明确提示展开。分页游标按实际返回的命中推进，不把上下文算成新命中；历史原文不删除。

## 日记的来源

程序记录作者身份、创建/修订时间及 `metadata.writtenIn` 的连接和群/私聊标识，模型不能伪造这几个来源字段。修订保留原写作场景和历史版本。旧日记没有写作场景时不补猜。

写作场景只说明“在哪里写下”，不说明“所写事情在哪里发生”；写入时间也不代表所述事件发生时间。日记对消息的证据引用另存 `evidence`，只允许指向该主体自己的真实记录 ID。没有证据时不能自行补出人物关系、因果或先后顺序。

## 发言策略

回忆及个人日记的来源提示继续进入模型上下文。模型自行判断当前对象、场合、保密约定和表达范围，可以在私聊中提及群聊回忆，也可以适当地使用自己的其他会话回忆。服务端不再因读过这些资料锁住 QQ 文字、图片、语音或转发发送，旧会话中保存的回忆标记也不会继续锁住发言。

这不改变本地文件、命令执行和向外部服务提交资料的独立权限。文件内容仍受原运维授权约束，含这类上下文时写入的日记保留受限来源标记，不能通过改写日记解除限制；把已读跨会话资料交给外部服务的检查保留。管理台仅在这些受限动作实际请求授权时显示申请，不再把普通回忆列为待批准的发言。

## 明确不声称完成的能力

- 来源标识与引用不能保证模型每次叙述准确；真实测试曾出现 DSH 对日记补叙，已强化提示，仍需更广泛的复杂对话质量评估。
- 不自动识别群内并行话题，不把时间邻居标成明确答复。
- 不猜测缺失的群名、历史昵称、已过期引用或断线期间未收到的内容。
- 不把“某人说了某话”认定为已核实事实；日记仍是主体自己的笔记。
- 不引入向量库或自动改写人格；原始档案、日记修订和主体隔离保留。

## 跨时间关系与稳定读取

`memory_related(id, afterSeq, limit, maxChars)` 按同主体、连接、会话索引查找明确 reply 和撤回通知。它可找到数天后引用最初提议的发言，并继续沿回复 ID 读取确认或撤回。每条边保留 `fromId`、`toMessageId`、可用时的 `toId` 及关系类型。缺失原文返回 unavailable；没有边也不说明后续不存在。更正、同意、因果和实际履约依然需要结合原文判断。服务端不根据关键词给消息贴话题或事实标签。

关系按源记录分组分页，返回预算不足时给原文读取入口。管理台新增“跨时间引用 / 撤回”，可直接打开两端原文。普通 `conversation_read` 仍按归档顺序读取，不假装完整话题；`markReadEligible=false` 的跨会话结果不能用于当前会话的已读水位。

`memory_search` 事件排序为归档 seq 倒序，首轮 cursor 固定 eventCeiling，后续以 beforeSeq 续读，期间新消息不会移动旧页。旧 offset 参数继续兼容，但 offset 方式本身不提供并发插入稳定性。日记使用更新时间和 ID 续读，排除首轮之后新建的日记；修订是实时视图，不是跨多次调用的数据库快照，途中修订可能改变排序，完整审计应按日记 ID/版本读取。

schema 3 保留 schema 2 引入的 FTS5 trigram，只缩小至少三个 Unicode 字符的候选范围，再逐项做原始转义 LIKE 校验；多个词仍取交集，不改变字面匹配语义。一、二字查询保留扫描与人物/来源/时间索引，未引入向量或外部检索。明确引用索引包含角色已确认回复，未确认或失败的尝试不作为回复证据。详细性能、原始资料与派生索引空间成本见 [QUALITY-0.4.md](history/QUALITY-0.4.md)。

日记返回显式 epistemic 说明，证据引用也不能证明其每句话。真实 DSH/Codex 的六维合成质量评估及观察到的失败保留在验收记录中；一次通过不等于消除幻觉。

## 时间邻文与账本分页

`memory_search` 的命中锚点继续按账本 seq 分页，关键词/人物只筛选锚点；场景邻文使用可靠发生时间，同一时间按存档顺序（seq）排列。QQ 时间只精确到秒，同一秒内的连发消息因此保持到达顺序。新增历史、时间富化及恢复后无需重排账本。结果 `timeBasis` 区分 message、observation、unknown；观察时间和未知时间只提供锚点及可取得的明确引用，不能冒充同一时刻的对话。

`conversation_read({aroundId,contextSeconds})` 使用同一时间索引，默认前后 10 分钟，最多扩至一小时。结果按时间和存档顺序排列；使用 `nextAroundBefore` 或 `nextAroundAfter` 作为 `aroundCursor`，保持相同 aroundId/contextSeconds。游标包含来源和锚点时间校验、首批账本上界；锚点时间更正使旧游标失效。其他记录富化是实时可见的，发生更正后重新检索，不宣称跨页快照隔离。页数、字符预算限制下仍返回可继续的游标；游标里的 seq 只用于同时间续页，不能当作已读水位。导出按 seq 升序，恢复时（包括恢复到已有其他主体的库）按导出顺序重新分配 seq，所以同一会话内相同时间的消息恢复后顺序不变。

时间展开的 markReadEligible=false、readThroughSeq=null，与普通 conversation/afterSeq 的账本游标分开。工具仍只记录真正展示的消息，零散读取不能越过未见缺口。前后文不是同一话题或因果关系；远距离明确回复/撤回使用 memory_related，长原文继续使用 memory_read。
