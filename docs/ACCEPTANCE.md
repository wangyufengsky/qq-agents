## 0.2.3：已发送嵌套转发的 API 回读

对上节 0.2.2 留下的限制继续排查，当时观察到本机 NapCat.Onebot 4.18.38 的原生运行环境没有初始化协议 `PacketApi`。**0.2.4 进一步确认具体原因为账号配置禁用了 PacketBackend，而非该原生版本普遍不支持；临时启用后的真实验证见下节。**资源 ID 进入后备解析时，日志报 `Cannot read properties of undefined (reading 'operation')`；按已发送消息 ID 查询则返回 JSON 卡片，原生实现只接受 forward 段，因此失败。此行为与[官方 GetForwardMsg 实现](https://github.com/NapNeko/NapCatQQ/blob/3420f0b76d7dc0ac92cde1663f21ea27f61e13bb/packages/napcat-onebot/action/go-cqhttp/GetForwardMsg.ts)和[消息解析实现](https://github.com/NapNeko/NapCatQQ/blob/3420f0b76d7dc0ac92cde1663f21ea27f61e13bb/packages/napcat-onebot/api/msg.ts)相符。

修复在统一桥接内完成：发送前保存源消息段快照；成功回执关联 `message.sent`；发送工具返回可直接读取的 `eventId`。对于已确认发送的卡片，若原生资源 API 拒绝，则使用该次发送的已观察来源作为外层，再通过已有网关/内嵌资源逐层展开。0.2.2 的旧发送可利用原已持久化的源事件恢复。每个节点返回 `source`，网关失败写入 `warnings`，不把本地来源记录标成网络下载成功。

独立环境复制上次验收数据库，清空副本中的转发缓存，启动仅监听本机的实际 HTTP 服务，通过 `/agent/tools` 调用 `qq_forward_read`，连接真实网关只读拉取已观察资源。未启动模型、定时器或入站唤醒处理，网络封装拒绝所有发送动作。

批次 `1025-B`。用户先回复“前五项全部正常”，随后明确回复“已看到，拍一拍正常”，六项客户端验收全部通过。五类内容共六条消息，包含一张构造嵌套所需的内层准备卡；后来另成功发送一次拍一拍。最终账本为七条 sent、一条 failed，没有 unknown；没有重复发送前五项内容。测试进程未观察到匹配的 WS poke 通知，拍一拍展示结论依据用户实际客户端确认；不补记未观察到的通知事件。

**嵌套来源修复：** 原先只对根卡片恢复已确认发送快照；如果内层本身也是自己先前发送的 QQ JSON 卡片，网关又无法读取它，遍历会停在内层。现在沿实际发送的源卡片逐层验证成功回执、同一角色/连接、出站方向和快照内容，建立内层来源对应关系，并保留分页续读所需的信息。中间层能从网关获取、下一层不能获取的混合情况也通过回归。变化、跨连接、入站或未确认来源不能获得后备读取权限。

通过真实本机 HTTP `/agent/tools` 回读本批次外层：`complete=true`，两层、三节点，包含内层松林；两层均明确标记已确认发送来源及原生读取失败警告。该验证封装拒绝所有发送，未用再次投递掩盖读取错误。

**PacketBackend 配置对照验证：** `nc_get_packet_status` 和账号配置均表明原值为 `disable`。只将 Codex 网关该字段临时改为 `auto`，通过原入口的 PID/进程组/启动时间/账号/工作目录校验后重启该网关；DSH 网关及两个 AI 桥接保持原状。Packet 就绪后，独立测试工具只发送一次拍一拍，网关确认成功；直接读取刚才的外层转发资源也返回 `ok`、两条顶层消息。测试最后按字节恢复配置，SHA-256 一致，再次启动 Codex QQ，并核对两只机器人暂停、两个 QQ 在线。没有把临时配置留作生产启用。

错误处理同时改进：网关拒绝中只保留 `PACKET_BACKEND_DISABLED` 或 `PACKET_BACKEND_UNAVAILABLE` 这类受控原因，向调用方返回明确失败原因并存入账本；不把网关完整堆栈、路径或凭据泄漏给模型。原失败请求保持幂等，不能自动重发。

## 验收中发现并修复

1. DSH 将未说明用途的 `context` 参数写成操作说明。MCP schema 现在明确要求复制当前回合的能力凭据，并保留凭据校验；真实首回合恢复。
2. DSH 的 forget 只取消重连意图，没有关闭旧逻辑流，复用会话无法取得新快照。现在取消对应流、清除关联，并防止迟到 end 干扰新流；实际睡眠唤醒与连续回合通过。
3. 原生 QQ 语音返回本机路径，旧实现误当 URL。现在优先通过已观察文件的 `get_record` 取得 WAV 字节；明确配置的 `voice.localRoots` 才允许本机后备读取，拒绝越界和符号链接逃逸。
4. 调度工具只暴露任意 JSON，模型无法确定 daily 的 `times` 等字段。现在提供 12 类 AI 可用规则的结构、范围和说明，cron 继续仅管理台可用；数组 schema 已经真实 DeepSeek/Codex 接受。
5. NapCat 在外层响应中直接提供内层 `forward.data.content`，内层 ID 再取会被拒绝。现在使用并归档已观察的内嵌内容，保持分页、深度、资源预算与来源权限。
6. 已发送合并转发回读可能是 JSON 卡片，旧提取函数只识别 forward 段。现在仅识别指定 QQ 卡片类型中的已观察资源，限制解析大小并沿用 ID 校验；拒绝无关/畸形卡片和未观察资源。网关不支持资源回读时明确报告失败。

前五项修复均先出现可复现失败，再通过对应回归与真实路径复验。第六项先通过失败回归复现，修复后卡片识别和权限/拒绝行为回归通过；真实资源再展开仍受上述网关限制。新增的真实验收脚本需显式 `--allow-real-models`，常规测试不调用模型。参见 [复验说明](LOCAL-ACCEPTANCE.md)。
