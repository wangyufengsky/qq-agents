# 图片、截图与文件资料库 · 2026-10-26

浏览过程中保存图片、内容页截图和文件，均使用角色自己的资料库。聊天回合可按需要发送；主体空闲浏览可先保留素材，再通过已有意图交给目标聊天。保存成功、模型看到预览与 QQ 投递成功是三个不同状态。

## 使用入口

| 工具                       | 行为                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| `image_save`               | 公开图片 URL 或自己文件库的 `fileId` 二选一，保留原文件并登记 `mediaId`                    |
| `app_image`                | 已观察 App 内容的 `recordId` 与从 0 开始的图片 `index`；默认封面，支持适配器实际返回的多图 |
| `web_screenshot`           | 公开网页的 1280×900 可视区域截图，返回 `mediaId`、`fileId`                                 |
| `app_screenshot`           | 已授权平台、属于自己的内容记录；截取工具专用页面，校验截图前后内容身份                     |
| `media_list` / `file_list` | 分页找回自己的图片、截图、生成图及原文件                                                   |
| `generated_image_list`     | Codex 原生生图完成后的登记结果、历史恢复与当前聊天的投递状态                               |
| `sticker_read`             | 查看已登记图片；文件名或网页文字不代替读图                                                 |
| `qq_send` / `qq_send_file` | 分别按 `mediaId` 或 `fileId` 通过已有出站账本发送                                          |

启用图片保存和截图时，同时配置 `file_download`、文件库 enabled/download/create 权限及所需工具白名单。主体 `readTools` 可配置 `image_save`、`media_list`、`file_download`、`file_list`、`sticker_read`、`web_screenshot`、`app_screenshot`，仍要求角色工具白名单；主体入口不直接发送 QQ，不开放 `file_import`。App 工具继续遵守平台权限、预算和时段。公开截图遵守自主联网或精确 URL 授权。

## 保存范围与限制

所有写入均在自己的媒体库或文件库；公开截图的临时浏览器资料也在本角色文件库内，结束即清理。工具不接受任意本机路径；`files.localRoots: []` 表示没有其他目录导入授权。文件只下载和保存，不执行下载内容，不自动解压。文件大小、总量和数量沿用各角色文件策略；静态图片登记上限 8 MiB，GIF 原图上限 20 MiB。

公开网页截图使用本机 Chrome/Chromium 和固定版本 `playwright-core`，无额外浏览器下载。可通过管理员环境变量 `QQ_SCREENSHOT_BROWSER` 指定浏览器程序。使用独立无登录环境，关闭页面脚本和 Service Worker；每个文档、子资源、跳转都通过公网 DNS 校验及地址固定的 HTTP 读取，不带浏览器 Cookie 或认证头，不放行 WebSocket、本机地址、内网及写请求。并发至多 2 次，单次 45 秒、100 个资源、24 MiB，单资源 4 MiB。脚本生成的正文可能不显示，因此截图不能宣称覆盖所有网页全文。

已授权 App 截图复用 OpenCLI 1.8.4 的内容页浏览入口与已有登录状态，使用临时工具页面，截图时短暂显示该页面以避免 Chrome 后台停止渲染，完成后关闭；不截取桌面或用户的其他标签页。不自动登录、点赞、评论、上传或发送。跳转到别的内容或登录页时拒绝登记；内容页出现遮罩、验证码或未加载部分也不能被描述为已读到内容。图片和文件直链仍要求服务器允许实际下载；授权浏览页面不保证每个附件链接无需登录即可下载。

## 原生生图和 429

Codex 原生 `imageGeneration` 完成事件现在可直接登记到桥接媒体库。只有当前绑定原生会话、当前回合的完成事件能触发登记；从角色独立 Codex home 的该会话生成目录读取，拒绝越界、符号链接和硬链接。会话归属和运维限制持久化；漏掉通知时从已经绑定的会话历史恢复。模型不传路径或自行指定原生会话。

原图保留后，发送失败无需再次生图。结果明确失败时可以修正后重试同一原图；投递结果 pending/unknown 时禁止换 requestId 重放。新功能不会自动向任何 QQ 聊天补发历史图片。

HTTP 429 本身不能证明余额不足。HTML 与 Cloudflare challenge 标记是验证拦截证据；结构化 `usageLimitExceeded` 才是明确用量限制。部分 Codex 版本会在结构化失败事件里省略 HTTP 细节，此时保留“原因未知”，不猜额度、不自动循环重试、不绕过验证。修复登记和发送流程不等于消除上游 Cloudflare 拦截。

## 验证边界

新增回归覆盖原生完成事件、会话与角色隔离、路径和链接拒绝、取消、失败分类、漏通知恢复、字节一致性、未知投递去重、图片与文件保存、App 多图、主体工具范围、配额及截图 URL 边界。

实际验证读取了既有 Codex 原生生图记录及 2,783,054 字节 PNG，登记后由隔离 QQ 网关接收，SHA-256 与原图一致。没有再次生图，没有真实 QQ 出站。公开 example.com 截图在本机 Chrome 实际完成并检查了图片与临时目录清理。真实 B 站内容页截图已经通过；初次后台窗口截图超时，定位为 Chrome 后台窗口渲染被挂起，改为仅截图时显示工具专用窗口后完成。其余平台未逐一实际截图验收，不将替身用例视为各平台实际验收。部署状态以本次交付记录为准。
